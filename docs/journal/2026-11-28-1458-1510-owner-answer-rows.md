# Card 1510: an owner's answer reaches the work that follows it

The card is a `type:spec` card under M8-U199 group A, with the claims exception M8-U208 item 1 grants. The pull request adds rows and changes no test.

## What I chose, and why

- **The answer is read from the card's issue, as the comments written while the label stood.** In #1418's window the coordinator posted each answer as a comment a second before removing the label (emend#90: comment 22:14:26Z, unlabel 22:14:27Z), so the window matches how the owner already answers. A comment written after the removal is no part of it.
- **The answer reaches the maker, never the judges.** Rigger cannot tell whether free text quotes a judge's findings, so handing it to a judge would put `R-EVIDENCE-4` at risk. The owner's ruling reaches the judges through the acceptance, as `D2` rule 1 has it.
- **Rounds start afresh at an answer, and a round ruled before any maker has run since spends none.** That is the one rule that keeps the M8-U174 case from spending the last round with a bound of one as well as two.
- **A body-only answer sends the judges back and spends a round.** The gate still reads markers at the head and digest. Only the counting of rounds changes, which "Markers" owns.
- **An answered card with a closed pull request starts again from `main`** where the forge keeps the old tip under that pull request, which is what M8-U174, U182 and U185 did by hand. Where the line's tip is held nowhere else, the maker continues from it, so nothing pushed is lost.
