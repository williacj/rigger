## Diagnostic proof

The trace captures the one-minute load at test start and measures release to the second pull or
wait failure before teardown. It emits one stderr line beginning `L7 trace:` with exactly
`releaseToPullMs` and `load1`. A run that never reaches release records `null` for that unavailable
interval. Duplicate end calls produce no second line.

The deterministic test, “L7 trace excludes setup and teardown and records the start load once”,
uses controlled clock readings and the documented load-average tuple. Its independent expected
record excludes setup and teardown, retains the start load and requires one emission. Its TDD
red emitted no record; the helper passed the same assertion. The ledgers retain both attempts.
Guarded duration and failing-wait receipts, their exact named failures and restoration checks
are recorded with the final-head evidence before handoff.

This is a harness diagnostic, as the card's Claims states. The checked registered requirements
`R-SCHED-6` and `R-RECORD` concern Rigger's triggers and engine event stream. None describes the
new test's assertions about this test-only stderr record's duration, load snapshot or duplicate
suppression. It carries no `// proves` declaration and adds no matrix claim.
