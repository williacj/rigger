## Hypotheses, in order

1. **H1:** the observed passing release interval is chiefly occupied by the verb's and stand-in's
   command chain, rather than an awaited `realHost.clock.pause`. The nonlanding observer's
   `attribution-solo`, `attribution-base-1` and `attribution-base-2` records confirm that narrow
   claim: their command-interval unions and uncovered time partition the observed intervals,
   and none records an actual clock pause in the interval. These observations do not establish
   the historical timeout's cause. No next hypothesis has been tested.

The timeout's cause is unknown. The initial uninstrumented baseline has no release-interval
measurement; the ledger preserves that missing evidence rather than supplying an inferred value.
The disposition and counted-run evidence are recorded in the linked ledger and pull request.

## Diagnostic proof

The trace measures from release to the second pull or the wait giving up, before teardown,
and captures the one-minute load at test start. It emits one `L7 trace:` line on standard error
with exactly `releaseToPullMs` and `load1`. A run that never reaches release records `null` for
its unavailable interval. Duplicate end calls produce no second line.

The deterministic test, “L7 trace excludes setup and teardown and records the start load once”,
uses controlled clock readings and the documented load-average tuple. Its independent expected
record excludes setup and teardown, retains the start load, and requires one emission. Its TDD
red emitted no record; the implemented helper passed the same assertion. The ledger records both
attempts. The remaining diagnostic proof obligations are a guarded duration mutation and a
guarded L7 failing-wait run, each with restoration evidence recorded in the ledger and pull
request before handoff.

This is a harness diagnostic, as the card's Claims states. The checked registered requirements
`R-SCHED-6` and `R-RECORD` concern Rigger's triggers and engine event stream. None describes the
new test's assertions about this test-only stderr record's duration, load snapshot or duplicate
suppression. The test therefore carries no `// proves` declaration and adds no matrix claim.
