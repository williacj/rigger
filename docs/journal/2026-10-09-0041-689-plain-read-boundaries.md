# Post-kill plain-failure boundaries

The current card separates a plain state-read failure evaluated before the unreaped bound from a terminal plain failure evaluated at or after it. In the first case a subsequent read can be cut before start or time out after start. L0 retains a prior live answer across either cut, while a path with no returned state answer retains no live observation. A terminal plain failure records the unread-table reason even where an earlier live answer exists.

Four added focused tests drive the two answer histories through both cut forms. Their fixture uses real synchronous reads and signal calls through L0, with only the external `ps`, `lsof` and logical clock supplied by stand-ins. It asserts ordered returned results, the positive remaining bound at the plain failure, a later `LATE` with no read start or a started `ETIMEDOUT` with no returned answer, continued signal-0 reachability, and the named event and reason. Two further focused tests drive a started terminal plain failure and assert its distinct bound evaluation and unread-table reason. The existing later-live/failed control remains a neighboring source-path control; the new failed-first/later-live/failed test supplies the P1D selected input.

The first focused red failed because its initial assertion included pre-kill reads. After restricting the assertion to reads after the named kill, the test failed on the missing later pre-start cut. The stand-in sequence supplied that boundary, and all six focused cases passed. Two terminal proofs initially expected a signal-0 poll after the terminal read; L0 evaluates that result without another poll. Their corrected assertion checks the recorded poll immediately before the read and the PID still live after the call. These failed outputs remain complete private originals for the card ledger.
