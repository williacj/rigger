## B24 cases encountered

- **Opening still in flight.** A freed-slot pull can arrive while L2 awaits an opening. Pending
  settlement and firings share one serial queue, so recovery cannot scan that unfinished opening
  and create a second card. A kept run queues recovery without awaiting it in an ordinary pull
  or drain, and polls have an independent wake while a firing awaits the forge.
- **Known issue after a later failure.** A made opening, a made board add or move, and a refused
  created transition retain the issue number in the current run. That number floors the newest
  number the scan reads. A successful opening whose outcome is refused retains it too.
- **Names and instants at the edges.** Empty, prototype-shaped and escaped names, with fractional
  occurrences past year 9999, write start/outcome lines that a later run reads back. A card start
  retains `after: 0`; the ISO occurrence is converted with `Date.parse` before L2 reads its mark.
- **Report catch-up before the first pull.** M7-K42 item 1 requires every report-only catch-up
  to precede the first pull even when an unrelated card firing remains pending. Startup lets
  those reports finish before pulling, deferring unrelated recovery to that pull. A card firing
  or a recovery blocking its own trigger releases the first pull to proceed independently;
  both clock operations still use the same serial queue and shutdown joins it.
- **Mixed catch-up order, accepted trade.** M7-K42 item 2 accepts the attacker's P7 order at
  9ab2d678: `["clock:alpha","pull","clock:beta","drain"]`, where a card catch-up sorts before
  a report catch-up. A pull never waits on a card firing, while firings remain serialized by
  occurrence, then name. The report-only ordering promise does not make a pull await that card.
- **L0 missing-label refusal.** M7-K42 item 3 leaves the opening whose missing-label error
  names no made issue to a separate L0 card. This card preserves `madeUnrecorded`'s issue floor;
  it does not change `repository-write.mjs` or infer an issue number from an unmarked refusal.
- **Across-restart residual.** Nothing carries an opened issue's number to the next start's scan.
  Whether the forge's newest-number read can trail a just-opened issue is unmeasured. The current
  run's floor does not establish a cross-restart freshness guarantee.

## Shutdown owns queued and issued clock work

The round-two judges found that the queue kept clock work exclusive without keeping its run
alive. A stopped run could therefore leave a recovery read capable of opening another card,
or let an already queued catch-up or recovery begin after stop. Round-three shutdown now checks
termination when queued work starts, between scan requests, after a new firing's fence read and
after its start append. Shutdown joins the queue and the timer's outstanding callbacks. Ordinary
pulls, polls and drains still do not wait for that queue.

An issued forge request is allowed to settle. Its L0 call outcome remains that request's record.
If stop prevents the remaining Ready placement, the L3 firing remains pending; the next run
finds the existing issue and completes placement before recording its firing outcome. This uses
the existing partial-firing recovery path and preserves the same-run issue floor.
