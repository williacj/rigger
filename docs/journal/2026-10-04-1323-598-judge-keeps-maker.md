# #598 — the pull keeps the maker's result when a judge fails

**The maker's result travels out of band, not on the error.** The fix could have attached the
maker's result to the error the judges threw. That error is sometimes L2's own, when its judge
answer throws on a review read the settle answered rejected, and L3 should not write onto an
error it did not make. So `attempt` hands the result to a callback from `work` the moment the
settle answers, before L2 is asked about judges. `work` then settles on `{ reached, failure }`
rather than rejecting, and `trigger` sorts the two. The card's own failure keeps the shape it
had at the base.

**A verb cannot refuse one judge's dispatch event, so the verb test refuses L1's make event.**
`once`'s sink is the consumer's event stream, and nothing a test hands the bin refuses one
append. The only way in is the trick `installGhRefusingStreamAfterMove` already uses: replace the
stream with a directory once something has happened. No `gh` call happens between the settle
and the judges, so the trigger is a `git` on PATH that does this once it has answered a command
naming a judge's directory. L1's `workspace.made` is then refused. L2 reads that outcome as no
failure of L1's to make the directory, and answers no action for that judge, which names the
card and the judge.

**The base failed the new tests on the reached assertion alone.** All five new tests ran at
`33defb2` with only the tests added. Each loop test failed on `failure.reached` missing the card,
and the verb test failed on the missing "claimed #10" line, while the judge's failure line was
already there.
