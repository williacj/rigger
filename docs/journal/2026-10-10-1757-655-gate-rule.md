# The gate reads the marker reader's answer

`readMarkers` already determines which current marker governs and orders readable older markers.
The gate uses those answers directly. Re-parsing comments in the gate would create a second rule
for identity, permission, and creation-time ties.

An unreadable marker can govern only when its parsed identity names this round. The gate refuses
it with the parser's reason. An unreadable marker at an older head or digest is absent from the
reader's ordered `markers` list, so the gate reports no marker unless another readable stale one
exists.

The refusal is a list because a judge fault and a failed required check can both block one
attempt. Each entry names the judge or context and its reason. The order follows the configured
judges, then the check map; nothing depends on prose in a marker's free fields.

The first red test demanded admission with three sound markers. Later reds established the
distinct missing, stale, unmet, critical, unreadable, edited, coverage, empty-panel, and unknown
check answers before each rule was added. The table test then exercised those answers at every
position in one-, three-, four-, and owner-only judge sets.
