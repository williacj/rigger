# 2026-09-27 — A redo in Review that exits zero changes nothing

**Where the fault was.** L2's `settled` in `src/workflow/transitions.mjs` treated every zero exit
as a return from Coding. L3 skips the claim move for a redo, so a card pulled from Review reached
`settled` still in Review. There it was moved to Review a second time, and a `coding`→`review`
transition was recorded for a move that never happened. `R-WORK-5` is checked by exactly that
kind of transition.

**The fix reads the card L3 hands over.** The card is the board item as L0 read it, carrying the
column it was pulled from. So `settled` leaves a card read in `review` where it is. A Ready card
reaches `settled` still marked `ready`, because L2's claim move does not change the item L3
holds. That is why the test is "not already in review" rather than "in coding". L3 and the
boundary rules are untouched: L2 already had everything it needed.

**The tests go through the loop.** `test/redo-settle.test.mjs` drives `loop-world`'s real loop over
the fake board for each of the three cases, and runs all three together to check that every
transition matches a move. The fake board names items by position (`item-1`, `item-2`, and so
on), not by card number, so the helpers map ids through a board read. A first draft keyed on the
number and redded for the wrong reason.

**Every run is bounded.** `loop-world`'s `drive` releases dispatches until the run ends, so a
mutant that re-pulls without end never ends it. The file's own driver gives up after ten rounds
and fails if a run starts more dispatches than it has cards. Before relying on that, I checked it
against a hand mutant in `next-action.mjs` that drops the freshness check. All eight tests
reached a named failure ("the run started 2 dispatches: 6,6"), none hung, and the file was
restored afterwards.
