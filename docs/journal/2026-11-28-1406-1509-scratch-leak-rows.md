# Scratch leak: rows R-WORK-44 to R-WORK-49

Card [#1509](https://github.com/williacj/rigger/issues/1509), acceptance K7 `cbbc8518be2c`, read at
`main` `d44e5952`. The pull request body carries the full argument; this entry keeps what was
learned.

- **The leak has two shapes, and only one is a judge's.** A judge's probe repositories under its
  shared scratch path refused the next dispatch of that role four times on 2026-11-27 (Emend's
  event record at `273cdc44`). The other shape is quieter: `scratch/rigger-151` and
  `scratch/rigger-157` hold no git checkout at all, yet stayed, because those cards reached Done
  before Rigger read their merges, and `### R-WORK-35`'s table puts that case out with "its
  directories stay". `rigger-215` stayed with no row behind it: its issue closed with no pull
  request, and no removal row reaches a card without one.
- **Removing a whole scratch directory at a dispatch's end is simpler than sorting its contents.**
  `R-WORK-44` removes everything not there when the dispatch began. What it keeps is a short,
  named list: a checkout whose git directory lies outside, a sign's directory, a labelled card's,
  and leftovers from before the rows.
- **A sign's directory is not removed at a dispatch's end.** Removing a directory `R-STATE-32`
  names would end that sign without a read showing its processes gone. `R-WORK-35` already removes
  such a directory at a merge, so the rows defer to it there and the body raises it as an open
  question.
- **Done cards' directories are retained and named, not removed.** Removing them would replace
  `R-WORK-35` and `R-WORK-41` under new ids, and would sit close to `D10` rule 1's "reclaim a
  workspace it no longer tracks". `rigger doctor` names them instead (`R-WORK-49`). Removing them
  is the body's first question for the owner.
