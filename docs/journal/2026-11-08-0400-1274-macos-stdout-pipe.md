# The macOS pipe refused a synchronous write

The owner's `ci:full` run 42441286181 failed `full_host` on macOS, `macos26-20261102.0473.1-ARM64-node26`. Two of 2,310 tests failed: both own606 worker positives in `test/exit-cleanup.test.mjs`, `606 B0 EX causal: SITE-EX-F0-X-Z` and `606 B0 EX causal: EDGE-EX-AQ-NEWPID-B0-omitted-reaped`. Each threw `EAGAIN: resource temporarily unavailable, write` from `writeFileSync(1, …)` in the parent's `emit`, which writes each worker original as one base64 line.

On that runner the test's standard output is a non-blocking pipe. A synchronous write larger than the free pipe buffer returns `EAGAIN` instead of waiting. The owner's measurement on a Mac recorded the same errno after 65,536 bytes. The two runtime refusals passed, because their originals are small. No product assertion failed.

## The change

The four parent-side `writeFileSync(1, …)` calls in `runExCausal` become `process.stdout.write(…)`, with their arguments unchanged. Node completes a partial write on a pipe, and the test process exits naturally, so the output drains whole. Nothing else in the file changes. The worker template's one `writeSync(1, …)` writes a single short line in the child, far below the pipe buffer, and stays.

## What this proves and what it does not

The red is run 42441286181's macOS failure, at the old bytes. The green is the owner's next `ci:full` at this commit, on macOS, which had not run when this entry was written. This commit's hook and the next affected host run show the test still passes on Linux; they say nothing about macOS.

`rigger-606` carries the same four lines and takes this change when #606 resumes.
