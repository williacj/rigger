ABOUTME: Journal for #504: every `ps` stand-in the forcing showed losing its first read is now
`warmed`, in the process adapter's, the recorded-group kill's and the restart's tests.

# #504 — warming every stand-in whose first exec is a bounded read

**The forcing found more than the card first named.** #500 showed that the system can hold the
first exec of a freshly written `ps` stand-in past the read that runs it. The card first listed five
stand-ins. Forcing every stand-in's first exec to hold, across all three files, made the tests of
fourteen of them fail (one run of each file at 76d9e47). Most read under the default `READ_TIMEOUT` of 5,000 ms, against a measured worst hold of
1,058 ms (`warmed`'s comment). The forcing holds without end, so it shows which tests depend on the
first exec arriving in time, not how likely a real hold is to outlast 5,000 ms. The owner ruled
(O32) that one card warms them all.

**The fix is the same at each one.** Each stand-in is `warmed` where it is defined, so its first
read is its second exec, and no call line changed. No bound moved and no sleep was added.

**One target passed under the forcing, and it shows what the forcing cannot see.** The
leader-and-zombie test reads its stand-in's first exec under the census, which timed out. The
adapter then recorded the group's kill, which that test accepts, and a later read set `cut`. So the
test passed while its census never read the zombie-only rows it exists to test. Warming it makes
the census read them. The "proves nothing" checks catch a branch never reached, but not a branch
reached only by a later read.

**A compiled stand-in needed its own forcing and its own warming exit.** The census re-read
processor test compiles its `ps` stand-in in C, so `fixture`'s forcing never reached it, and it
failed twice under load in a hook run. Warming it as written would have marked its first call, and
the re-reads would then have been timed from the census's first read rather than its second. So
the program now exits before marking a call when `RIGGER_FIXTURE_WARMING` is set. The test also
checks that the stand-in's first call came after the command exited, which a warming run that
marks the call fails.

**Refusal tests pass under a hold for the wrong reason.** In `test/kill-recorded.test.mjs` and
`test/restart-kill.test.mjs`, the tests whose stand-ins fail on purpose still pass under the
forcing, because a timed-out read is refused just as a failing one is. Of those, only the stand-in
the owner granted (`startsAs`) is warmed here. The others are left as they were.
