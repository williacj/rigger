# 2026-09-23 — The gate corrupts the repository it runs in

`core.hooksPath` was armed today, and the first commit attempted from a linked worktree rewrote the repository rather than refusing. `git commit` exports `GIT_DIR` and `GIT_INDEX_FILE` to its hooks, `.githooks/refuse-if-suite-red` runs `npm test` with that environment intact, and the tests that build a fixture repository spawn `git` without scrubbing it. Each such spawn therefore operates on the real repository: the branch gained six commits titled `fixture`, the index was replaced by a fixture tree, and the shared `core.bare` was flipped to `true`, which left the main checkout answering `fatal: this operation must be run in a work tree` for every session. The commit was then refused, because a test read `docs/the-widget.md` out of the polluted index and got ENOENT — so the output blamed a red suite and said nothing about what had just happened underneath it.

It does not reproduce in an ordinary clone, which is why the gate looked fine when it landed. There, `GIT_DIR` is `.git` and `GIT_WORK_TREE` is set beside it, so a fixture's `git init` re-initialises the same repository harmlessly and the commit succeeds. In a linked worktree `GIT_DIR` is `.git/worktrees/<name>` while the config is shared, and the same `git init` writes `core.bare` into the config every checkout reads. Measured on a clone taken from the GitHub URL at `716f419`, with no change of mine: `npm test` reported 282 of 282 passing run plainly, the same suite in the same linked worktree redded under the gate, and `env -u GIT_DIR -u GIT_INDEX_FILE -u GIT_WORK_TREE -u GIT_PREFIX -u GIT_COMMON_DIR npm test` reported 282 of 282 again. So the environment is the whole of it, and either side can hold the fix — the gate can scrub, or the tests can stop inheriting. Every dispatched maker works in a worktree by rule, so until one side changes, no dispatched card can commit and every attempt damages the repository for everyone else.

The header count needed a tool check before it needed a sweep, and it needed two. `git grep -c 'ABOUTME:'` answers 2 for `AGENTS.md`, whose header carries the prefix once, because it also counts the rule the file states about headers; it answers 2 for the code-review skill for the same reason. Counting consecutive prefixed lines at the head of the file instead answers 1 for both, which is the answer read by hand. But the first reader written that way skipped a YAML frontmatter block whole, and so reported no header at all for the four role prompts that carry theirs on the line below the opening `---` — the placement `AGENTS.md` explicitly allows. One wrong tool over-counts by reading the whole file, the other under-counts by reading too little of the head, and both are silent. What caught the second was a cross-check the reader carries: every `ABOUTME:` in the first eight lines of a tracked file has to be accounted for by the header the reader found, and anything else is printed as a suspect. Measured at `716f419` with that reader, 117 tracked files carry a header and 46 repeated the prefix — one across three lines, 45 across two — against the 43 the card's ratification recorded at an earlier ref.

A shell is not a text editor, and three attempts proved it before a file did. Writing a test body through `node -e` inside a single-quoted argument turned an intended `\n` escape into a real newline inside a string literal, and `node --test` booked the unparseable file as one failing test named after the file — the exact output a discriminating red has. Worse, `sed -n '119,124p' AGENTS.md | cat -A` showed no `\r` on lines that a byte read proves are CRLF, so the tool used to inspect an anchor disagreed with the file about the file. Every edit after that went through a script written to disk, where the escaping is JavaScript's and the anchor is resolved against the bytes; each such script printed its anchor's occurrence count and refused on anything but one, and the sweep additionally compared each header's words before and after so a rewrite that changed wording would refuse rather than land.
