ABOUTME: Journal for #540: the suite leaked every temporary directory it made; one helper now makes
them all and removes each when its test ends, and a check refuses any other mkdtempSync under test/.

# #540: the suite filled the disk with its own temporary directories

**The cause.** Fifteen `worktrees` tests failed with `No space left on device` in #528's forced run
at `bf8cf64`. The owner found the cause (O58 on #540): `npm test` made its scratch directories
with `mkdtempSync(join(tmpdir(), 'rigger-…'))` and in most places never removed them. By
2026-10-02 there were 268,778 such entries, about 17 GB, made since 2026-09-29. My own partial
survey that morning, run before O58, agreed with it. Under the default `TMPDIR`, 440
`rigger-clone-` directories of about 10.6 MB each, made by `test/doctor.test.mjs`'s fresh clone,
came to 4.4 GiB on their own. The agents' fresh clones and `TMPDIR`s in the coordinator's
scratchpad came to about 29 GiB more, and O58 makes those the coordinator's scripts' to remove.

**Why the helper takes no test context.** Most of the 74 calls sat in fixtures that are never
handed `t`, such as `repositoryIn`, `world`, `stubGh` and the files' own small helpers. Threading
`t` through every caller would have changed hundreds of lines O58 does not grant. `node:test`'s
exported `after` registers its hook on whichever test is running, whether it is called in the
test's body or in a function the test awaited, and it hands that hook the test's context. I
measured this on Node 26.5.0 and on Node 20.20.2, the floor CI runs. So the helper registers
through `after`, and inside that hook it calls `t.after` for the removal. As in `scratch` before
it, a hook added during teardown runs after every other, so the test's own teardown still sees the
directory. `getTestContext` would have said the same thing more directly, but Node 20 lacks it.

**`scratch` is built on the helper.** Its teardown sweeps and then removes, and it leaves the
directory where a process it cannot end still names it. The helper takes that sweep as
`beforeRemoval`. The removal code, which restores write permission and never follows a link,
moved into the helper rather than being copied. So `test/scratch-teardown.test.mjs` now proves
the helper's removal too.

**A directory shared across a file's tests.** `test/package.test.mjs` installs the packed tarball
once and shares it across its tests. A removal at the end of the first test would pull the
install out from under the rest. So the file makes that directory at its top level, outside every
test. There `node:test`'s `after` registers on the file's root, so the directory is removed once
all of the file's tests have ended, passed or failed. The first design removed it on the process's
exit; the Codex judge held, in round 1, that this is no removal when a test ends.

**The one leak that was not `mkdtempSync`.** `test/demo.test.mjs` sources `test/demo-world.sh`,
which makes its world with `mktemp -d "$TMPDIR/rigger-demo.XXXXXX"`. The tape needs that world to
outlive the shell that sources it, so the script cannot remove it. The test now hands that shell a
`TMPDIR` the helper made, so the world lands inside a directory removed when the test ends (O59).
O59 also had the five removals the helper now duplicates deleted, and O64 the empty `finally` and
unused `t` parameters those deletions left.

**Why the check reads tokens.** The first check matched `mkdtempSync(` on a line. Both judges
showed it passes a call split across lines, an aliased import, a destructured key, `.call` and
`fs.mkdtempSync` through a namespace. It now reads each file with acorn's tokenizer and flags
every token that is the name `mkdtempSync`, which catches the import or key every alias needs. A
mention in a string, a template or a comment is not a name token, so the list of writes in
`test/dispatch.test.mjs` is not flagged. A computed `fs['mkdtempSync']` is a string token and is
not flagged.

**Read-only trees (O68).** The owner found `rigger-process-*/state/` directories left read-only,
which a plain `rm -rf` cannot remove. The helper's one removal, `removed`, which `scratch` used
before it, first gives the owner write permission on every directory in the tree and only then
removes it. Every path through the helper reaches the removal through `removed`, now that the
exit-time option is gone. A test now runs a generated test that leaves a read-only subdirectory
with a read-only file inside a read-only directory. Against a helper without that step, it fails
with `ENOTEMPTY` from the removal hook. With it, the directory is gone.
