# #462 — a pull's failure carries the cards that reached their workspaces

**The outcome rides on the rejection.** Every existing caller of `loop.pull()` asserts that a pull
with any failure rejects, and the card grants no existing test line. So the pull still rejects
with its AggregateError, and that error now carries `reached`, the same `{ card, workspace }` list
the pull settles on when nothing fails. A pull that settled on both lists would have changed every
`assert.rejects(built.loop.pull())` in `retry.test.mjs` and `loop.test.mjs`.

**The verb prints the same line in both branches.** `once.mjs` builds each workspace line through
one local function, `stoppedAt`, which both the success and the failure branch use. On failure,
the workspace lines come first and the failures after them, so the two cards waiting in Coding
read as they would had none failed. The exit stays 1 (`O5`).

**The loop's failure lines already matched L2's record.** The item asking that the pull carry
#20's two attempts "as L2 recorded them" held at the base. Its test passed before the change, and
it pins that each `attempt N:` line's fields equal L2's `attempt.failed` event for that attempt.
The three tests that went red at the base were the two workspace-path items and the
once-and-only-once item.

**`loop.run()` is unchanged.** It already gathers each pull's failure into its own AggregateError.
A pull's `reached` now sits on the inner error, and `run()` does not lift it out. No verb calls
`run()` before M4, and no item asks for it.
