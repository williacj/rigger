# 2026-09-25 — Labels are a list

The engine reads a kind's `select.labels` as a list, calling `some` on it. #252 had the validator
refuse an empty list, but it said nothing about a value that was not a list at all. A string such
as `labels: 'type:change'` passed validation, and the first time the engine selected cards it
threw. The fix belongs in the validator, where the config is loaded. That way the consumer's typo
is refused by name and never reaches the engine as a crash.

The check extends #252's rule instead of adding a second one next to it. `readLabels` asks three
things in order: whether the value is a list, whether it names at least one label, and whether
every entry is a non-empty string. A value that is not a list gets one refusal and nothing else.
Reading its entries would give a string one entry per character and a number none, and neither
of those is what the author wrote.

The entry check copies the priority options rule, including its reason. It reads through
`Array.from` because `some` skips an empty slot. That makes two uses of the same one-line
predicate. The Rule of Three does not ask for an extraction yet.

The check covers kinds only, because that is what the card asks. A provisioning step's
`select.labels` has the same shape and is still accepted when it is not a list. Nothing under `src/` reads
it yet (grep on this branch), so today it cannot crash anything. The gap is reported with the pull
request, not fixed here.
