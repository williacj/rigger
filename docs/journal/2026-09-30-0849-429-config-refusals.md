# #429 — The config refuses what L1 cannot use

## What we learned

**A refusal sits beside the shape check, never in place of it.** The shape table already refuses a
container that holds no declarations, with exactly one refusal. Each new rule therefore steps
aside where its container is no set of declarations. It also steps aside where the key it reads is
absent: a missing `run` is the required-key refusal's, and a missing `cwd` takes the default. The
existing "one refusal wherever it sits" test caught nothing here, because every new rule was
written to that pattern from the start. It is still the test that holds them to it.

**A config with no `provisioning` declares no step.** A kind naming a step then names one Rigger
has no command for. A config whose `provisioning` holds nothing has already earned its refusal, so
the kind's names are not read against it. Read the other way, every kind would earn a second
refusal for the same fault.

**`..foo` is a directory, not a step up.** The escape check reads the normalised path's first
segment. A prefix test on `..` would refuse a directory named `..foo`, so the accepted-paths test
holds one.

**Tests of what stays accepted need a mutation to prove anything.** Five of the acceptance items
say a spelling earns no refusal. Those were true at the base, so their tests passed on their first
run. Guarded mutations of the root, timeout, cwd and topic rules each redded the intended tests,
which is the only evidence those tests discriminate. The pull request records each one.

## What stays open

A topic can hold no `/` and still name a branch git refuses, such as one holding `..`, a space or
`~`. No acceptance item here covers it, so the pull request names it as outside the acceptance.
