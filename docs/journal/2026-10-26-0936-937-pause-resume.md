# Pause and resume (#937)

`rigger pause` and `rigger resume` land as thin callers of `src/scheduling/admission.mjs`. Each resolves the repository through `settled`, as `once` does, reads no `rigger.config.mjs`, and builds the module over that repository's `.rigger/`. Neither touches `.rigger/admission/` itself, and neither records an admission event: the module records `admission.close` and `admission.open`. `recording` now hands `work` the run id it gives the sink, and `pause` hands that id to the module, so a closer's `run` is the `run` of the verb's events. Neither verb draws an id.

`resume` builds the second of `ARCHITECTURE.md`'s three `resume` steps, the removal. The status issue's read and close are M6-11c's, so `resume` makes no forge call, and `R-SCHED-24` stays a gap until M6-11c merges.

The not-yet-implemented branch of `src/cli/verbs.mjs` and the unlanded-verb loop of `test/cli.test.mjs` are retired together under the owner's U48. That test now asserts that no verb the README lists is missing from `LANDED`. Guarded mutation: with `pause` dropped from `LANDED`, that assertion failed with "the README lists verbs that have not landed", and the restored source passed.

## The tests

`test/pause-resume.test.mjs` runs each row through the verb, in a scratch repository under the test's temporary directory that holds no `rigger.config.mjs`. It runs in the suite's deterministic tier, so it hands the verb's guard an `ask` that runs git directly, and no process group is signalled. Where the file system or the sink will not give a failure on demand, the test injects it through the module's `fs` and says so. Those failures are the sink refusing between a link or unlink and its event, a temporary file that cannot be removed, a partway removal failure, and a closer gone between the read and the unlink. The three directory failures are the real file system's own. `test/once.test.mjs` runs the bin's `pause`, then `once`, which claims nothing, then the bin's `resume`, then `once` again, which moves the same card it moves with no pause.

These tests were written after the code they cover, so each was shown to discriminate by a guarded mutation, restored before the commit. An extra `admission.close` event that `pause` recorded itself failed the stream test. A `gh` call from `resume` failed the forge test, which records every process started while `resume` runs. A `node:fs` import in `resume` failed its through-the-module test. A `resume` that removed nothing failed the `once` test, and so did a `pause` that closed nothing.

## Round 2, after the judges' first verdicts

The owner granted a one-time test-first exception for this pull request (U80), so the admission above stands as written. The judges found four faults in the tests, and each is repaired below. No production code changed in this round.

- **Path spelling.** The scratch repository was read with `realpathSync`, but the verbs resolve it with `realpathSync.native` (`real` in `src/cli/doctor.mjs`). Under a `TMPDIR` spelled in a case other than the one on disk, 14 of the 23 tests failed on their path assertions. The fixture now reads `realpathSync.native`. The same run with the miscased `TMPDIR` then passed all of them.
- **An open `resume` changing nothing.** The two open-admission tests now compare the admission directory before and after: absent stays absent, and empty stays empty. A `resume` that adds an owner closer while still saying admission was already open fails both.
- **The boundary and the ids.** The static import check could not see a dynamic `import()`, a direct read, or an id drawn by the verb, so runtime checks replace it.
  - While a verb runs, every `node:fs` and `node:fs/promises` function is replaced and the ESM bindings are synced. Every call naming a path under `.rigger/admission/` must come from a stack inside `src/scheduling/admission.mjs`. A direct read through `import('node:fs/promises')` or `import('node:fs')` in `pause` fails this, and so does a direct listing in `resume`.
  - `node:crypto` is made to draw known values. `pause`'s closer must carry the module's id and `recording`'s run, with one draw of each. `resume` must draw nothing but `recording`'s run. A `Math.random` id source, a second `randomUUID`, or a `randomBytes` call in `resume` fails these.
- **Split test.** The no-config test is now one test per verb, so `resume`'s half is reached whatever `pause` does.
