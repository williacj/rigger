# Reaper exit after directory removal

At base `8fea50a`, `runEnding` waited for the nested run directory to disappear and then sampled
the process table once. `test/suite-reaper` removes that directory before it exits. A forced E4 F5
run held the actual nested reaper at that point. The directory was absent, `/bin/ps` still reported
the reaper in state `R`, and the original process assertion failed. `/usr/sbin/lsof` exited 0 with
no qualifying cwd row for that PID. The trace recorded the reaper absent at teardown. This was a
controlled reproduction of the failure reported on PR #666, rather than a frequency claim about
unforced CI runs.

The check now polls the process set and directory together, stopping on the first answered poll
where both are clear or at the original 10,000 ms deadline. Its final process assertion still
precedes the directory assertion and retains both messages. A process found through either `ps`
or `lsof` remains a survivor; the changed wait does not change the process census.

The first added test failed at base with `ReferenceError: checkEnding is not defined`, then passed
when the polling check was introduced. Deterministic final-poll cases cover the reported reaper,
runner, and fixture combinations. Separate tests start real processes to exercise a `ps` survivor,
an `lsof` cwd-only survivor, and a transient `ps` reaper. Each test's teardown ends its child.

The complete suite, repeated head-file runs, load observations, controlled base and head runs,
and CI are recorded in the pull request for the exact head they test.
