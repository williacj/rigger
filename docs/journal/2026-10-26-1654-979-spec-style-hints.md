# Card 979: advisory spec-style hints for rules 4 and 5

The card follows U75, which puts a change to how makers and judges work into the repository's
own checks, and U77, which runs the Rounds set on the Mac mini. Rules 4 and 5 stay judgments.
A hint points at a sentence an author should reread before a judge does, and nothing reads a
hint to decide an exit.

`hints(text)` sits beside `findings` in `scripts/spec-style-lint.mjs`. It reads paragraphs and
table cells through the same fence-blanking and sentence splitter, so fenced code gives no hint.
Since U85 it reads list items too, as the end of this entry says. `check(root)` returns the hints beside the findings, and only the
findings set `failing`. `--hints` prints them after the summary. Without it, the lint prints what
it printed before byte for byte, which the pull request shows by running the merge base's script
on the head's tree.

The thresholds are the card's: three `then` in a sentence, or three of `where`, `if` and
`unless`. A `D#`, an `R-` id or a backticked path, beside one double-quoted run of eight words,
is a rule 5 hint. A sentence can draw both, and both hints read the same paragraphs and cells.

Over the four binding documents at the head, `--hints` prints one hint, a rule 5 hint on a list
item in `docs/spec/decisions.md`. Before U85, with list items skipped, it printed none.

The new tests went into the two existing test files rather than a new one. A new file would need
a line in `test/suite-tiers.test.mjs` and `test/suite.sh`, and the card changes no existing line
under `test/`.

Four tests were written after the code they pin: the list-item, fenced-code, usage and
retired-register tests. Each was then run against the merge base's two scripts, with only the
test file's `hints` import line dropped, since the base exports no `hints`.

- The usage test went red on its exit assertion, 1 where it expects 2, because the base reads
  `--hint` as a root path.
- The retired-register test went red on its exit assertion, 1 where it expects 0, because the
  base reads `--hints` as a root path. That red shows the option missing, not the retired
  register's exclusion, which mutation M3 shows.
- The list-item and fenced-code tests failed with `ReferenceError: hints is not defined` and
  reached no assertion. That is no red. They have no test-first evidence, only mutations M1 and
  M2, and the coordinator was told. The owner excused those two once, under U82.

Rounds 1 to 4 tried to keep list items out of the hints. Each round's judges found a list
extent the rule missed: a wrapped line, a lazy line, an item holding a heading, a thematic break,
a tab. Round 4, granted under U83, walked CommonMark 0.31.2's list-item and block-structure
sections in `listContinuations`. Its judges were still ruling on it when the owner chose another
course.

Under U85 the hints read every paragraph, list items included, and the list tracking is gone.
`paragraphs` now takes the set of lines that end prose. `findings` passes the base set, list
markers included, so its output is byte for byte what it was. `hints` passes the set without the
markers, so a marker line reads as prose. Items with no blank line between them read as one
paragraph, so a sentence can run from one item into the next. `unfenced` is back to its base
text. The tests that pinned list extents went, and so did the first list-item test, which asserted
no hint. U82 still covers the fenced-code test, which stays.

Two tests came first, at 23:44, run against round 4's code. "a list item and the same text as a
paragraph get the same hints" went red: the item drew no hint where the paragraph drew one on
line 1. The list-item row of Table A went red the same way. Three guarded mutations cover what
replaced the list code: restoring the marker in the hints' set, giving it to `findings`, and
dropping the table row from the hints' set.

What taught us: a rule needing four rounds to approach its edges is a rule worth asking the owner
to drop. The judgment it served stays a judgment, and a hint on a list item costs a reread.

The skill's "Not all of it lintable" bullet gained one sentence. `npm run budget:instructions`
measured 14,916 live words at the first merge base `ac3df94c` and 14,933 at its head. After
merging `main` at `383f16e9`, it measured 15,027 at that merge base and 15,044 at the head. Either
way, the card adds 17 words against its cap of 30.

What taught us: a hint that shares the lint's reader inherits its disclosed biases for free. A
merged sentence can draw a hint it should not, and a split one can hide one.
