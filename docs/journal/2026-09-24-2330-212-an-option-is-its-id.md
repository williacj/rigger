# 2026-09-24 — An option is its id, not its name

Spike #212 asked which ways of adding a `Status` option through `gh` keep every card's column. The
report is `docs/spikes/status-option-through-gh.md`.

`updateProjectV2Field` replaces a field's whole option list. Sent back by name, colour and
description alone, every option came back under a new id, and every item on the throwaway board
lost its `Status`. The call exited 0 and the options looked the same by name, so nothing on the
surface said the board had been emptied. Sent back with their ids, the same options kept every
item in place, including when the new option went mid-list.

The lesson for a board client is that it has to read an option's identity and send it back. A
name that matches is not enough. The `gh project` subcommands cannot help: `field-create` refuses
the reserved name `Status`, and `field-delete` refuses a built-in field.

Two reads straight after a write missed that write, and the next call showed it. A client that
checks its own write by reading straight back can be told the write never happened.
