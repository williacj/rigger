# 2026-09-24 — The list that ranks

Card #195 landed five deltas the owner ratified: which layer reads the board, which layer changes a
card's column, which kind selects a card, and what the Engine settings row declares. Four were text
to copy. The fifth left one clause to the architect, and it is the one worth recording.

## Two sources for one order

The ruling that proposed the deltas ranked priority by "that field's own option order", the
board's. The owner's U23 ruling then had the config declare the options in rank order, and
`setup-board` create the field from that list. That leaves two lists which can disagree: the one
the config declares, and the one the board holds after anyone edits it.

The clause makes the config's list rank. Were the board's order to rank, the declared order would
matter only on the day `setup-board` creates the field, and a config that says one thing while the
engine does another is the drift the config exists to prevent. `R-SCHED-1` asks only that an owner
change what runs next by changing a card's priority, which either source serves.

A value the config does not declare ranks with a card that has none. That extends U3's ruling for a
card with no value rather than inventing a second rule. Refusing to pull was the alternative, and
it would stop all work over one renamed option, which is a behaviour no requirement asks for.

## What it cost

The original clause was written before U23 existed, as a conditional on U3. A conditional delta
survives its condition being met in a different shape than the one it assumed, and still reads as
ratifiable. The coordinator's brief caught it, by reading the rulings against the clause rather
than the clause alone.
