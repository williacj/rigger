# #541 — L0 never stops a process group

**Why the sentence changed.** #539 found that a child which calls `setsid` while L0's census holds its
group stopped leaves the group already stopped. The census never reads it and the kill misses it, so
it sits under pid 1, stopped, for good. The Failure model said only "A process that leaves its group
is outside this containment." Ruling 11 holds that this sentence assumes the process was free when
it left. This one was not: L0's own stop reached it, and only that stop keeps it from running or
exiting.

**Resume, not kill.** Killing the process would reach past `R-STATE-17`, which puts a process
outside every group Rigger created, and outside every dispatch's directory, beyond the rule. It could
also end a consumer's own `git maintenance` mid-run. Resuming puts the process where it would have
been had the stop never reached it, which is outside containment, as the existing sentence promises.
Where it works in a dispatch's directory, the census that follows still ends it. L0 records each
resume by name and command line.

**Order.** This is a proposal, and the owner's merge ratifies it (`D21`). #539's fix merges only
after it.

**Revised under O62 (ruling 14).** The engineer judge on #545 showed that "never" promised more than
L0 could find. Git's `daemonize()` exits the parent before its child calls `setsid`, so a route
through the parent missed about a quarter of cases under load. Ruling 13 offered a narrowed promise,
(A), or never stopping a group, (B). The owner chose (B) as O62. Ruling 11's resume sentence is
withdrawn. The Failure model now says L0 never stops a process group to contain it. It reads the
group, kills it whole, and kills and reads again until no member lives. A process the kill ended
that no read before it found is recorded as the kill of the group. The first sentence of the
paragraph now records a process by name only where a read before the kill found it. Nothing is ever
left stopped, so a child that detaches mid-kill dies or leaves running. #539 builds (B) after a
spike, and merges after this card.

**Two exceptions written in (O70, ruling 15).** #545's engineer judge found that "until no member is
left alive" claimed more than L0 does. Where L0 cannot read the process table, `ended` treats a
failed read as no live member. It settles once `UNREAPED_BOUND` passes, without knowing the group is
empty. A member L0 may not signal (`EPERM`), or one held in an uninterruptible wait, kept the loop
going with no end, so the call never settled. Under O70 the sentence now names both exceptions. The
second rests on a bound #539 builds, after which L0 records each process it could not end by name
and command line, and settles. Until #539 merges, that second exception describes the code #539
delivers, not the code on `main`.

**The census gets the same exception (ruling 17).** #549's architect judge found that `R-STATE-19`'s
"not ended" reaches the directory census as well. Today the census kills by pid, then gives up after
`UNREAPED_BOUND` and records the process as killed. That record is false for a process L0 may not
signal, or one held in an uninterruptible wait. The census paragraph now says that L0 records such a
process as one it could not end, and waits on it no further, under the same longer bound. #539
builds it on each path the census runs on.

**An unreadable census, written in (O72).** Under O71 `R-STATE-19` gained a third sentence, for a
dispatch's directory whose processes L0 cannot read. The census paragraph now says that, in that
case, L0 records the directory and why in their place, and waits on them no further. It sits directly
after ruling 17's sentence.
