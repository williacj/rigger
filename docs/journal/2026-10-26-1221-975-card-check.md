# Card 975: the pre-dispatch attack checks five card defects, and `check:card` runs two of them

The acceptance skill's "Have it attacked before dispatch" now names five defects the second agent
checks, and the convention that pinned binding-document text is fenced with `markdown` first in
its info string. `npm run check:card -- <body-file> [root]` checks the first defect, and spec-style
rules 1 and 2 inside each pinned fence. It refuses no card, so `R-CARD-8` stays the whole of the
engine's form check, and it enforces no rule of `D17`.

The retired-id reader the #978 attack placed in `scripts/duplicate-id-check.mjs` landed here as
`retiredIds(root)`, because this card reached it first. It returns a `Set` of the ids
`requirements-retired.md` holds as `idRows` reads it, and the `D#` of each `## D# —` heading in
`decisions-retired.md`.

The word cap set the skill's form. The first draft held the card's own sentences and measured 134
words over the base with `npm run budget:instructions`; the cap is 80. The section names for
defect 3 cost thirteen words alone, so defect 3 cites "Write each item", the section that holds "A
list of instances is evidence for a class", rather than that sentence.

`check:card` reads fences without importing `src/workflow/form-check.mjs`, so the opening and
closing patterns of `R-CARD-35` and `R-CARD-26` are written twice. A body directory or a register
that is a directory fails with `EISDIR`, whose message names no path, so the script adds it.

The first tests ran the script as a child process, and the suite's deterministic tier refused every
one: `test/suite-guard.cjs` admits only `git` and `tar` there. So the command is the exported
`main`, which the tests call with a body file and a temporary root, and the script's own last line
only hands it `process.argv`.

Round 2 found two gaps. `ruledOutTerms` throws only where the one-term rule is missing; a rule
naming no spelling reads as an empty set, and `check:card` then passed every pinned term as clean.
It now exits 2 naming the skill. The convention's "and nothing else" left an example's fence
unsaid, and the skill's own example acceptance was fenced `markdown`, so the convention now says
an example takes another info string or none, and that example is fenced `text`.

What taught us: a word cap on a checklist is met by referring to sections, never by shortening
the defects, because a reader acts on the defect's own words.
