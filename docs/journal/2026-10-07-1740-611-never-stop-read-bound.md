# A named survivor needs a post-kill answer before the next directory listing

At base `c3cb2ab32f89c47345966502dd96c8cfb965fbe8`, the target's post-kill `lsof` can consume almost all of the exit cleanup's read bound. The read driver then enters `reaped` with no post-kill state answer. An `ETIMEDOUT` first state read records “not shown to have ended: the process table could not be read,” even though the earlier directory sweep named the PID and sent its kill. `LATE` has the same branch in `reaped`, but none of the counted failures used it.

Twenty instrumented file runs on the base measured five passes and fifteen target failures, at start loads from 1.68 to 3.46 by `uptime`. Every failed trace recorded the named outside PID, its `SIGKILL`, a post-kill `lsof -w -n -P -a -d cwd -u 501 -F pun` `ETIMEDOUT`, and the first `reaped` `ps -p <outside PID> -o pid=,stat=` `ETIMEDOUT` with no prior post-kill answer. Each passing trace recorded a post-kill state answer before a later `LATE` or `ETIMEDOUT`. The complete traces and outputs are in `c611-base-file-01.log` through `c611-base-file-20.log` under the external task TMPDIR, with a runner result and start/end load in each.

The deterministic fixture marks the listing after the named kill and cuts only the census's starting clock by 150 ms. It keeps the configured read bound, sends the same kill, and leaves more of the kill-relative bound for the first `reaped` state read to start and time out. It neither sleeps nor waits on a timer. Ten consecutive forced base target runs failed the original exact-reason assertion; each marked the post-kill listing and state-read timeout, with no live state marker. Their full outputs are `c611-forced-base-01.log` through `c611-forced-base-10.log` under the external task TMPDIR. #579's measured pre-kill unnamed mechanism does not explain these named failures.

The L0 fix asks `ps` for newly killed PIDs' states immediately after the named kill, before another directory listing can spend the remainder of the sweep bound. It keeps a live answer for `reaped` if a later state read hits its deadline and skips one already shown ended. A failed optional look leaves the directory sweep running; no answer is invented. Ten consecutive forced local-head target runs passed the original guarded record and marked both the early live answer and timed-out later read (`c611-forced-head-local-01.log` through `c611-forced-head-local-10.log`).

Four tests tied to the early state observation failed with head tests over base `src/` and passed on the local head: the guarded target, a late listing, an early zombie and an early gone answer (`c611-fix-tests-base-2.log`, `c611-fix-tests-head-2.log`). Thirteen new controls passed over base `src/` (`c611-controls-base.log`); their already-correct public outcomes are not credited to this fix. The first local `npm test` passed 2,511 tests, with 2,494 passes, no failures and 17 skips, at start/end one-minute loads 1.23/4.31 (`c611-full-head-local.log`). `npm run budget:package` passed at 4,710 production lines, and `npm run matrix:check` passed after regeneration.

The late-listing control uses the cleanup's default read timeout. Its forced `LATE` comes from the existing clock stand-in, without increasing any configured bound.

The existing clock-forcing stand-in first failed in `c611-affected-1.log` because it treated the added optional read as an unexpected read. That fixture was retargeted, and `c611-affected-2.log` passed its 93 then-current tests. The first focused head run with a stricter state-timeout marker failed because the read was `LATE` before its stand-in started (`c611-fix-tests-head.log`); the targeted census clock cut made the intended `ETIMEDOUT` outcome repeatable. The base diagnostic pilot failed its F1 clock test because temporary tracing called `Date.now()` when disabled; the tracer was corrected before any counted base run (`c611-base-file-pilot.log`).

The card's historical #604, #647 and #686 assertion diffs establish the same reason mismatch, but they do not identify their failed argv. The current-base traces do: all fifteen counted mismatches used the first post-kill state read's `ETIMEDOUT` cell after a timed-out listing.
