# #408 — `init` never writes a remote's credentials into `rigger.config.mjs`

## What was learned

- **The pattern could not see the host.** `SLUG` took the last two segments split by `:` or `/`.
  With one path segment after the host, the second-to-last segment is the authority, so the
  userinfo and host were read as the owner. Two-segment remotes read correctly only because the
  authority was never reached.
- **Dropping the userinfo alone would not have been enough.** Without it,
  `https://github.com/widgets` still reads as `github.com/widgets`: no credential, but a host
  named as an owner. So the fix drops the whole scheme and authority, or the `user@host:` of an
  scp-style remote, and reads the owner and name from the path alone. A one-segment remote now
  yields no owner and name, and `init` writes the placeholder and says why.
- **A test about a secret can leak it through its own failure.** `assert.equal` prints the
  actual value on failure, so the red run printed the fake token in the error's `actual` field.
  The placeholder check uses `assert.ok` with a redacted message instead. The token is fake, but
  the pattern is the one a real test would copy.
