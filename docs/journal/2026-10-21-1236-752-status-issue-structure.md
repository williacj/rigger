# Card #752: the status issue's structure

The draft had L2 prefer the issue an existing hold's closer names, but no sentence said how L2
learns those numbers. L3 alone reads `.rigger/admission/`, and L2 reads only what it is handed or
what L0 shows it. A preference over facts one layer cannot see is a boundary crossing written as a
tie-break. The delta now has L3 hand the numbers to L2's notice function.

The same gap sat in the per-trigger placing: "L2 places it at each trigger" named no caller. L2
runs only when another layer calls it, so every "at each trigger" sentence about L2 needs the L3
call that starts it.

The shape rule listed what L2 alone chooses, and left out which issue it closes. A runner that
admits a close by shape can close any issue, a card's included. Every write a runner admits by
shape needs every free part of it named as L2's.

"It comments on that issue naming the card" restated `R-SCHED-25` and dropped half of it, the
reason. A citation can't drift that way.

Round 1's judge found two schedules the draft missed, and both came from one gap. The close of an
issue was read as an event with no author and no history, so a close by `resume` on behalf of
other holds, and a close of an issue that had stopped being the notice, both looked like the
owner's. The fix has L2 judge each close against the issue's timeline. Walking every interleaving
of `resume`'s three writes against a hold's five steps, as a table, found the one order a
comment-after-close would have lost.
