# #1304 — the release decision

`D33` is the id the card's acceptance names. At `origin/main` `52fb8a3d` the register's table ends
at `D31`, and no binding document named `D32` or higher. Two checks of the open pull requests'
diffs of `docs/spec/decisions.md` gave different answers.

- Before drafting: five pull requests were open, and only #1268 changed the register. Its diff
  allocates `D32`, which supersedes `D31`, so `D33` was free.
- At the push: nine were open. #1268 still allocates `D32`. #1318 (card #1305, opened
  2026-11-09T03:34:57Z) also allocates `D33`, for "A test fault is fixed on the card that finds
  it", and its acceptance binds it to that id.

The table skips from `D31` to `D33` until #1268 merges, and `npm run check:ids` reports 0 ids
allocated more than once on this branch alone. Whichever of #1318 and this card merges second
duplicates `D33` and reds the build. The id is the card author's to move, so the card escalates it
as `ambiguous`.

The tagged commit is the commit under test, not the commit that closed M8. The pre-dispatch
attack on #1304 (finding 3) showed why. A commit after the exit run that changes the packed
tarball, such as the README update M8's "Then" asks for after the publish, moves the closing
commit under `D7` rule 4. Whether that commit also moves what `D7` rule 1 promotes is left to the
Phase B release card's filing, and `D33` holds either way.
