# Boundary entry-point spike, card 1151

The audit measured main commit 4f43b740fa3078a0913c9483d0dab39f6e145722 after #1146 merged. The [report](../spikes/entry-points-l1-l5-cli.md) holds the search, value maps, probe links and proposed fix cards. The deterministic baseline passed 4,208 tests with zero failures.

The most consequential result is that syntactically valid JSON is insufficient as a boundary check. L1 accepts a nonfinite number in an extra group-record field, while L5 accepts null and incomplete event records. The latter can later make report derivation throw an unbuilt TypeError. A substring in a malformed event stream can also trigger a telemetry push. These are different entry points and need separate fixes from CLI display.

The CLI argument dispatcher passes extra words to nine verbs that never read them. A terminal escape in an unknown verb, a closer path, several diagnostics or event-stream text can reach output unescaped. Text parsers that preserve controls inside L2 still satisfy the inside-string contract; the print site owns making that text printable. This separation keeps the next cards at the boundary rule's intended edge.

The first probe run stopped on my fixture's missing parent directory. A later print probe failed because its temporary copied module resolved imports relative to spikes; another failed on a malformed fake board response. A final expression probe initially matched two verdict lines. I corrected those fixture errors and retained their full outputs in the maker scratch directory. They are probe failures, not Rigger failures. The final probe sources and unfiltered outputs are linked from the report.

The reviewer found that my first map collapsed positions whose observed behavior differs. I probed JSON bytes inside and outside strings across five readers, starter/provider/target-hook positions in init, pre-write Git hooks, and root versus nested workspace entries. The existing target hook read can fail after config is written; a provider symlink can read foreign bytes; a nested CLI directory is traversed. I rebuilt the print inventory from the source response search and expression positions, then verified the config-error path through actual setup, plan, once and run calls. These findings extend the same seven proposed cards without changing production code or tests.

I propose seven fix cards and no production edit in this spike. The proposed line additions fit the measured layer budgets, but the future makers must remeasure at their own bases and obtain grants for any existing test lines they need to change. The report and this journal entry are the only authored prose in this branch; the probes stay ignored under spikes.
