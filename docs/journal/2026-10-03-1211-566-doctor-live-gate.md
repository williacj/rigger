# #566 — the real-CLI sign-in comparison moves behind RIGGER_LIVE_CLAUDE

**Why.** `test/doctor.test.mjs`'s agent CLI test took `npm test`'s refusing `claude` off `PATH` and
asked whatever `claude` came next, twice. A recording `claude` first on the inherited `PATH`
recorded `claude auth status --json` twice at `f06aca9`, so `npm test` depended on the host having
a real agent CLI. The owner ruled (O82) that `npm test` never calls one.

**Where it went.** The comparison lives in `test/doctor-claude-live.test.mjs`, its own file like
the other live runs (`test/claude-live.mjs` says why). It takes the gate and the `PATH` past the
refusing stand-in from `claude-live.mjs`, whose `pastRefusing` does what `doctor.test.mjs`'s own
`pastRefusingAgents` did. That copy had no other caller, so it went. The skip message is the file's
own, because `claude-live.mjs`'s says a live run starts a session and this one starts none.

**What to know when running it.** With `RIGGER_LIVE_CLAUDE=1` the test asks the first `claude` on
`PATH` past the refusing one. That lets a stand-in answering a recorded `loggedIn` stand in for
the installed CLI. The mutation runs used one, so they never reached the real CLI.

**Left as it was.** `doctor.test.mjs` still imports `delimiter` and `claudeAdapter`, which nothing
in it now uses. Their import lines are outside #566's grant table, so they wait for a grant.
