ABOUTME: Records card #1333's Codex probe host seam, controlled test routes and retained executable boundaries.

Scope and acceptance: [#1333](https://github.com/williacj/rigger/issues/1333), acceptance revision `dd6d29147658`. The card owns the grants, Table H and the two admitted route B cases.

I pass the optional host from `invocation` through its private skill probe to L0's existing `runCommand` host port. Omitting it retains that port's default. L1 production code is outside this change.

The controlled fixture reuses `logicalCodex` and `manualClock`. Its ChildProcess events and streams follow `test/process-host.test.mjs`; its process-table responses implement the documented census columns. Its clocks, reads and signals describe a logical process, not an OS process.

L1's scratch checks still use the permitted git executable. The fixture scopes the default host's clock and signal port for those checks, following `test/clock-firing-world.mjs`, and restores their descriptors after the test. The Codex adapter map and L1 dispatch receive the controlled host. A hanging probe is observed starting before its bound is advanced.

Route B preserves two executable premises. The TMPDIR writer executes `writer/codex`, a shell program that writes the file using the environment L1 handed to a real session. A logical write would not establish that OS environment boundary.

The judge case preserves `installFakeGh` and its executable `gh`. That installer unconditionally calls `warmed(gh, [WARMING])` in `test/fake-gh.mjs`; the Codex probe host cannot replace that start. No forge call is inferred merely from that installation. The case also retains the executable Codex session for its main/head arguments.

The first H2 test failed before source edits, at base `a3fd41c724935fd9edaa587dd2cb54860d0faf27`: its `doesNotReject` assertion reported that the probe escaped the supplied host. Its native-start tripwire prevented an actual Codex start. After the four forwarding edits, the identical test passed. The retained logs are `1333-h2-red.log` and `1333-h2-green.log` in the card's scratch directory; their command exits are 1 and 0. The PR holds subsequent verification and counterexample receipts.
