# 2026-09-27 — The demo tape runs an installed rigger in a world built from test fixtures

The tape needs a `rigger` installed from the tarball outside the checkout, a consumer repository
outside it, and a PATH on which the fake `gh` is the only `gh`. That is a composition of test
fixtures and nothing else, so the architect placed it under `test/` (`D18` rule 2, ruling on
#239): `test/demo-world.mjs` builds it from `test/installed-rigger.mjs`, `test/fake-gh.mjs` and
`test/git-repository.mjs`, and `test/demo-world.sh` is the one entry the tape sources in a hidden
block, because a PATH and a working directory reach only the shell that sets them. The pack-and-
install sequence moved out of `test/package.test.mjs` into `test/installed-rigger.mjs` so that it
exists once. `.github/workflows/ci.yml` gains only the vhs step and its checks.

**CI reads the tape's own record of the screen.** vhs writes a `.txt` output holding the
terminal's text after the last recorded command, so the tape names one beside the GIF and the
demo job greps it for the claim line and for the `exit 1` the tape types `echo exit $?` to show.
No status file, no wrapper around `rigger`, and nothing the viewer does not see. The suite runs
the workflow's own grep and `test -s` commands over a hand-written screen and its broken variants,
so a check that stops discriminating reds here first; three mutations of the workflow confirmed
each test reds on its own assertion.

**A plain YAML scalar cannot carry the message.** The first demo run never started: GitHub
reported a workflow file issue, because `once: claimed #12` holds both `: ` and ` #`, and a plain
scalar may hold neither. The two grep steps are double-quoted scalars, and the test that reads
`run:` lines strips that quoting. Parsing the workflow with a YAML loader before pushing would
have caught it; nothing in the suite does, since Node ships no YAML parser.

**The narrow PATH is narrow.** The first test reached for `wc` inside the world and found nothing,
which is the world working as designed: the tape's shell holds node, git, `rigger` and the fake
`gh`, and nothing else. The test counts in JavaScript instead.

**A deliberately red run still has to pass the gate.** The acceptance wants CI red on a commit
where `once` exits zero, and the pre-commit hook refuses any commit whose suite is red. So each
throwaway commit changes `src/cli/once.mjs` and the assertions that read it together: the exit
flip moved the claim line to stdout, because the entry point picks the stream by the exit code,
and the test helpers on that branch read both streams. Both throwaway runs then red on exactly
the demo step aimed at, with the check jobs green, which is the cleaner evidence.

**A tracked GIF has no header to carry.** `AGENTS.md`'s header rule exempts one format, JSON, and
`npm run check:headers` refuses any other tracked file without an `ABOUTME:` line; measured at
2ff1609 by staging a probe GIF, which the check named. So the GIF the acceptance commits under
`docs/` cannot land without the owner: the card escalates that item as `ambiguous`, with the
exemption or a GIF comment extension as the two routes.
