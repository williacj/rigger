# Run lifecycle rows for a sound card's checks

Card 1511 asks what Rigger does with a card every judge has ruled sound while the consumer's
checks have not all passed. Its K7 digest was `3ba14c55d18f` at the start. Done means every
acceptance item met at the head, the rows a proposal in this pull request, and the checks green.

The proposal adds `R-SCHED-56` to `R-SCHED-62` and `R-ESCALATE-28` and `R-ESCALATE-29`, each with
a dimensions table. A run with no clock trigger declared stays up at drain while such a card can
still merge. A passing card merges within the run's interval plus one pull's reads. A failed check
escalates the card as ambiguous, and a check that neither passes nor fails escalates it after a
bound the consumer sets, two hours by default.

Escalating rather than dispatching a maker was the one real choice. Dispatching keeps a work
fault off the owner's desk, but it breaks `R-FAIL-2` whenever the cause is the environment, which
Rigger cannot tell. The pull request carries the alternative as an open question.

The wait runs from times the forge holds, the last sound verdict and a check's latest start, so
that a restart neither loses nor resets it. A re-run's start restarts the wait, so that the owner
re-running a check and removing the label is not escalated again at once.

Emend's event record, read at `refs/rigger/events` commit `273cdc44`, settled two readings. The
start the coordinator expected at 23:36Z was two intervals after the run's start, while the
README counts one interval from its exit; the next start came 3600.3 s after that exit. And
`doctor`'s calls carry a run id of their own, which meets `R-RECORD-7` and feeds no `R-RECORD-2`
signal.

The failed forge reads were the surprise. In the run counted, all seven fell between 340 and
377 ms, and three sat inside a card's re-read that went on to merge. Emend's main has no classic
branch protection, and the rules read takes that 404 as an answer, so a fault rate counts it. That
is named for the architect, not written as a row.
