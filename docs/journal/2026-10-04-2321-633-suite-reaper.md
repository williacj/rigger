ABOUTME: Records why the test suite needs a run-scoped reaper, the process evidence used to shape it, and the limits of the probes on card #633.

# Card #633: end a test run's processes when its shell dies

The old suite made a directory for its refusing `gh`, but left each test's temporary directory directly under the caller's `TMPDIR`. A test's `scratch` teardown ended processes naming its directory, but a killed test-file process could not run that teardown. A SIGTERM to `test/suite.sh` left `node --test` running; a SIGKILL to its process group also left fixtures in other groups. The card's seven endings and seven fixture kinds fixed the scope of this work.

The suite now makes one directory per run and passes it as `TMPDIR` to the runner. It starts a reaper in a group of its own, then holds the write end of a FIFO that the runner cannot inherit. The reaper reads to end-of-file, finds processes whose command line or working directory names the run, includes the runner and its descendants, kills each by PID, and removes the run directory after none remains. The runner carries a no-op `--require` path inside the run so the reaper can identify it without relying on a reused PID. A normal shell exit waits for the reaper; SIGTERM and SIGINT are passed to the runner; SIGKILL closes the pipe without a shell trap. The reaper uses the same `SWEEPS` bound as the existing scratch teardown and the existing temporary-directory removal routine.

The first version of the reaper was a `.mjs` file directly under `test/`. A full `npm test` run discovered it as a test and the repository's process-spawn check found that its dynamic command lacked an explicit environment. The full output was captured in `c633-head-development-suite.log` on 2026-10-04. Moving the reaper to an extensionless test helper and passing `env` to its read-only process commands fixed both failures; the affected 67-test run in `c633-affected-after-helper-move.log` passed.

The corrected matrix has one test for each in-scope ending and fixture kind. The base comparison used an HTTPS clone at `e38887102ffebbb9c6c0be28da67c1942e4a4cd0` with the exact head test file copied into it and the base's three existing fixture and suite files unchanged (`cmp` and `git diff --exit-code` on 2026-10-04). `c633-base-49-cells.log` recorded 17 passing and 32 failing cells; each failure named a surviving process. `c633-e1-e7-f1-f7-all-2.log` recorded 49 passing cells in the working tree. These are measurements of the named runs, not predictions about other hosts.

The full `npm test` run after the final PID guards in this working tree started at one-minute load 2.32 on 2026-10-04, ended at 14.77, and reported 2,258 tests, 2,248 passes, zero failures, and ten skips (`c633-head-before-commit-suite.log`). The suite at base, in the HTTPS clone, reported 2,209 tests, 2,199 passes, zero failures, and ten skips; its start load was 25.52, above the card's evidence bar, so that run is historical baseline diagnosis only (`c633-base-suite.log`).

The full-run interruption probes each waited for 500 reported tests. In the working tree, `c633-probe-head-term.log` and `c633-probe-head-group.log` recorded no `ps` or `lsof` survivor ten seconds after SIGTERM to the recorded suite-shell PID or SIGKILL to the recorded npm group. At base, `c633-probe-base-term.log` recorded 41 live process rows after SIGTERM, including the orphaned runner, and `c633-probe-base-group.log` recorded two after group SIGKILL: a `tail` and a stand-in agent. Each log records its starting and ten-second load, process count, runner PID, process tree, process CPU use, and cleanup result. The probes ended their own surviving PIDs after recording them.

An earlier 49-cell run ended with exit 137 after 19 passing cells, immediately before F3 E6, and left no process from its run. The likely cause is the E6 PID-file race: `writeFileSync` can make `file-pid` visible while it is still empty, `Number('')` is zero, and the earlier E6 path could signal PID zero, killing its own process group. This is an inference from the stopped cell and the race, not a captured signal trace. A judge reproduced empty reads; the deterministic regression in this revision failed on the empty PID before the fix and passed after E6 waited for a positive integer. The interrupted run's full output is in `c633-e1-e7-f1-f7-all.log`.

The extra process is the reaper. While the shell lives, it waits on the FIFO and does not end a fixture merely because that fixture's own parent exits. The matrix's F2 and F3 cases observe their parents exit while the tail remains alive, and the F4 case observes both the leader and its tail before ending the run. The existing scratch teardown still sweeps before removing its directory last, as the full suite's teardown tests verify.
