# #479 — a card's facts are read beside the board's, not among them

**The new reads are `repositoryReads`, a second export of `read.mjs`, not keys of `readSide`.**
Three tests that this card may not change compare `readSide`'s keys with something else, both
ways: `test/forge-adapter.test.mjs` with the fake board's operations,
`test/forge-board-owner.test.mjs` with its `OPERATIONS` table, and `fullRead` in
`test/forge-read.test.mjs` calls every key with no argument. A key added to `readSide` reds all
three. The repository reads take a branch, an issue or a pull request, which none of those tables
can call.

**The fake repository is its own module, `test/fake-repository.mjs`.** The card's Lands-in names
`test/fake-board.mjs`. That file's header says the fake board holds "no card's linked pull
request", and its item rule refuses an item naming one, and the card grants no existing line there.
So the pull requests went beside the board rather than into it, with the reads compared both ways
against `repositoryReads` as the board's are against `readSide`.

**GitHub's GraphQL has no merge base.** `Comparison` holds `aheadBy`, `baseTarget`, `behindBy`,
`commits`, `headTarget`, `id` and `status` (introspected with gh 2.99.0 on 2026-10-01), and
`PullRequest` holds no field naming one. The merge base is read from the REST comparison of the pull
request's base branch and head SHA. For #497 on 2026-10-01 it answered `ef60b49`, which
`git merge-base origin/main 559db5b` also gave. The diff `gh api` printed for #497 under the diff
media type was byte-identical to `git diff ef60b49 559db5b`.

**The comparison's path names two refs, so the fake's command for it shapes both.** `commandOf`'s
grant puts a placeholder for each number and for the repository in a REST path, so one key answers
every pull request. A comparison's path holds a branch name and a SHA instead of a number, so it is
shaped as `compare/_..._`. That is the grant's purpose, and more than its words; the pull request
says so.

**Several branches are answered from one listing of the repository's branches.** One request per
name, or aliases in one request, would give the fake `gh` a different command for every count of
names. Listing `refs/heads/` a page at a time keeps one command, and answers any number of names in
one call. On this repository that listing held 25 branches on 2026-10-01, one page.

**A body never edited answers null.** `Issue.lastEditedAt` is null until the body is edited (#479
answered `2026-10-01T13:20:50Z`). The read answers what the forge holds rather than standing the
issue's creation time in for it.
