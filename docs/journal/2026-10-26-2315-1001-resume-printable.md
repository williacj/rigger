# `rigger resume` prints an unreadable admission's entries printable

Done for #1001 means its acceptance revision `4c408ff93fbb`. [The architect's attack on this
card](https://github.com/williacj/rigger/issues/1001#issuecomment-6433437350), finding 1, ruled that
both of L3's rejections for an unreadable admission carry the entries as `unreadable`, the array
`read` answered, unchanged. `resume`'s rejection now does. Its message is unchanged, so a caller that
prints only the message, and the existing tests that read it, still read the paths raw.

The words stay in the CLI. `src/cli/resume.mjs` prints a rejection carrying `unreadable` through
`doctor.mjs`'s `unreadableAdmission`, which writes each path and cause through `printable`. Any
other rejection, such as a removal that failed partway, still prints its message. So ", so resume
removes nothing" no longer prints for an unreadable admission. `resume.mjs` defines no escaping of
its own, and a new test holds it to none of the instances the card names. That held the ABOUTME
line to the same rule: a first draft of it said "printable", and the test would have refused it.

#1004 had not merged when this branch was cut from `9da9cd5a`, so its test that no file under
`src/scheduling/` imports from `src/cli/` was not there. `test/resume-printable.test.mjs` adds one
that does its own reading and shares no helper with `test/printable-closer.test.mjs`. Once both
cards merge, the two tests overlap. That overlap is what the card's acceptance item names, and
merging them would be its own card.

The Table A tests were appended to `test/pause-resume.test.mjs`, since they need that file's
scratch repository and git asker. A new file would have needed a copy of the asker. The appended
block brings its own two imports, because changing the file's existing import lines would change
existing lines under `test/`.

The process fell short once. The first round wrote the three Table A tests about printed words
together, and ran them red together. The reviewer's round 1 finding on PR #1012 blocked on that. In
the rework, the printing code in `resume.mjs` went back to `9da9cd5a`, the three tests were taken
out, and they were added again one at a time.

Row 1 went red at 23:35:34 CDT, because the old clause still printed. It went green at 23:35:44
with the one-line call to `unreadableAdmission`. Rows 2 and 3 then passed on their first run, and
this is the cause. `unreadableAdmission` makes both the path and the cause printable in one call,
and `printable` is private to `doctor.mjs`. So whichever row went first, its minimal code brought
the other two rows' behaviour with it, and only a contrived intermediate copy of doctor's words
could have made a second row red. The owner chose to take the one red-to-green step as covering
rows 1 to 3 ([U84](https://github.com/williacj/rigger/issues/740#issuecomment-6433937167)).
Mutations M1, M2 and M4 are what show rows 2 and 3 discriminate. Rows 4 and 5 already held at
`9da9cd5a` and were never red: they hold behaviour this change must keep, and mutations show they
discriminate.
