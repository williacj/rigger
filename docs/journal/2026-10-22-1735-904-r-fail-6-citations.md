# Card 904: ARCHITECTURE.md cites R-FAIL-6 and names the out class

[#904](https://github.com/williacj/rigger/issues/904) proposes the structure delta that follows
[#875](https://github.com/williacj/rigger/issues/875). Once #875 retired `R-FAIL-5`, "Failure
model" still cited it three times. Each citation rests on a row `R-FAIL-6` holds unchanged, so
the delta changes only the id there ([K57](https://github.com/williacj/rigger/issues/740#issuecomment-6342343334)).

[K60](https://github.com/williacj/rigger/issues/740#issuecomment-6342491227) also has the card name
K56's third class, `out`. "Failure model" now lists L2's classes as the work's, `environment`,
`card-local` and `out`, and says `out` answers `stop`, never `again` or `hold`. The workspace entry
in the environment list now reads as `R-FAIL-6`'s host row, so it no longer retries the two
configuration causes U30 stops with no second attempt.

The first judge found that narrowing dropped a host row. A continuing workspace whose fetch fails
with an answer was in no class once the list became the whole of `environment`. The list now
names each of `R-FAIL-6`'s five host rows in that table's terms.

[K63](https://github.com/williacj/rigger/issues/740#issuecomment-6352704763) places the memory row.
L3 keeps a card stopped for a refused branch name or a relative worktree root out of later pulls
in the invocation. A line moved or deleted since L2 read it gets no row, because `R-FAIL-6` has the
next pull read the forge again.

What taught us: L2's class value and `R-FAIL-6`'s class column share a word but not a scope.
L2's `out` covers three of that table's out rows, and L2's `environment` takes in a judge withheld,
which the table classes out. Naming the two apart in the document is what keeps either from being
read as the other. Narrowing an entry to exclude a cause can also drop a row the entry carried, so
check each row of the source table against the narrowed list.
