# 2026-09-24 — The live instruction pool budget rises to 14,000

The owner ratified 14,000 words for Rigger's live instruction pool on 2026-09-24, on the evidence
card #161 produced. `ARCHITECTURE.md` owns the figure and `scripts/instruction-budget.mjs` reads
it from there rather than typing it, so the change is one figure on one line.

Card #161's maker measured that the architect's role prompt takes the pool past the old 13,000 and
suggested about 14,200 rather than 14,000, because 297 words of headroom is thinner than the 449
this milestone has worked with. The owner chose 14,000. The headroom is therefore a choice, and
this card did not reopen it.

be used to check these.

neither merge reached the work. The `AGENTS.md` pool is
pooled separately and was not touched: 2,084 of 2,500 at every ref above.

## What claims the figure

Nothing did. The old figure appeared in five places in the tests. Four are fixtures — a synthetic
`ARCHITECTURE.md` written into a temporary directory so the reader has something to read — and a
fixture asserts nothing about this repository's own budget. The fifth is the typed-figure guard
below, which asserts the opposite: that the figure is absent from the scripts. So the document
could have recorded any figure at all and the suite would have stayed green. The four fixtures
still say 13,000, deliberately: each states the budget its own case needs, and a fixture that
tracked the ratified figure would be claiming to be something it is not.

`test/instruction-budget.test.mjs` now reads the real document and asserts the live budget is
14,000. Its red was the document's own prior state rather than a synthetic mutation: before the
one-figure edit it failed `13000 !== 14000`, which is exactly the defect it exists to catch, an
unratified figure in a document only the owner may revalue.

The same test also covers a second defect. The Budgets section ends two sentences with "budget is
N words", the `AGENTS.md` pool's and the live pool's, and `liveBudget` tells them apart only by
the words in front of them. A reader that latched onto the first would return 2,500 here.

## The guard that had gone quiet

`test/budget-checks.test.mjs` asserts that neither budget script types a figure, against a list of
the figures that must not appear. The list named the old figures, so on the day the live budget
became 14,000 it would have stopped guarding the live figure while still passing.

A mutation showed the cost. Replacing `liveBudget`'s throw with `return 14000` — a fallback, which
is what `D8` bars — left `each check refuses to run at all once the architecture stops stating its
figure` green, because the `AGENTS.md` reader still throws on a silent document and the script
still exits non-zero. Only the typed-figure list caught it, naming the script and the figure. At
the base ref, where the list lacks 14,000, the same mutant goes green on the whole suite — so
leaving the list alone would have disarmed the one guard that existed.

Then the same fault turned up in the list itself, one budget over. It named 2,000 for the
`AGENTS.md` pool, which `ARCHITECTURE.md` retired when it raised that budget to 2,500, and it did
not name 2,500. `return 2500` planted in `instructionBudget` left the guard 8 of 8 green while the
script typed a figure the document records. That gap was harmless, because `an architecture stating
no word budget fails rather than guessing` asserts the throw and so catches a fallback whatever
figure it returns. The list is now the full set either budget has been recorded at: 12,000 for the
package, 2,500 and the retired 2,000, 14,000 and the retired 13,000.

The lesson is about the kind of test rather than the contents of a list. A list of figures names
values where it means a property — that neither script types a budget — and it goes quiet whenever
the values move without it. The fixtures at `test/budget-checks.test.mjs:35`, `:90` and `:105` name
values too and are safe, because there the value is the fixture's own and nothing outside can
revalue it.
