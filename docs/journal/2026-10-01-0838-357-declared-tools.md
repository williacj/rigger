# #357 — what a dispatched agent may reach is the repository's to say

**The need came from a spike, not a failure.** The M2-S1 spike's headless Claude Code runs
connected the owner's claude.ai Gmail and Shopify connectors in every run
(`docs/spikes/what-leaves-the-process-group.md`, "The MCP servers it declared"). No maker has used
one. The owner ruled that a dispatched agent may use only what the consumer's repository declares
("Spike #355 findings", on #332).

**"Tools" already meant something else in the register.** `R-SAFE-1` and `R-SAFE-2` use it for the
programs Rigger itself calls. So the new row scopes the word to itself, as an action the agent CLI
offers the agent. "Connector" appears in no binding document, so the row defines it too.

**The card's words left the built-in tools to a guess.** None of this repository's role prompts
lists a tool, so read strictly, the card's row would leave a maker no shell and no editor. The row
counts each built-in tool as declared unless the repository withholds it. That is the PM's
reading, and the pull request puts it to the owner as an open question.

**What the row does not reach.** Skills, hooks and settings in the owner's own account load into a
session too: the coordinator-dispatched session that wrote this row was offered the owner's
personal skills, which no file in this repository declares. No ruling and no evidence
covers them, so the pull request names them out of scope rather than widening the row.
