# #357 — what a dispatched agent may reach is the repository's to say

**The need came from a spike, not a failure.** The M2-S1 spike's headless Claude Code runs
connected the owner's claude.ai Gmail and Shopify connectors in every run
(`docs/spikes/what-leaves-the-process-group.md`, "The MCP servers it declared"). No maker has used
one. The owner ruled that a dispatched agent may use only what the consumer's repository declares
("Spike #355 findings", on #332).

**"Tools" already meant something else in the register.** `R-SAFE-1` and `R-SAFE-2` use it for the
programs Rigger itself calls. So the new row scopes the word to itself, as an action the agent CLI
offers the agent. "Connector" appears in no binding document, so the row defines it too.

**The card's words left the built-in tools to a guess.** None of this repository's role prompts
lists a tool, so read strictly, the card's row would leave a maker no shell and no editor. The row
counts each built-in tool as declared unless the repository withholds it.

**A built-in tool can be a connector in all but name.** Two round-1 judges found the gap: Claude
Code's browser integration and Codex's browser and computer-use features ship with the CLI and act
through the owner's signed-in sessions. Deemed declared, they escaped the "never". The owner's O25
(on #357) counts such a tool like a connector: never used unless the repository declares it. The
row became a lead row and two continuation rows, `R-SAFE-7` to `R-SAFE-9`, because what counts as
declared now turns on three conditions.

**What the rows do not reach.** Skills and hooks in the owner's own account load into a dispatched
session too: the session that wrote these rows was offered the owner's personal skills. Those are
`R-SAFE-6`'s, under architect rulings 1 (Q1) and 4 on #467, so these rows leave them alone. A
plugin's tools and connectors are within them.
