# Report's redos after an interruption

Card #1068, acceptance revision `b2f43df6efc0`, implements `R-STATE-3` under
`ARCHITECTURE.md`, "What `report` derives" and "Redos after an interruption".
The [architect's redo ruling](https://github.com/williacj/rigger/issues/1009#issuecomment-6440744086)
places this derivation in L5. `R-WORK-24` owns the separate restart from Review whose
transition carries `redone`; that transition contributes no attempt here.

`workClaims` remains the one definition of a work claim. It now retains the pull,
whether the claim dispatched, and whether it released its slot. L2 still counts all
work claims, including those that dispatched nothing. L1 walks the retained claims in
stream line order and remembers each card's most recent work claim that dispatched.
Only an interrupted predecessor in another run makes the current attempt a redo.

The CLI prints the redo count beside the first-attempt count after the stream's
survivor rate, then names each redo by card and run. It adds no per-run attempt figure.

The first test covers single, empty, provisioning-only and merge claims; dispatches
before a pull, under another card or another layer; repeated dispatches; normal release;
and the next pull's boundaries for dispatch and merge detection.

The history test covers the canonical redo beside another card's first attempt; normal
release; the same run; an idle intervening claim; exit cleanup; `redone` alone and after
normal release; an idle predecessor; an intervening merge; the most recent predecessor
ending normally or belonging to this run; releases under another card, in another run
or before a pull; repeated redos; separate cards; and unread events and fields.
The repeated-redo fixture uses nonlexical run names and equal timestamps so line order
supplies its ordering. A refused sink release remains the contract's stated residual,
which this card excludes.
