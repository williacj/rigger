# 2026-09-27 — Rigger starts no further work while it cannot record an event

#277 proposes `R-RECORD-9`: when Rigger cannot record an event, it says what went unrecorded and
starts no further work until it can. The owner ruled that on 2026-09-25, answering #220's
`ambiguous` escalation, and the PM relayed it on #220. The row's wording is the proposal; the
ruling is recorded, not proposed. The architect placed the halt in L3 on #277, `ARCHITECTURE.md`
carries the placement from #281, and #280 built it. This card adds the row and the claims.

**The tests came first, from #280.** `npm run matrix:check` refuses a declaration naming an id the
register does not hold, so #280 landed its halt tests undeclared and this card declares eight of
them. The row has two clauses, and each is claimed at two levels. At L3, over the fake board and
the shared sink: the claim-only call claims no card, the loop calls no injected dispatch, the next
call claims once the sink accepts again, and L2's refused-transition report reaches L3's caller
unchanged. Over the real `once` and `run` bins: every card stays in Ready while the stream refuses
from the start, and the verb names the card, both columns and the sink's error when the board took
the move and the stream then refused its event.

**Two mutations, one per clause.** Removing the halt in `src/scheduling/loop.mjs` reds the
no-claim, no-dispatch and lifting tests at L3, and the ready-column tests over both bins: the
cards move to Coding unrecorded. Replacing L2's report in `src/workflow/transitions.mjs` with the
sink's bare error reds the L2-report test at L3 and the naming tests over both bins, on the
missing `from ready to coding`. Every run reached a verdict naming tests, and every file came back
byte-exact.

**The halt mutant hangs one loop test, so that target was narrowed.** With the halt gone, "given a
redo card and a sink that refuses from the first pull event on, a run ends after one board read"
dispatches the redo, and the injected dispatch is held open with nothing to release it, so the
file never reports. The first attempt sat eleven minutes before it was killed; the runner now
bounds a run at 180 seconds and prints what had finished, which is how the hung test was named.
The loop target for that mutation is `--test-name-pattern=given a sink that refuse`, six tests
under the same pattern unmutated, six red under the mutant. The `once` and `run` files run whole,
because the claim-only call does not loop.

**A runner defect, caught by `git status`.** The first runner called `process.exit` inside its
`try` when a guard failed, which skips the `finally`, so the mutant stayed on disk after the
timeout and a second mutation started on top of it. The tree was restored by hand and that run
discarded; the runner now records the guard's code and exits after the `finally` has restored the
file. The tdd skill's guard 6 is what made the defect visible, and it is why the report mutation's
figures come from a rerun on a clean tree.
