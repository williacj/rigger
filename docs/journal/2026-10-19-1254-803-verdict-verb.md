# Card #803: the verdict verb

The verb confirms only on a terminal at its standard input, so its tests need a real one. Node has no pseudo-terminal of its own, and `/usr/bin/script` refuses a socket as its standard input, which is what Node's `spawn` gives a child as a pipe (`script: tcgetattr/ioctl: Operation not supported on socket`, macOS 27.0, 2026-10-19). A named pipe is refused the same way. Bash's process substitution, `script ... < <(exec cat)`, gives `script` a real pipe, and the test ends it once `script`'s output ends, so nothing outlives the run.

A first probe written as `cat | exec script` hung for the whole tool bound: the outer shell held the test's standard output open while it waited on `cat`, so the end of output never came and `cat` was never ended. The process substitution leaves `script` the only holder of that output.

`stty -onlcr` inside the terminal leaves the verb's line endings as written, which is what lets a test compare the printed comment byte for byte with the one the fake forge received.

The fake forge answers a comment's creation without the `html_url` GitHub answers, and `test/fake-gh.mjs` lies outside the card's Lands in. A relay `gh` in `test/verdict-world.mjs` adds that field, and fails a named read where a test asks, without changing the fake.

## Round 1: a runner's ~/.bashrc put the real `gh` ahead of the relay

Round 1's CI run 39302554905 failed 55 verdict tests on both Node 20 and Node 24. Every test that read the forge from the pseudo-terminal got the real CLI's "To get started with GitHub CLI, please run:  gh auth login". The gate check script, run with the same environment and no terminal, read the fake in the same test, so the PATH handed over was sound and something inside the terminal chain changed it.

Apple's /bin/bash reads `~/.bashrc` under `bash -c` when its standard input is a socket. That is the remote-shell heuristic, and Node hands a child a socket for a pipe. On this host, `env -i PATH=/xx:/usr/bin:/bin HOME=$HOME /bin/bash -c 'echo $PATH'` printed the owner's `~/.cargo/bin:~/.local/bin` ahead of `/xx`. The same command with standard input from `/dev/null`, a shell pipe, `--norc` or another `HOME` printed `/xx:/usr/bin:/bin` (measured 2026-10-19, macOS 27.0). The test handed the verb the real `HOME`. That the runner's own `~/.bashrc` put its `gh` first is an inference from this mechanism and CI's message; the runner's file was not read.

Locally the owner's `~/.bashrc` adds no directory holding a `gh`, so every local run passed. A `HOME` holding a `.bashrc` that puts a stand-in `gh` first reproduced CI's message here: 30 of 40 tests failed in the forge and terminal files.

The fix closes the route twice. Bash runs with `--norc --noprofile`, and the verb is handed an empty `HOME` of its own. `world` also refuses to run if any directory on the verb's PATH, after the relay's, holds a `gh`. Two tests ask the verb's environment, at a terminal and without one, which `gh` a shell and a Node process select.

## Rounds 3 to 5: an import guard that matches spellings never finishes

Item 19's import check was refused four times, for a self import, a query, an uppercase `FILE:` scheme, an uppercase `;BASE64` data URL, and doctor's exempt config load pointed at the verb. Each fix matched one more spelling, and Node reads more spellings than a test can list. The check now names every import it cannot prove loads another module. It admits a `file:` URL whose real path is not the verb's, a builtin, and doctor's config load, because there the source fixes that the loaded file is named `rigger.config.mjs`. Everything else counts as importing the verb, whatever Node would make of it.

Round 6 found one more: `./Verdict.mjs` loads the verb on macOS, whose default filesystem folds case, and the check compared path strings. Files are now told apart only as the filesystem tells them apart, by device and inode. A name is never compared to the verb's name. Instead the filesystem is asked whether that name, in the verb's directory, is the verb's file. One test now replays every route the judges found, rounds 1 to 6.

Round 7 found a loader: `createRequire` from `node:module` loads the verb without any `import` naming it. The check now counts every builtin except the ones `src/` uses today that run no code, and every module the layer-boundary rules refuse for a loader, code built at run time, a worker, an addon, a binding or an import they cannot resolve. Those rules already listed the loaders, so the check takes their answer rather than keeping a second list.
