# 2026-09-27 — A committed GIF needed the header rule widened, and CI to forget the copy it holds

The first round stopped short of committing the GIF because `AGENTS.md` exempted one format from
the `ABOUTME:` rule, JSON, and `scripts/aboutme-header-check.mjs` reads that sentence to decide
what is exempt. The owner ruled on 2026-09-27 to exempt GIF inside this card: the sentence now
names "JSON and GIF", and the check's parse reads a list of formats where it read one word. The
check still reads the exemption out of the rule rather than holding its own copy, so a format the
rule does not name, a PNG for one, is still a finding.

**Committing a file at the path CI checks changes what the check proves.** The demo job's
`test -s docs/demo.gif` was written for a checkout holding no GIF. With the recording committed
there, it passes on the committed copy when the tape writes nothing, and the card's item on a
missing GIF quietly stops holding. The job now removes the committed GIF before `vhs` runs. The
suite's old test asked each check about a file in isolation and could not see this; the new one
runs the job's GIF steps in order, in a checkout that holds a GIF, with the tape stood in for by a
command writing nothing, an empty file, or a real one.

**A status is a position on the screen, not a pattern.** CI read the exit with
`grep -E '^exit [1-9]'`, which any line of the verb's own output could satisfy. Codex's
counterexample was output carrying `exit 1` above an echo reporting `exit 0`, and the grep passed
it. The status is now the line after the last `> echo exit $?` the tape typed, read with `awk`.
The verb has exited before that line is typed, so nothing it prints can come after it. The tape
and the GIF are unchanged.
