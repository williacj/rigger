# #370 — A dispatch the exit cleanup ends still gets exactly one `dispatch.end`

## What was built

- L0's exit cleanup now hands each caller's step the command's exit code as well as its group.
  Where Node has already reaped the command, the step gets the command's own status. Otherwise it
  gets the code of the cleanup's `SIGKILL`, which is 137.
- L1's step removes the entry and then appends `dispatch.end` with that exit code and the
  duration. The step runs after the cleanup has recorded every kill, so the end comes after them.
- Where the sink refuses that end, the step throws L1's refusal. L0's `attempt` writes the refusal
  to standard error. L1's refusal now puts each unrecorded event on a line of its own naming the
  dispatch and card, so one line carries all three.
- A process kept running past its ending (a signal listener of its own) has the dispatch's call
  settle as before, but L1 records nothing more of it. Without this, the call's own path appended
  a second end once the killed command was reaped.

## What we learned

- **A refusing sink cannot be one from the start.** A sink that refuses every append from the
  first one refuses `dispatch.start`, so no dispatch ever runs. The test instead makes the stream
  read-only once the dispatch is running, and checks that no kill reached it.
- **L1's `dispatch` takes no `ps`**, so the exit-cleanup fixture's stand-ins for `ps` never reach
  a dispatch's census. The test of the exit code of a command that has already exited goes
  straight through the adapter's `onExit`.
- **Mutations shown to discriminate.** The mutations ran on `test/exit-cleanup.test.mjs`'s 63
  tests at `ae58cd6`. For each, the anchor was found once, the change was shown by
  `git diff --shortstat`, and the file was restored byte-exact with `git diff` against HEAD clean.
  - No guard after the cleanup ended the dispatch: 1 red, the kept-running test, with 2 ends.
  - Entry removed after the end is appended: 18 red, on "the record held dispatch d-1's entry".
  - The end carries exit 0: 18 red, on "ended with the exit code 0".
  - L1's refusal lines not naming the dispatch: 1 red, the refusing-sink test.
  - The child's own status ignored: 1 red, the exit-code test.
  - No end appended at exit: 19 red, on "has 0 dispatch-end events", and the refusing-sink test.
  - Each step taken before the kills are recorded: 19 red, on "end comes before survivor.killed".

## Round 2: a command that exited while its call is in flight

#370's author revised items 5 to 7 and added items 16 to 18, after both judges returned the card.

- **L0 now holds a call, not a group.** L0 used to drop a call from the exit cleanup once the call
  had emptied the group. A dispatch whose command had exited, while its survivors or its held
  output kept the call in flight, then got no end, and its entry stayed. L0 now holds each call
  until a turn after it settles. The cleanup kills only a group the call has not emptied, and it
  records the call's own unrecorded kills.
- **Why a turn after, and not as the call settles.** The caller's code after its await runs in the
  turn the call settles, so an ending in that turn must still reach the caller's step. L1's step
  therefore does nothing for a dispatch whose end it has already recorded.
- **The command's own exit code, reaped or not.** Node reaps no child while the cleanup runs, so a
  command that has exited, and that Node has not yet reaped, is a zombie. The cleanup's last read
  of the group also reads `xstat`, the zombie's wait status in hexadecimal.
  - Measured with `/bin/ps` on macOS 27.0 on 2026-09-28: exit 0, 3 and 200 read `0`, `300` and
    `c800`, and `SIGKILL` and `SIGTERM` read `9` and `f`.
  - So the low seven bits are the signal, and the byte above them is the exit code.
- **A removal the record refuses rides on the end.** The end then carries `kept`, naming the entry
  and why.
- **Deterministic windows, each arranged in the caller.**
  - An unreaped command: the caller spins synchronously until `ps` shows it as a zombie.
  - A command reaped in the turn the caller ends: the caller wraps `ChildProcess.prototype.emit`.
  - Held output: the caller raises `SIGTERM` as the adapter arms its 1,000 ms output bound, which
    it does once it has killed the group's child.
  - An ending in the turn a call settles: the caller exits in the call's `finally`.
- **A fixture race.** The first survivor test used `leaving`, which exits at once. The caller could
  then end before the second command had written its group. `lingering` waits for the release.
- **Mutations shown to discriminate**, run at `1159784` on `test/exit-cleanup.test.mjs`'s 70
  tests. For each, the anchor was found once, the file was restored byte-exact, and `git diff`
  against HEAD was clean.
  - The call let go as it settles: 1 red, the settle-turn test.
  - The call let go once the group is emptied: 2 red, the held-output and settle-turn tests.
  - The zombie's status not read: 1 red, the unreaped test.
  - Node's own status not used: 5 red.
  - L1 ending a dispatch it has already ended: 1 red, on two ends.
  - No `kept` where the removal is refused: 1 red.
  - The call's own unrecorded kills not recorded at exit: 1 red, the held-output test.
  - The wait status read as decimal: 1 red, the unreaped test.
