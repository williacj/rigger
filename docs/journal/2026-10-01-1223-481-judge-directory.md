# #481 — a judge's directory, and the checks git would have covered

**A head commit is checked as a name before it is fetched.** The head SHA reaches L1 from the
forge, and `git fetch origin <x>` takes `x` as a refspec, so `main:refs/heads/taken` would write a
branch and `--upload-pack=…` would be read as an option. Measured with git 2.54.0 on 2026-10-01,
`git rev-parse --verify --quiet --end-of-options <x>` prints back any full-length hexadecimal name
whether or not the object is there, and nothing else unchanged: a branch prints its commit, an
upper-case name prints in lower case, and an abbreviation or a refspec exits 1. So L0 fetches only
a name git printed back unchanged, and compares rather than copying git's rule (`D16` rule 1).

**Fetching a commit by its name needs no branch on `origin`.** A commit reachable from any of
`origin`'s branches, tip or not, fetched under protocol version 2; one `origin` lacks exited 128
with `not our ref`; one the repository already held exited 0 without asking. So "does not hold
after fetching" is read off `git cat-file -e` after the fetch, whatever the fetch answered.

**Two of the replace rule's checks were covered by git or by a later check.** Mutation showed
that dropping the not-a-directory check still refused a file at the path, because `readdir` then
fails and the path reads as unreadable; only the recorded reason changes. Dropping the
is-a-worktree check still refused a plain directory left at `head` where git listed a deleted
worktree, because git's own `worktree remove` refused it and `head` sorts first. Put at `main`, the
plain directory is reached only after `head` has been removed, so the test now replaces `main`, and
there the check is what keeps the attempt from changing anything.

**Placement followed an existing test, not a preference.** The judge make first lived in its own
module importing helpers from `workspace.mjs`. The rule 10 test replaces `workspace.mjs` with a
stub that exports three names, so the new module's imports failed to resolve there. It now sits
beside `makeWorkspace` in `workspace.mjs`, sharing its failure record, and no existing test line
changed.

## Revision 1

**A refusal that has already fetched has changed something.** The first version fetched the main
line and the head before it checked the path, so a refused attempt still moved
`refs/remotes/origin/main` and wrote objects. My refusal tests compared `refs/heads` alone, with
`origin` standing still, so nothing could show it. Both judges found it. The check now runs first
and makes no git call that writes. The tests advance `origin` before each refusal and compare every
ref and every object.

**Compare real paths with one function on both sides.** L1 built the worktree paths with
`realpath(3)`, which answers the disk's spelling. L0's registration lookup compared them through
Node's JavaScript `realpathSync`, which keeps the spelling it was handed. With a root spelled in
another case than the disk, the lookup missed, and the refusal said "on the branch undefined". The
judge check now reads git's listing and resolves both sides with `realpath(3)`. The same defect in
`makeWorkspace` is #509's.

**A make of Rigger's own that was killed leaves a lock only Rigger may take away.** A
`git worktree add` killed partway leaves its worktree locked `initializing`, and
`git worktree remove --force` refuses it. The check now unlocks that reason alone, whether the
worktree's directory is there or gone, and refuses any other lock as a person's.
