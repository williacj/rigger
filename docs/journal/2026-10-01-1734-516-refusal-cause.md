# #516 — a refusal says why its read failed, so a timeout cannot pass for it

**The gap was real at the base.** At 4f017db, with the stand-in body of each of the eight listed
tests replaced by `exec /usr/bin/tail -f "$here/hold"`, a read that never answers, all eight passed.
Each asserted only that the call refused and named its entry, which a timed-out read does too.

**Two refusals could not name the cause, so the fix had a source half.** A test can only assert a
cause the refusal states:

- `run` rejected a `ps` that exited non-zero with Node's own `Command failed: <ps> <args>`. That
  names no exit status, so neither "exits 2" nor "prints part of the table and exits 1" could
  assert the status its stand-in exits with. It now says `<ps> <args> ended with <status>`, the same words the
  synchronous `runNow` already used, through one `exited` helper.
- `startsIn` retries a read that answered short, listing no process or leaving out a live leader,
  until its deadline. Where the deadline fell while a retry was running, that retry was killed
  and the refusal said only `timed out after 300 ms`. It also said `its leader or every member`
  where it knew which. It now says which the last answered read left out. Where a retry was
  given up at the deadline, it says that too.

The second half is what would have made the head's own assertions flaky. Retries pause up to
50 ms between reads, so a deadline landing mid-read is not rare. The two `next never answers`
tests force it: the first read answers short, and every later read hangs. With the wrap removed
from the source, both red on `the process-table read timed out after 300 ms`.

**Warming is what lets the head pass under load.** PR #502's forcing holds the first exec of every
`ps` stand-in until it is killed, as a loaded host did. Each listed stand-in is now `warmed`, as
`startsAs` already was, so that hold is paid before the read starts. No bound moved, and nothing
sleeps.

**The never-answering body really never answers only because `hold` exists.** `tail -f` on a
missing file exits 1 at once, with the error on standard error. Every listed test's directory gets
`hold` from `startGroup` or `holding`, so the mutation held. The head run's failures confirm it:
each says `timed out after 300 ms`, or `ETIMEDOUT` for the synchronous read.
