# 2026-09-28 — A start that cannot read a recorded group kills nothing in it

**An empty start-time read admitted the group.** `startsIn` read the recorded group through
`run()`, which hands back nothing for `ps` exiting 1 with nothing printed, the one answer `ps`
gives for no process matching. The leaderless rule then admits the group, because every one of no
starts is no earlier than the recorded leader, and `contain` killed it. A `ps` stand-in that exits
1 silently reproduced it: the test's live group died, and the call settled without failing (the
engineer's N24 on #369).

**Signal 0 decides whether the group is empty.** The start-time read now keeps an empty answer
only once signal 0 no longer reaches the group, as the census already does. While the group still
answers it reads again, since a member that is exiting answers signal 0 and may not be listed, and
at its deadline it fails, so L1 keeps the entry and names it. A group that holds only zombies is
unaffected, because its read lists them.

**The other failed reads were already refused.** A read that exits non-zero with or without part of
the table, one that times out, and one whose start time does not parse each rejected at the base,
and now each has a test. Only the silent exit 1 was taken as an answer.

**`rigger once` does not yet run the kill.** At the base, `claimVerb` never calls L1's kill of
recorded groups: #349 (M2-09) wires it into `once.mjs` and `loop.mjs`. So the item asking that
`rigger once` exit non-zero on a silent failed read has no path to meet in this card's landing
place, and it went back to the coordinator as `ambiguous` rather than absorb #349's wiring.
