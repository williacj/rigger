recorded a process the kill does not end without its name, and what names it within its bounds.

# #579: the census's wait could not read what its kill left

**Where the bound ran out.** The census lists the directory, stops each process, reads states,
lists the stopped ones again, and then reads each name, the command lines and the states again
before its kill. Under load these reads can take the whole 1,000 ms bound. Where it runs out
after the second listing, the process is already in `ours`. The catch path kills it unnamed, and
`settled` recorded it by pid alone. #573's run at `fafebac` shows that record:
`name: undefined, cmd: undefined`.

**Why the wait could not name it either.** #578 gave the wait its own bound, starting at the kill.
But the read the census's bound cut short was a `ps` read, and `runOnce` marks a `ps` it gave up
on as `unanswered` for the rest of the exit cleanup. So each read in the wait failed at once, and
the record's reason became "the process table could not be read", where the bound had in fact cut
off a read of a table that was answering. A stand-in that holds the census's name read before the
kill reproduces both halves with no load: at `e9a5eca` the record is unnamed and gives that reason.

**What names it.** The fix has two parts, and removing either one reds the forced test. First,
the wait reads the name and command line of each process killed unnamed before it waits on it. A
process the kill does not end is still stopped then, so the name is the one the census listed.
Second, a census whose own bound cut a `ps` read before its kill lets the wait read `ps` again
under the wait's own bound. No bound is larger.

**What it does not reach.** Two other modes look like this one and are not it, because no process
is killed unnamed in either. The bound can run out before the second listing, and then the process
is resumed and recorded nowhere: that is `actual: []`, and :604's guard failing on "never sent its
kill". The other is the group census's own read timing out on a test with no directory at all,
which was the reviewer's failure cited as :778.
