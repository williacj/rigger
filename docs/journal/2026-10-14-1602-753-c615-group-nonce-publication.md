ABOUTME: Records why the C615 Mac group test read an empty nonce on CI, the trace that discriminated it, and the repair #753 proved.

# The C615 group fixture's nonce was readable before it was written

The C615 Mac group test's generated fixture wrote its nonce with `writeFileSync(join(here, 'up'), nonce)`. That call opens `up`, creating it empty, and only then writes the 36 bytes. The parent waited only for `up` and `group-birth.json` to exist, checked the caller was live, and read `up` once. So a parent whose read fell between the fixture's open and its write read `''` and failed the nonce guard. CI jobs [115693478303](https://github.com/williacj/rigger/actions/runs/38515570251/job/115693478303) and [115956813984](https://github.com/williacj/rigger/actions/runs/38594263367/job/115956813984) each failed that guard reading `''`.

The trace that discriminated it is an observer every Node process of a run loads first through `NODE_OPTIONS`. Fixture, caller and parent each append their steps on the fixture's files to one file opened for append. An entry appended after one step returned and ahead of an entry appended before another step began puts the first step before the second, across processes. Wall-clock time takes no part in that order.

Twenty consecutive unforced instrumented whole-file runs at base `f3a23ae` never read an empty `up`. The observer marks an existence check and a write after they return, and marks a read as it starts, so the trace orders only some pairs. In one run, N03, the parent's mark that `up` existed precedes the fixture's mark from before its write began, so the parent saw `up` before any byte was written. In fifteen runs the fixture's mark after its write returned precedes the parent's mark from before its read, so the read came after the write. In the other five (N03, N04, N05, N13, N14) the parent's read and the fixture's write overlap in the trace, so their actual order is unknown. In nineteen runs it is unknown whether the parent saw `up` before or after the bytes were written. The two historical CI jobs left no trace, so it stays inference that their fixture stalled between the open and the write. The logs cannot exclude a fixture that exited between the two, and they cannot show why it paused there. Each natural attempt's classification is in the pull request that closes #753.

The forcing holds the fixture's nonce write after its open until the parent has either found no `up` or read it. Under it, the base test failed five times out of five at its `:3468` nonce guard, reading `''`. The same forcing at the head passed five times out of five, including the full census. The head fixture writes `up.partial` and renames it to `up`, so `up` exists only once the whole nonce is written. Six controlled tests run the C615 group test in a nested runner under this observer, one for each publication cell: an empty, part-written or fully written write held open, and a returned write of no bytes, of other bytes, or of the nonce.

The observer adds one append between the fixture's open and its write, which widens the window an unforced run can hit. That overhead is the same at base and head.
