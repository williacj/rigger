# #649 — the decision ending D21 and D22

`D21` and `D22` each said M5 reverses them, and `D21`'s deferred table named four things M5 had to
settle. The owner's rulings on #642 settled them, and `D25` records them as seven rules. The owner
ratifies by marker, the gate's statuses come from a dedicated App, and anyone may merge once both
checks are green. A change to a binding document or a Self-hosting path also needs a sound owner
marker at its head.

`D25` took the next free id. `D24` landed first under P39, and the judge-provider rule that this
card once carried as rule 8 is `D24`'s now, so `D25` only cites it.

Three things were not obvious from the card.

- `AGENTS.md` now names paths that do not exist yet: the gate workflow, its template and script
  (#702), and the `self-hosting` check (#662). The path check fails on a missing path wherever it
  sits. So `doc-references.json` exempts each one with its reason, which is the mechanism that file
  holds for assets yet to land. Each exemption is spent once its path arrives, and
  `test/path-check.test.mjs` then fails until someone removes it. Whichever lands second, this card
  or the one adding the path, removes the exemption.
- The path check reads any backticked `a/b` span as a path, so the status context `rigger/gate`
  backticked in `AGENTS.md` or the decision register fails it. Both documents quote the context
  names instead.
- The retired entries keep their bodies word for word, and only their status lines change, to
  `Superseded by D25.`, as `D19`'s did when it moved. The preamble lets a superseded status carry
  only that opening, so `D21`'s "Amended in #319" does not survive the move. Round 1's judges
  returned that question to the card's author, who ruled it and added a sentence to the preamble
  saying so, and that a row's status carries no period.
