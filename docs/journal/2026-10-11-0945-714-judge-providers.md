ABOUTME: Records what card 714 taught while making a judge's provider configured, recorded in its
marker and enforced by the gate: where a missing provider fails closed, and what a fixture rewrite hid.

# A missing provider fails closed at the gate, not in the review loop

The panel function answers every agent judge's provider from the config's roles and the card's
labels. Handed no `roles`, which only tests do, it answers a plain-named judge with no provider. The
gate refuses that panel as malformed, naming the judge, so a merge is never admitted without a
provider check (the delta's section 3). The review loop's `stateOf` compares a marker's provider only
where one is required, so an L2 handed no roles still dispatches, returns and continues as before.
One existing test merged an Owner card through an L2 handed no roles. Once the gate checked
providers, it answered `ignore` naming the malformed panel, and the granted retarget hands it the
config's roles.

# A fixture rewritten by text inherits every field it does not rewrite

One Owner-card test made the owner's marker by replacing `role: reviewer` with `role: owner` in a
reviewer marker. Once the reviewer fixture carried `provider: claude`, the rewritten owner marker
named a provider, and `ownerAnswer` left it for the owner. A marker built from another by text
replacement needs each new field checked against the role it ends up with.

# A loop of tests cannot carry a `// proves` line

The three `ownerAnswer` cells were first one `for` loop of `test` calls under a `// proves` line.
`npm run matrix` refuses a declaration inside open brackets, so each cell became its own top-level
test, and the `doctor` cells were unrolled the same way, so each cell has a title a judge can cite.

# The gate stays small

The provider, owner and conflict checks add about ten lines to the rule. `gate.mjs` counts 37
production lines by `npm run budget:package` at this card's head, a measurement, because the panel
function that decides each provider lives in `next-action.mjs`, outside the gate's budget row.

# A second role reader let an undefined role through

The first head's validator read each entry's role in its own helper, which answered `entry.role` and
skipped a role it could not read. An object entry whose own `role` was `undefined` therefore passed
every check, and the reviewer found it with a one-test probe. The checks now read the role only
through `judgeRole`, and a test holds every `.role` read in `validate.mjs` inside it. A role that is
not a declared role's name, `undefined` included, is refused as no role the config declares.

# A refusal test asserts what it left alone

The first head's refusal tests asserted the refusal and its reason only. Each now also asserts that
its input is unchanged: the config's full snapshot for the validator, the facts for the gate, and the
card for L2, with the events L2 recorded. A mutation that wrote one key to a refused judge entry
failed five validator cells on that assertion alone.
