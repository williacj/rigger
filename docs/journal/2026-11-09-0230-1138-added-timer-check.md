# Added-timer check

Card [#1138](https://github.com/williacj/rigger/issues/1138) implements
[D30 rule 6](../spec/decisions.md)'s added-timer steps. It answers the
[owner's direction](https://github.com/williacj/rigger/issues/740#issuecomment-6497180994)
to stop bad tests before they become debt. Its placement follows the
[architect's ruling](https://github.com/williacj/rigger/issues/740#issuecomment-6497153704),
"Card B", with the added-timer mode as that ruling's fourth and fifth amendments place it.

The check is `.github/scripts/check-host-declarations.mjs`. It reads the record #1137's guard
writes when `RIGGER_SUITE_TIMER_RECORD` is set, and runs in `fast` and `nightly` as the step
directly after `npm test`, which sets that variable. Its base is the merge base of the head with
the commit `.github/scripts/check-test-list-growth.mjs` resolves for the event. That resolution
is now exported from the list-growth check as `eventBase`. The list-growth check's notice for a
base that predates the lists plays no part here.

For a pull request, both checks now take the base as the checked-out merge head's first parent.
That is the tested base `ci.yml`'s `collect` already reads, rather than the payload's
`base.sha` ([M7-K92](https://github.com/williacj/rigger/issues/1009#issuecomment-6764289003)).
The payload's base lags whenever `main` moves after the branch was last updated. CI run
42777007623 showed the cost: the check counted tests `main` had gained since then as added by
this pull request and refused them, and merging `main` (M7-K91) only lost to the next landing
(run 42792861753). A test `main` gains was checked on its own pull request and again on its
push to `main` against `before`, so treating it as the base's lets nothing escape. Row T12 now
reads that way, and row T13 pins the push.

The scanner in `scripts/build-test-matrix.mjs` gains `testsIn`. It lists each top-level test,
declared or not, by file and title, and each top-level runner call whose title it cannot read.

Round 1's judges showed that a scanner which recognises statement blocks by their openers misses
some of them: a `for await` body, a labelled block, and a block that automatic semicolon insertion
separates from the line before. It also counted a call in an uncalled concise arrow, and a call to
a name that a block declared for itself. Those calls went unchecked, or older tests were refused
as if they had been added. The scanner now reads the question the other way round. A runner call
is reached while the module loads unless it is inside a function body, however that function is
written. Each block keeps the names it declares, so a block-local binding hides the import.
Quoted computed members, such as `test['only']`, are members like `test.only`. A matrix in
`test/runner-call-forms.mjs` places every call form in every statement, block, expression,
function-body and binding-scope position. A host test runs every case under `node --test` and
holds the scanner to the tests the runner actually registers. The scan now fails closed. Every reference to a registering import that the module reaches is
either a call the scan identifies by its title, or it is listed as unidentified with its line:
a comma-expression callee, a parenthesised member, a tagged template, a call through `.call`, or
a read of the binding as a value. An added one is refused, so no supported call form lets an
added arm pass unchecked. The places the module never reaches while it loads now also cover
parameter defaults and class instance fields. Static fields and static blocks are still
reached. The scanner still reads tokens
rather than a syntax tree, because `scripts/` ships with the package and nothing there may import
`acorn`, the dev-only parser ([#213's journal](2026-09-25-0837-213-bindings-not-reachability.md)). A shape that the matrix does not hold is a
review finding. A test is added when the
head holds its title in the file more times than the base does (D30 rule 2), so a rename, a
move from a bounded file and a second test sharing a title all count as added.

Row T6 counts only the calls a change adds. An unidentified call is keyed by its source from the
callee to the end of its first argument, so a body edit keeps the key. A test added by appending
a case to an array that an unchanged call loops over therefore adds no call, and is outside the
step, as D30 rule 6's wording ("a top-level call that the change adds") leaves it.

`scripts/preflight.mjs` gains the same step, using the merge base it already computes. Where the
change adds a conversion-list test, it runs `npm test` on those files with a new record directory,
then runs the mode over that record. A failed run is named, and the mode does not run after it.

`test/check-host-declarations-host.test.mjs` is a new host-tier file: it runs real fixture suites
and real Git. Its tests are therefore added host tests under D29 rule 11, with no declaration form
until [#1238](https://github.com/williacj/rigger/issues/1238). They and the new tests in
`test/check-host-declarations.test.mjs` carry no `// proves`: they are harness diagnostics for
D30 rule 6, which no row of `docs/spec/requirements.md` describes.

Card revision `93937f8ca762`, under the PM's ruling and the architect's at
[1138#6769264817](https://github.com/williacj/rigger/issues/1138#issuecomment-6769264817), replaces
the scanner's reasoning with listing. "An unidentified runner reference: any reference in a file to
a binding the file imports from `node:test`, or obtains from `node:test` by any route, that
registers a test or a suite, other than the callee of a top-level call the scanner identifies or a
reference inside that call's own arguments." The scanner lists each by line wherever it occurs,
function bodies included. It reads no scopes, so a local binding of the same name is listed too:
a false refusal, which fails closed. Identifier escapes and string specifiers are read as they
decode. Row T6 refuses an added reference whose line the base does not hold byte for byte. Row T14
refuses an added line that reaches `node:test` other than by a static `import`: a dynamic
`import()`, `require` or `createRequire`, `process.getBuiltinModule`, `eval`, or an `export … from`
of `node:test`, unless the module it loads is a string literal naming another module. Over every
existing `test/*.test.mjs` the identified tests are unchanged. Unidentified lines grew in eight files,
from bindings a dynamic import of an unreadable target makes and from function parameters named
like the runner. Only an added line is refused, so those older lines refuse nothing.
