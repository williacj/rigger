ABOUTME: Records the added-timer check's placement, its runtime reading of added tests and the host-test classification for card 1138.

# Added-timer check

Card [#1138](https://github.com/williacj/rigger/issues/1138) implements
[D30 rule 6](../spec/decisions.md)'s added-timer steps. It answers the
[owner's direction](https://github.com/williacj/rigger/issues/740#issuecomment-6497180994)
to stop bad tests before they become debt. Its placement follows the
[architect's ruling](https://github.com/williacj/rigger/issues/740#issuecomment-6497153704),
"Card B", with the added-timer mode as that ruling's fourth and fifth amendments place it.

The check is `.github/scripts/check-host-declarations.mjs`. It reads the record #1137's guard
writes when `RIGGER_SUITE_TIMER_RECORD` is set, and runs in `fast` and `nightly` as the step
directly after `npm test`, which sets that variable. Its base is the merge base of the head with
the commit `.github/scripts/check-test-list-growth.mjs` resolves for the event. That resolution
is now exported from the list-growth check as `eventBase`. The list-growth check's notice for a
base that predates the lists plays no part here.

For a pull request, both checks now take the base as the checked-out merge head's first parent.
That is the tested base `ci.yml`'s `collect` already reads, rather than the payload's
`base.sha` ([M7-K92](https://github.com/williacj/rigger/issues/1009#issuecomment-6764289003)).
The payload's base lags whenever `main` moves after the branch was last updated. CI run
42777007623 showed the cost: the check counted tests `main` had gained since then as added by
this pull request and refused them, and merging `main` (M7-K91) only lost to the next landing
(run 42792861753). A test `main` gains was checked on its own pull request and again on its
push to `main` against `before`, so treating it as the base's lets nothing escape. Row T12
reads that way, and row T13 pins the push.

Three attacks broke a static scanner that read the added tests from source: calls in function
bodies, escapes, and routes to `node:test` other than a static import each let an added arm pass.
Under [M7-U68](https://github.com/williacj/rigger/issues/1009#issuecomment-6774793951) the owner
chose a runtime oracle instead, since what counts as a test is `node --test`'s answer (`D16`
rule 1). The scanner extension moved to #1238, and this card leaves `scripts/build-test-matrix.mjs`
as it found it.

The mode runs each conversion-list file the change modifies twice under one lister reporter, the
check's own default export: at the head, and in a detached worktree at the base. The lister names
every test reported at nesting 0 and never filters on `data.file`, because a test registered
through a helper reports the helper's file and one registered through the runner's mock reports
the mock's. Both runs are full runs, since a skip, name or only pattern makes the runner report
nothing for the tests it filters out ([1138#6774885550](https://github.com/williacj/rigger/issues/1138#issuecomment-6774885550), B2).
An arm recorded from file F under title X is refused where head(X) > base(X), with head(X) the
larger of the head run's count and 1: the record holds no line per registered test, so the arm
itself is the proof that the job's run registered X (B1). A title that differs from run to run
therefore counts as added under each value, and is refused only where something armed under it.

The base worktree is made under the temporary directory and removed with
`git worktree remove --force` then `git worktree prune` however the run ends (B3). It links the
head checkout's `node_modules`, so a base run that cannot load a package the head no longer
installs gives no titles and is refused naming the file, as is a file that throws while loading
or registers no test: node:test reports each as one test named by the path it was given. A test
registered after the root test completes, or in a child process, is seen by neither run, and is
left to the judges.

T18's bound is four times the slowest base run measured in one CI run before the step gated any
job: run 42895935883 ran every conversion-list file at merge base `cd181d6f` under the lister, and
the slowest, `test/loop.test.mjs`, took 149012 ms, so the bound is 596048 ms. The multiple is a
judgment. A run past it, at the base or at the head, is refused naming the file and the bound.

`scripts/preflight.mjs` gains the same step, using the merge base it already computes. Where the
change modifies a conversion-list file, it runs `npm test` on those files with a new record
directory, then runs the mode over that record. A failed run is named, and the mode does not run
after it.

`test/check-host-declarations-host.test.mjs` is a new host-tier file: it runs real fixture suites,
real `node --test` runs and real Git. Its tests are therefore added host tests under D29 rule 11,
with no declaration form until [#1238](https://github.com/williacj/rigger/issues/1238). They and
the new tests in `test/check-host-declarations.test.mjs` carry no `// proves`: they are harness
diagnostics for D30 rule 6, which no row of `docs/spec/requirements.md` describes. The modules
the scanner attacks used are kept in `test/added-timer-oracle-cases.mjs` as the lister's oracle
cases.
