# #582 — tests that time a real command under a short bound

**Why.** Several of this milestone's flakes came from a test whose bound timed a real `ps` or `lsof`,
so the host's load decided the test. Where the real command is not what the test proves, a
stand-in that answers on cue proves the same thing without that dependence.

**The rule the audit used, which the coordinator ruled on.** An `lsof` listing, and a start-time
read the test scripts end to end, are not the subject: the test already knows the answer, a pid,
a user and a directory, or the rows `startGroup` wrote. A `/bin/ps` read after a kill is the subject,
because the test checks Rigger against the kernel's own reaping, zombies and joins, and a modelled
table would check it against a model instead. So most in-scope tests stay on the real table.

**What moved.** The exit cleanup's census in `never-stop.test.mjs`'s EPERM and hang-after-kill
tests, and the first listing in `directory-census.test.mjs`'s stopped-then-failed census, now list
through `test/listing-stand-in.mjs`, which prints what `lsof` prints of the one process the test
names. `test/listing-stand-in.test.mjs` holds that answer to the real `lsof`'s, so the stand-in
cannot drift from the tool it replaces. In `kill-recorded.test.mjs`, the start-time reads of the
partial-table case and of `startsAs` print the group's rows from `group.pids` without running `ps`.

**What did not move, and why.** `never-stop.test.mjs:537` is #579's, whose acceptance keeps the
real table. `maker-dispatch.test.mjs:455` cannot take an `lsof` stand-in without a source change,
because `loop` takes none. `kill-recorded.test.mjs:542` and `:570` are #580's.

**What we learned.** Holding the start-time read does not fail the `startsAs` tests at the base: a
read that never answers is refused as a malformed start is, and `refusesStart` asserts only the
refusal, not its cause. So a slow real read could never have failed them; it could only make them
pass without reaching the calendar check they name. That gap is outside this card.

**How the forcing was done.** On a Linux host, as root, inside a private mount namespace, an
overlay put a `lsof`, or a `ps` whose `-g` reads hold, over the real one for that run alone. The
hold is `tail -f` on a file nobody writes, so no sleep, timer or load is involved.
