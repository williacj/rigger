# Post-kill census and first-read evidence

The census returned only the members of its last round. A member shown and named in an earlier round could still answer signal 0 at the confirming read, yet disappear from the record if later process-table responses omitted it. The change carries completed-round sightings to the confirming read. That read still decides whether each shown pid is alive, a zombie, or already reaped. A complete name and command line produces a member event; an incomplete identity produces a reasoned group event.

The exit cleanup recorded failed reads after its first kill, but dropped a failure of its first confirmation read before that kill. A joiner could then be killed and reaped before any later read listed it. The change retains the failed first read as a separate reason for the group event, including when the read bound prevents another look.

The new stand-ins log ordered process-table arguments and responses. A parent outside the group marks a joiner only after waitpid reaps it. Another parent reaps a shown member before the confirming read, guarding against a false kill event. A marked caller clock forces the two synchronous deadline cells without a test sleep; the unanswered cell ends at the production read deadline.
