# 2026-09-25 — L3 emits its event family

`loop()` now takes L5's sink and writes four events under layer `L3`. They are `run.start`,
`trigger` (whose `trigger` field is `pull` or `drain`), `pull` and `slot.release`. The loop's
JSDoc lists each one's fields. Every name and field here is new, so the pull request lists them
for the record.

**The pull event sits where #280 needs it.** `ARCHITECTURE.md`, "Failure model", orders a start
as claim, then append, then act. The claim is still taken in the trigger's synchronous step. The
pull event is the first statement of the card's work, before its first await, so it follows the
claim and comes before L2's claim move. A pull event the sink refuses therefore rejects that
card's work before the move, and the `finally` releases its claim. Nothing here reports the
refusal specially or halts later starts, which is #280's.

**Drain lives inside the pull trigger.** Only a pull learns that nothing can be pulled, so the
drain check runs right after the pull's claims. Drain fires when that pull claimed nothing and
nothing is in flight. One flag, cleared by any claim, keeps it to once per idle period. Without
the flag, three cards released together fire three pulls that each find the board empty, and
the record would hold three drains. The guarded mutation shows exactly that. Because drain sits
in the pull trigger, a bare `pull()` can fire it too, and it is the same trigger either way.

**Two field meanings are judgments, not facts the card fixed.** `queueDepth` counts the
pullable cards this pull left waiting, so this card is not among them. `inFlight` counts the
cards in flight with this one included. `ARCHITECTURE.md`'s telemetry example uses both names
without defining them.

**Two tests passed as soon as they were written.** The layer test and the overlap test read
behaviour the earlier items had already built. Every other test was red first. Four guarded
mutations of `src/scheduling/loop.mjs` show that the two late tests discriminate, and that the
drain guards do too. The pull request lists them.
