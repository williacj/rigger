# A status-issue write the forge made is not a failed notice

Card #1056 (M7-56), acceptance revision `123291a0ed68`, base `origin/main` `47b1a37c`. It is the
follow-up #1055 names for `src/workflow/status-issue.mjs`, on
[the #1055 attack's finding 2](https://github.com/williacj/rigger/issues/1055#issuecomment-6456170632).
Since #1055, a forge write side marks `failure.made` where the forge took a write and only an
event of it was refused. `statusNotice` recorded such a step as `notice.failed`, a false record
(`R-RECORD-6`), and the verb said "failed to", a false report. `R-RECORD-9` still asks that the
unrecorded events be said, and the verb still exits non-zero.

The card's [placement ruling](https://github.com/williacj/rigger/issues/1056#issuecomment-6470906596)
keeps L2's `failed` key, which L3 passes on unread, so `src/scheduling/loop.mjs` is unchanged. A
made step returns `{ failed: { step, cause, made, unrecorded } }` and emits nothing through the
sink. [The recheck's ruling](https://github.com/williacj/rigger/issues/1056#issuecomment-6471192168)
puts the wording in `noticeLine`, now exported from `src/cli/once.mjs` and called by `claiming`
for both `closer.notice` and `reached.notices`. Where `made` is present, the line names the step
as made and each unrecorded event's `event`.
