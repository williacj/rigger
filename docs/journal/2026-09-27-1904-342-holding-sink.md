# #342 — the sink holds events until the verb names the state directory

## What was built

`openSink` takes no directory now, and holds each stamped event until `name` gives it one (delta
H5, as ratified on #332). The directory is made at the first write, not at open. `end` is
idempotent. An unnamed sink writes what it held to standard error there, and writes any later
event to standard error as it arrives.

## What we learned

- **The round-3 measurement holds only for a process that has not printed.** The engineer's
  round-3 review on #332 measured `fs.writeSync(2, …)` arriving whole on Node 20 at 2,000,000
  bytes. That fixture never touched `process.stderr`. Once it has been touched, as it is in any
  verb that prints, the descriptor is non-blocking, and a single `writeSync` to a full pipe comes
  back short without throwing. Measured with a scratch fixture on macOS 27.0, one `writeSync` of
  200,000 bytes delivered this much:

  | Node | Bytes received |
  |---|---|
  | 20.20.2 | 8,192 |
  | 24.21.0 | 65,536 |
  | 26.5.0 | 65,536 |

  A loop that resumes after a short write and retries `EAGAIN` delivered 2,000,000 bytes whole on
  all three versions. It did so both from an `exit` listener and from a re-raised `SIGTERM`. The
  sink uses that loop. The test touches `process.stderr` before it writes past 65,536 bytes.
- **M2-06 #26 has the same trap.** The cleanup's own write to standard error will fail the same
  way if it copies the round-3 fixture. The loop lives in the sink and is not exported. Rule of
  Three says to extract it when a second caller needs it.
- **Making the directory at the first write changed how a test makes the sink refuse.** L2's
  refused-sink tests in `test/transitions.test.mjs` removed the state directory after the sink
  opened. The sink now remakes it at its first write, so those tests make the directory refuse
  writes instead, and they match `EACCES` where they matched `ENOENT`.

## What failed

Node 20 and 24 are not installed on this host, so this suite was run on 26.5.0 only. The
measurements above ran against Node 20 and 24 binaries fetched into the scratchpad. CI's matrix
is what runs the 65,536-byte test on 20 and 24.
