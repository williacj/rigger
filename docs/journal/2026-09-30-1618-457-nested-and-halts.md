# #457 — a nested worktree is refused, and every refused event is the halt

**The refusal test passed at the base for the wrong reason.** The first test, the handed engine
registered at `rigger-42/engine`, asserted only that the attempt fails naming the path. At the base
it passed: `git worktree remove --force` deleted the engine with the card's directory, and the
attempt then failed on the vanished handed path, whose message holds the card's path too. The
test went red only once it also asserted that the engine's uncommitted file still exists after the
failure. A refusal test here needs to show the refusal changed nothing, not only that it failed.

**L1 reads the list, and compares by real path.** L0 gained `registered()`, every path
`git worktree list --porcelain -z` lists, read by the same parser `registration` now shares. L1
resolves each by real path and refuses where one lies strictly inside the card's directory. A path
that no longer resolves, a registration whose directory is gone, lies nowhere, so a `prunable`
registration does not stick the card. A link inside the workspace resolves to where it points, so
a worktree reached only through a link does not count, and `git worktree remove` does not follow
the link. The check runs before `writable`, so a refused workspace keeps its modes, which the
nested owner's read-only directory shows (mutation N8).

**A refused event reached L2 as a workspace L1 could not make.** L0's `fetch.retried` was emitted
bare, so the sink's error left the fetch as a plain failure. L0's kill events already rejected as
`EVENT_REFUSED`, and L1's `step` wrapped both into `WORKSPACE_NOT_MADE`, as it did its own refused
`workspace.failed`. L0 now rejects a refused `fetch.retried` as `EVENT_REFUSED`, and L1's `notMade`
carries any L0 refusal, and its own refused `workspace.failed`, as `EVENT_REFUSED`. L2 already
treats every code but `WORKSPACE_NOT_MADE` as the halt, so no layer above L1 changed.

**Two first attempts hid the retry.** The halt tests at the loop first passed without the fix for
the kill event and `workspace.failed`, because the second attempt met the same refusal, so nothing
started either way. Each now refuses only the first event, or clears the plain directory before a
second attempt, so a retry would start the step and the maker, and the test tells the two apart.

**Not every L0 event can be forced through the workspace path.** `timeout.killed` needs a git call
to outlast `GIT_TIMEOUT`, five minutes, and `group.killed` a process-table read that fails; neither
timeout nor `ps` reaches L1's handle, and the retry test's world builds that handle itself.
`output.held` is reachable, through a stand-in whose child leaves its group holding the output,
but the only such fixture lives inside `test/process-adapter.test.mjs`. The PR names these.
