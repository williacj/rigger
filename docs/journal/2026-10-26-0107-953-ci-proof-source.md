ABOUTME: Why candidate CI proof keeps its recorded merge source while reporting later main movement.

# CI proof names its tested source

The inline CI policy keeps the event's PR base and head separate from the freshly read PR
and branch facts. The checkout must still match the event merge SHA, tree and ordered parents,
and its parents must be the recorded base and head. The current PR head, base ref, state and
draft status must still agree. For a main-targeting PR, a different current PR base or main
head alone no longer invalidates that recorded source. Nonmain targets keep both original base
equality guards.

The aggregate retains exact equality with the source recorded by plan. Its JSON output names
that source and exposes `testedBase`, `currentMain` and `mainAdvanced`. The last field compares
the tested main base with the observed main head; it is null for a PR targeting another branch.
The collector reads actual main separately for that case rather than presenting the other
branch's head as main. This implements the owner's [Q1 ruling](https://github.com/williacj/rigger/issues/953#issuecomment-6401702096)
without changing merge-time policy or repository settings.

Controlled tests cover Table A using literal merge, event, current API and proof identities.
They preserve refusal of changed proof identities, changed current heads, unavailable facts,
unauthorized labels and missing tier results. The CLI output check uses local recorded Git/API
stand-ins. A guarded mutation removing the added JSON visibility fields failed its named
assertion; restoring the exact original bytes made it pass again.

The Linux checks do not supply the card's two live-forge outcomes. Those remain unproved until
the coordinator admits and records distinct stale-start/unmoved-main and equal-start/moving-main
attempts. A run whose main moves is still evidence only for the merge source it executed.

The recorded-fact cases run in the ordinary tier so hooks and portable feedback exercise the
policy without hosted proof. Their shared fixtures and workflow parser have one definition;
the ordinary evaluator imports the actual inline exports and supplies the recorded collector
collaborators in process. Its one-time initialization makes the CLI entrypoint inert and
restores the selected environment value before any case runs. The host subprocess evaluator
and actual CLI boundary tests retain their existing execution path.

The deferred-report naming defect at `0c58ff2c` used the required `check (26)` context for
truthful deferred aggregate failures as well as eligible full proof. The check job now has an
explicit name: a successful canonical BROAD_DEFERRED plan selects `broad deferred (26)`;
other planned outcomes select `check (26)`. The job ID, condition, matrix, dependencies and
all policy, collector, source, guard and worker/aggregate code remain unchanged. Deferral
still fails; a name is not proof.

The ordinary regression first failed because the actual parsed job had no explicit name. The
one-field change made it pass. Literal canonical-plan cases protect required naming for
eligible, INVALID, UNKNOWN, failed, cancelled and missing-plan states. A guarded mutation
removing the successful-plan predicate failed the failure-plan assertion and was restored
byte-exact before green. Source comparison preserves every pre-existing workflow byte except
the added field, every old test body and the shared helper.

This pure evaluator covers only the admitted canonical producer domain and missing values.
GitHub's [expression documentation](https://docs.github.com/en/actions/reference/workflows-and-actions/expressions)
uses case-insensitive string comparison; the tests claim no general JavaScript/GitHub
equivalence or protection against fabricated lowercase producer modes. Actual rendered names,
new-head full proof, deferred reports before and after it, check-app/rules identity and normal
server merge eligibility remain pending. Historical runs and approval remain at their actual
older source, and independent review must verify any permitted evidence-reuse boundary.
