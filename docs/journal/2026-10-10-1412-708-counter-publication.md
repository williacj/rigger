# Publish a complete post-kill state count

The [#708 card](https://github.com/williacj/rigger/issues/708) owns the two state-read counters in `test/never-stop.test.mjs`. The [#615 normal-suite failure](https://github.com/williacj/rigger/issues/615#issuecomment-6100898664), measured on 2026-10-10 at `413a4a9` plus additive F-R2 tests, provided another occurrence: an ordered read trace recorded the second live answer with count 2, then a later timed-out read, while the test's final counter read returned an empty string. The trace did not observe shell open/write syscalls, so interruption between redirection truncation and `echo` remains an inference from the file state and the interrupted read.

The selected-base fixture used unlocked read-modify-write and redirected `echo` directly onto `state-count` at `7f26ab8` lines 1728–1729 and 1804–1805. An additive third-write forcing pauses after the base shell opens the destination. In ten serial host-gated selected-base runs on 2026-10-10, the named `:2260` test failed at `the plain failed state read was not reached` in every run; the retained `base-forcing-series.jsonl` and its separate TAP originals identify each attempt. This is controlled evidence for the truncation failure path, rather than a ruling on #699's historical `r03` phase.

The fixture now uses macOS `lockf -k` to serialize each increment and writes the next value to a sibling file before `/bin/mv` publishes it. The selected lock file remains inside that test's scratch directory. A new overlap test starts two counter calls at a barrier; with the old update it measured a final 1 after both calls exited 0, while the changed update measured 2. The test then exercises the real post-kill cleanup path. The head's third-write forcing opens only the sibling file and holds the update; an additive assertion confirms that interruption was reached, while the protected counter assertion still reads the prior complete value. Ten serial host-gated head runs on 2026-10-10 passed the same named test; `head-forcing-series.jsonl` names their distinct TAP originals and load measurements.

An S4 control uses the existing listing clock cut to reach exactly one failed state answer and checks that the protected count guard still rejects the absent second call with its original message. The ordinary `test/never-stop.test.mjs` run with this repair measured 131 passes and zero failures on 2026-10-10 before the staged-write assertion was added. The final-code `npm test` attempt `normal-d440rrq4` measured 2,720 tests, 2,703 passes, zero failures and 17 skips on 2026-10-10, at one-minute load 3.41 before and 6.74 after on 12 logical CPUs. The repeated file-run verdicts are recorded with the pull request rather than inferred from that earlier file run.
