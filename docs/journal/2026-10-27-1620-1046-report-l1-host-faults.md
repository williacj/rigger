run's id is a heading indented two spaces, and the stream's heading is "across the stream". The
signals sit four spaces in.

L3's lines keep their text and move under the `L3` heading. They are indented two more spaces,
so a run's heading reads alike in every section. The Layout grant covers the one existing test
line this moved: the two-runs test's split by run. It now splits L3's section on `^  run `. The
Other-layers grant covers the second: the no-other-layer test now refuses `L0` and `L4` to `L9`,
and asserts that the `L1` and `L2` headings are present.

A rate prints as `name: rate (numerator label N, over denominator label D)`. A zero denominator
prints as `no name: why`, and never as a number. The rate is shown to four decimal places at
most, as L3's figures are.

## Cases the rows did not name

The catch-all row defers these to "What `report` derives". Each is how I read it:

- **A claim's next `pull` is sought within its own run.** The denominator is "the work claims,
  by `run` and `card`". So the stream's figure is the sum of its runs' figures. A `merge.start`
  recorded in a later run never turns an earlier run's claim into a merge claim.
- **"Carrying `reason`" and "carrying `maker`" mean the field is present on the line.** The
  envelope's rule that null and absent are alike is stated for `card` and `dispatch`. It is
  applied to a kill's `dispatch`, so a kill with a null or absent `dispatch` is counted nowhere.
- **A host-fault event with no `card` is not counted**, because the numerator counts events
  "under a card".
- **Every run in the stream gets a heading in each section**, including a run with no event of
  that layer. A run with no `dispatch.end` prints only its survivor rate's "no rate" line, and a
  run with no work claim prints only its host-fault "no rate" line.
- **A `dispatch.end` with no `card` prints without one**, so a provisioning step's end shows its
  card only where L1 recorded one.

## One stream, figure by figure

This is the stream the test "report over two runs derives each run's L1 and L2 figures from its
own events, and the stream's from both" writes, with the report `rigger report` printed over it:

```text
r-a  L3 pull #7 | L2 maker.failed #7 | L3 pull #8 | L1 dispatch.end d-1 100 ms | L0 survivor.killed d-1
r-b  L3 pull #9 | L2 judge.withheld #9 | L1 dispatch.end d-2 100 ms | L1 dispatch.end d-3 100 ms
```

```text
L1
  run r-a
    dispatch d-1: 100 ms
    survivor rate: 1 (dispatches with a survivor or group killed 1, over dispatches that ended with a result 1)
  run r-b
    dispatch d-2: 100 ms
    dispatch d-3: 100 ms
    survivor rate: 0 (dispatches with a survivor or group killed 0, over dispatches that ended with a result 2)
  across the stream
    dispatch.end events: 3, each listed under its run
    survivor rate: 0.3333 (dispatches with a survivor or group killed 1, over dispatches that ended with a result 3)
L2
  run r-a
    host-fault rate: 0.5 (host faults 1, over work claims 2)
  run r-b
    host-fault rate: 1 (host faults 1, over work claims 1)
  across the stream
    host-fault rate: 0.6667 (host faults 2, over work claims 3)
```

Each figure, and the events it was counted from:

- **r-a's durations:** its one `dispatch.end`, d-1, 100 ms.
- **r-a's survivor rate:** its denominator is d-1, which carries no `reason`. The numerator is d-1
  as well, because r-a's `survivor.killed` carries `dispatch` d-1. That gives 1 of 1.
- **r-b's durations:** d-2 and d-3, 100 ms each.
- **r-b's survivor rate:** the denominator is d-2 and d-3. No kill event carries either id, so the
  rate is 0 of 2.
- **The stream's count:** the three `dispatch.end` events above.
- **The stream's survivor rate:** d-1 of d-1, d-2 and d-3, so 1 of 3.
- **r-a's host faults:** the `maker.failed` under #7. Its work claims are the `pull` of #7 and
  the `pull` of #8, since no `merge.start` follows either. That gives 1 of 2.
- **r-b's host faults:** the `judge.withheld` under #9, over the `pull` of #9, so 1 of 1.
- **The stream's host faults:** both faults over the three work claims, so 2 of 3.

The L3 section prints that each run's span is zero, because every event carries one time. The
marker check names no marker.
