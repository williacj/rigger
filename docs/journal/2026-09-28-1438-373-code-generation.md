# #373 — No module under `src/` runs code it builds at run time

## What was built

- `test/layer-boundaries.mjs` gained the code-generation rule, beside the dynamic-import rule and
  shaped like it. `GENERATORS` lists `eval`, `Function`, `constructor` and the three enumerators of
  own properties, refused wherever a module names one as a value or as a fixed string. `GENERATOR_MODULES` lists `node:vm` and `vm`, refused
  as a static import, a re-export, a star export or a dynamic `import()` whose specifier the source
  fixes.
- A name that only keys an object literal or a class member reads nothing and passes, as the
  loaders' names do, so a class may still declare its own `constructor`.
- A dynamic `import()` of `vm` is reported under the new rule in place of the dynamic-import rule,
  so the message names why it is refused.

## What we learned

- **`constructor` is the route that spells no other name.** Every function reaches the `Function`
  constructor as `.constructor`, and an async or generator function reaches its own kind of it,
  which no global names. Refusing `Function` alone leaves `(async () => {}).constructor(code)` open.
  Refusing the name `constructor` closes that and also the destructured
  `const { constructor: build } = fn`. It costs `src/` nothing: at `d3da69f`, `grep -rn constructor
  src/` finds it only in two comments.
- **Enumeration spells no key at all.** `Object.getOwnPropertyDescriptors`,
  `Object.getOwnPropertyNames` and `Reflect.ownKeys` list a prototype's non-enumerable own
  properties, so an async function's prototype yields its constructor with no `constructor`
  written anywhere. The rule refuses those three names too. A probe script run at `1f21242` over
  `src/` found that no module names any of them.
- **What remains is the loaders' limit.** A key the source does not fix is out of this reader's
  sight, for `constructor` exactly as for `mainModule`: one computed from a variable, joined from
  parts, or handed in as a parameter. That stays a review finding, as the reader's comment says.
  Refusing every such read is not open to this card: the same probe counted 44 computed member
  reads with a non-literal key, in 10 modules under `src/`.
- **Mutations shown to discriminate.** Each mutation had its anchor found once, was read back off
  disk, and was run on `test/layer-boundaries.test.mjs`'s 93 tests at `6a3ce1c`. The file was then
  restored byte-exact against `HEAD`. Each reddened exactly one test:
  - `eval` dropped from `GENERATORS`: the eval test.
  - `Function`, `constructor`, `getOwnPropertyDescriptors`, `getOwnPropertyNames` or `ownKeys`
    dropped, each on its own: the Function-constructor test.
  - The key exemption dropped: the test that a class's own constructor passes, on
    `export class Card { constructor(id) { … } }`.
  - The dynamic `import()` of `vm` not refused under the rule: the `vm` test.
  - The static import of `vm` not refused: the `vm` test.
