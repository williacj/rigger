# Card #1246: unchanged head

L2 now compares the tip with the head it gave the maker inside one settle, after the forge has shown
that tip. A forge still showing another head therefore runs the existing reads first, and a tip
the forge never shows is withheld rather than escalated.

The standing rulings reach L2 as the markers L2 already handed the maker, through L3 unread beside
`startHead`. `markerReason` in `src/workflow/judges.mjs` cannot be imported, because that file does
not change on this card, so `standingRuling` writes the same form from the handed shape.

The card's class 2 list predicted the wrong reds. Measured with `npm test` on the Mini at the card's
working tree: `test/loop.test.mjs` L1724 went red, and lane L1063, `judgedPull` and hold-close
L202/L207 did not. Three tests the list did not name went red: lane L204, lane L749 and the
`continuing-maker` rows of the judge selection memory test. Each had a maker leave the head it was
given. The coordinator granted their lines as M7-K68.

The memory test's states need the judge's identity to stay at the seed head after a maker returns.
Flipping the forge's head around the settle does not hold that, because L2 decides the judges from
what the settle read. Giving the maker a different head to start from does, so the maker's tip
returns to the seed head.
