# On a hold, Rigger opens the status issue in Owner

K53 gave this card the renames that attach the status issue's number to a hold's closer. r4 planned
the card without a change to `src/substrate/forge/read.mjs` (N1). B2 gave the issue's state to
M6-11c. Both moved here. At `66e5b7c9`, `readIssue` answers no state, and the read side has no
label read, no newest-number read and no permission read of its own. The notice needs all four. So
this card changes `read.mjs`, a Self-hosting path, and the owner judges last: the pull request needs
the owner's marker at its head (`D25` rules 5 and 7).

The architect attack's placement ruling binds the shape. The notice is phased, never a callback.
L2's notice function is an async generator. Each value it yields is a rename, "after `<k>`" or
"issue `<n>`". L3 makes that rename through `admission.mjs` and hands back the outcome as
`Promise.allSettled` records it. Only then does L2 go on. L2 is handed no admission handle and no
function: a test walks everything it is handed for a function and finds none. A rename that finds
its closer gone has L3 call `return()` on the generator, and L2 writes nothing more. L3 queues its
calls on one promise, so one call's steps end before the next call lists the directory. That is
what keeps a second call for the same hold from opening a second issue.

A test on the real `nextAction` under the loop found a defect the in-memory tests had missed. A
failure that carries its dispatch id had `attempt.failed` hand the sink a field named `dispatch`.
The sink stamps that field itself, so it refused the event, and L2 answered no action. The fix
records the failure under an emitter that carries the id. Only a test that drove the real L2
through the real sink could show it.

With this card in, holds reach the forge in test worlds that never needed it. Five existing tests
seeded a bare `hold-<id>.json` to prove that a closed admission writes nothing, and the trigger now
writes for such a closer. Two worlds' L2 reached the real `gh`, which the suite refuses (#276). One
grant request on #1016 covered them all.

Claiming `R-SCHED-23` over-reports it in `docs/derived/test-matrix.md` until M6-11c lands. This
card's tests cover only Table B's five rows. The issue's close, read at each trigger, reopens
nothing yet.

The write-access list `['admin', 'maintain', 'write']` now stands in four modules:
`status-issue.mjs`, `escalation.mjs`, `marker.mjs` and `judges.mjs`. Extracting it would change
modules outside this card's "Lands in", so it is named as work for a card of its own.
