`test/gate-closure.test.mjs` gains three tests, at acceptance revision `238f9a61f740`.

- The canonical-form test asserts `.github/workflows/self-hosting.yml` holds exactly one line
  `  SELF_HOSTING_COMMIT: '<40 lowercase hex>'`. It refuses the file, naming the line, where any
  other line holds `SELF_HOSTING_COMMIT` other than as the shell reference `${SELF_HOSTING_COMMIT}`,
  and where the canonical line is absent or occurs twice. It reads the key as a whole identifier in
  the line as written. A shell reference is never joined to the text around it, so
  `SELF_${SELF_HOSTING_COMMIT}HOSTING_COMMIT` holds no key, and neither do longer names such as
  `XSELF_HOSTING_COMMIT`. Round 4's reviewer found the first version deleted each shell reference
  before searching, which joined the text around it into the key.
- The ancestry test reads the pin from that one line and asserts `HEAD` reaches it.
- The closure test reads the pin from that one line, measures the check's import closure in the
  tree at that pin, and admits no bare import, no CommonJS call, and only `src/cli/doctor.mjs`'s
  config import.

The last two pass at #1373's merge, so the owner's M8-U13 admits them without a red run; the pull
request quotes each failing against a deliberate break. The canonical-form test was red first, run
against the YAML reader it replaced.

Earlier revisions of this pull request read the pin with a YAML reader. Rounds 1 to 3 and an
independent attack each found a YAML spelling of the pin that the reader mishandled: value quotes,
key quotes, continuation lines, a no-break space, a byte-order mark, CR line ends and root
indentation. The judges ruled each such spelling layout, so hardening the reader one spelling at a
time did not converge. The card's author then made the pin line's form part of the contract, and
the reader was removed. The canonical-form test now refuses, by its line, each of those spellings
that changes the pin's line. A byte-order mark before the first line leaves the pin's line
canonical, so it is read.
