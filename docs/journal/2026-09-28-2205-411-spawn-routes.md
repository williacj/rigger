# #411 — Rule 7 refuses every route to a spawn it can read

## What changed

Rule 7 in `test/layer-boundaries.mjs` now refuses, outside `src/substrate/process.mjs`:

- importing `node:cluster` or `cluster`, by any static form or a dynamic `import()` of a fixed
  specifier, beside `child_process` (`SPAWN_MODULES`);
- naming `binding` or `_linkedBinding` as a name or string that keys no object literal or class
  member (`BINDINGS`), which catches `process.binding(...)`, `process['binding'](...)` and
  `const { binding } = process`.

The routes came from the engineer's F3 on PR #410; the import-form tests from N47 there.

## Why a name, and not a call on `process`

The loaders (`LOADERS`) are already refused by name wherever a module names one, and the three
spellings the card names are all caught that way with no new reader. Matching only calls whose
receiver is `process` would miss an alias of `process` and add a reader of receivers. The cost
is that a module outside the adapter may not name a local `binding` either. No module under
`src/` does, by the boundary test's head-tree check at this branch.

## What it does not do

A key the source does not fix, such as `process[['bin', 'ding'].join('')]`, is outside the rule,
as #373 records for the code-generation rule. The comment above `SPAWNERS` says so.

A destructured `{ binding }` is reported twice on its line, once for the shorthand key and once
for its value, because acorn gives each its own node. The message is the same; nothing
depends on the count.
