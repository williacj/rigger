# An absent environment and an unpinned gate rule

The Claude reviewer and architect on [PR #731](https://github.com/williacj/rigger/pull/731) found that an absent `gate` environment hid a missing integration pin. The card requires the one gate line to name every fault it can judge. A missing pin needs no environment variable, so the absence of the environment does not defer that verdict.

The test-first run on 2026-10-13 added “gate line names the missing integration pin beside an absent environment” and failed with one test: the line contained only “environment gate is absent, or not readable with this token.” The one-minute load was 3.81 at start and end, with 472 user processes at start. Its full output is retained as `659-round2-pin-red.log` in the dispatch scratch directory.

The verdict now checks null integration pins outside the environment-present block. App-ID comparisons still require the variable read. The test covers both a ruleset and classic branch protection, and the subsequent `npm test -- test/doctor.test.mjs` run passed 98 tests, with no failures. Its one-minute load was 4.70 at start and 4.33 at end, with 465 user processes at start. The full output is retained as `659-round2-doctor.log`.
