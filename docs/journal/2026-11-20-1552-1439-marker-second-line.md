# The Codex judge's marker block goes on the verdict's second line

The coordinator's Codex judge prompt told a judge to end its verdict with the gate's marker block, while `parseMarker` in `src/workflow/marker.mjs` reads a block only where it opens on a comment's second line. A judge that followed the prompt literally posted a marker the gate never read: the Codex reviewer's verdict on PR #1436 (1436#7051260376) probed its own comment and got `{"state":"none"}`. The gate's own printed instruction already said "Its second line opens this block"; the prompt overrode it.

The prompt now shows the verdict's layout as an example inside a four-backtick fence: the heading, the `rigger-marker` block directly under it, then the rest of the verdict. Its prose says the same, and says to fill every placeholder, `coverage` included, to leave out `coverageReason` and `toSound` where they do not apply, and to copy the block without the run log's per-line prefix. That prefix was read from `gh run view 44823296567 -R williacj/rigger --log` on 2026-11-20: each line opens with the job name, a tab, the step name, a tab and a timestamp.

The new test in `test/coordinator-launchers.test.mjs` is a harness diagnostic with no `// proves` line, as the card states. It runs the real `codex-judge.sh` against the stub `codex` and checks the prompt it was handed against the card's conditions E1 to E4: one four-backtick example holding a `rigger-marker` line under "## Post", a `**Codex …**` first line, a block `parseMarker` does not answer `none` for, and a non-empty line after the block's closing fence. It names each condition a layout breaks. Its D29 rule 11 declaration names wiring as its reason, and `test/marker.test.mjs`'s "a marker block not directly under the comment's first line is no marker" as the deterministic test of the gate's read.

Three rounds shaped it. Round 1 found phrase checks for "second line" and "closing fence", so "line two of the comment" failed a correct prompt. Round 2 found a list of wrong-position words, so "at the top of the comment" and "not at the end" failed a correct prompt. The independent attack after that found the layout-example version still deciding things no one had fixed, such as refusing an unrelated fenced block placed first, and passing prose that sends the block last. The card's author then pinned the example's structure as E1 to E4 and left the prose to the judges' reading (M8-K53), and the test now checks exactly those conditions.

The differential test against the rebuilt source copy sets aside the changed "## Post" lines through a `placed` function called from `kept`, under the card's grant G1. The card's author widened G1 to cover the doc comment above `sourceCopy`, base lines 254 to 256, and this work rewrote lines 255 and 256 to say the comparison also sets aside the lines `placed` names.
