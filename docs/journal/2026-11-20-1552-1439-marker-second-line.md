# The Codex judge's marker block goes on the verdict's second line

The coordinator's Codex judge prompt told a judge to end its verdict with the gate's marker block, while `parseMarker` in `src/workflow/marker.mjs` reads a block only where it opens on a comment's second line. A judge that followed the prompt literally posted a marker the gate never read: the Codex reviewer's verdict on PR #1436 (1436#7051260376) probed its own comment and got `{"state":"none"}`. The gate's own printed instruction already said "Its second line opens this block"; the prompt overrode it.

The prompt now puts the block directly under the heading, the rest of the verdict after the block's closing fence, and says to fill every placeholder, `coverage` included, to leave out `coverageReason` and `toSound` where they do not apply, and to copy the block without the run log's per-line prefix. That prefix was read from `gh run view 44823296567 -R williacj/rigger --log` on 2026-11-20: each line opens with the job name, a tab, the step name, a tab and a timestamp.

The new test in `test/coordinator-launchers.test.mjs` is a harness diagnostic with no `// proves` line, as the card states. It failed on the prompt's text at `bbaa0429`, naming the sentence "End the verdict with the gate's marker block for your role.", and passes at the head. The differential test against the rebuilt source copy sets aside the changed "## Post" lines under the card's grant G1. The doc comment above `sourceCopy`, which says the comparison sets aside only the header and slot line, is not under G1 and is left as it was; the pull request names it.
