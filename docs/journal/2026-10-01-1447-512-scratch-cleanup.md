ABOUTME: Journal for #512 (M4-F5): `scratch` now removes its directory once its sweep has found no
process naming it, so the suite stops leaving `rigger-process-*` directories under TMPDIR.

# #512 — a scratch directory is removed after its sweep, never before it and never through a link

**The cause reproduced at the base.** At 0934433, `npm test -- test/process-adapter.test.mjs` in a
fresh clone, with TMPDIR a new empty directory, left 121 `rigger-process-*` directories in it.
`scratch`'s teardown called `sweep` and nothing else, so every test that took one left it.

**The order is the point.** The teardown sweeps first and removes second. `sweep` throws where a
process naming the directory is still alive, so removal never runs over a live process, and the
directory survives for whoever reads the failure. A mutation that swapped the two steps redded the
test that injects a process the sweep cannot end: its file was gone.

**The removal waits for the test's own teardown.** The first version removed the directory in the
hook that swept it. The pre-commit suite then redded nine tests, seven in `test/dispatch.test.mjs`
and two in `test/kill-recorded.test.mjs`, with `ENOENT` from `chmodSync`: each takes a scratch
directory, takes write permission away from part of it, and registers a hook to give it back after
`scratch` registered its own. `node:test` runs hooks in the order they were registered, so the
directory was gone before theirs ran. With Node 26.5.0, a hook added while teardown runs is run
after every other, which a probe showed for a passing, a failing and a timed-out test. So the sweep
keeps its place and adds the removal as a hook of its own, which sweeps once more and then removes.
A hook that throws stops the hooks after it, at the base as now, so a test whose own teardown throws
still leaves its directory.

**Write permission is restored by a walk that never follows a link.** Node's recursive `rmSync`
does not follow symbolic links, but it cannot empty a directory whose write bit a test removed.
So the teardown first gives the owner `rwx` on the scratch directory and every real directory
inside it, deciding by `lstat`, and refuses where the scratch path itself is no longer a
directory. A mutation that walked by `stat` instead changed an outside target's mode from 0o500 to
0o700, and the symbolic-link test redded on that mode.

**The new tests sit in their own file.** `test/process-fixtures.test.mjs`'s header and import line
are existing lines outside the O39 grant, so the tests went into `test/scratch-teardown.test.mjs`
rather than widening the diff. Four of them hold the teardown in a stand-in context made under a
TMPDIR inside the test's own scratch directory, so whatever a failing teardown leaves, the outer
teardown removes. The pass and fail cases run a real `node --test` child instead, because only the
runner says whether a test failed.
