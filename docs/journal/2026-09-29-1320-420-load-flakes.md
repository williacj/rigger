ABOUTME: Journal for #420 (M2-06d): why four tests failed under load, or at ordinary load, and why
each cause was in the test and not the product.

# #420 — Three test instruments that cost more than their tests allowed

## What was wrong

**T1 and T2** read a pid file the joined process had opened but not yet written. The stand-ins
answered once `joined.pid` existed, so the cleanup's kill could land between the open and the
write. The empty file read as `Number('')`, which is 0, and signal 0 to pid 0 reaches the test's
own process group, so the test saw a live process. The product had killed the joined one.

**T3**'s `ps` stand-in started four or five processes on every kill read. A 201-deep chain needs
201 reads, one after another, and under load that ran past the test's 10,000 ms read timeout.

**T4**, and guard-probe-kill's seventh test with it, counted macOS's assessment of a file just
written inside the 1,000 ms `OUTLIVED` window. The system holds the first exec of such a file
until it has assessed it.

## What taught us

The #418 maker's scratch directories were still on the host. Every one of the six logged T1/T2
failures had an empty `joined.pid`, and every passing instance had a pid in it. Reading what a
failed run left behind settled a question that instrumenting new runs had not caught.

The kernel source ruled out the first theory. XNU's `reap_child_locked` leaves the group and
leaves the pid table under one lock. So a group signal 0 finds empty, beside a pid signal 0
still reaches, has to be a different pid. It turned out to be pid 0.

T4's cost was visible only by comparing a first exec with a second exec of the same file. At
idle a fresh three-line script took a median of 42 ms to reach its first line, and a second exec
of it took 3 ms. Beside whole suites, one first exec in 150 took 1,058 ms. A 250 MB script makes
the first exec take 1.4 s every time, which forces the cause without a sleep.

## The fixes

- **T1 and T2.** The joined process writes its pid under another name and renames it. It then
  holds until its caller has ended, so the kill always lands straight after the join is
  announced.
- **T3.** The stand-in is compiled, and starts only `ps` on each read, as the author ruled.
- **T4.** Every fixture can be warmed: run once to an exit before its body. The stand-ins that
  must be ready within `OUTLIVED` are warmed before the timed call.
- No bound was raised.
