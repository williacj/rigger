# #382 — No module under `src/` starts a worker thread

## What was built

- `GENERATOR_MODULES` in `test/layer-boundaries.mjs` became a map from each refused built-in to
  why it is refused. `node:vm` and `vm` keep #373's reason. `node:worker_threads` and
  `worker_threads` carry their own: a worker runs code from a string or from a file that rules 7,
  8 and 9 never read, since they read only `src/`'s import graph.
- The rule's two checks, static and dynamic `import()`, read the map, so a worker is refused
  wherever `vm` already was: a named, default, namespace or bare import, a re-export, `export *`,
  and an `import()` whose specifier the source fixes.
- One new test in `test/layer-boundaries.test.mjs` covers those ten shapes, under a comment that
  says why the rule exists.

## What we learned

- **A worker is two routes, and only one of them is code built at run time.** `new Worker(code,
  { eval: true })` runs a string; `new Worker(path)` runs a file the rules never parse. So #373's
  message, "code built at run time", would misdescribe the second. That is why the map carries a
  reason per module rather than one shared suffix.
- **No new route around it.** `getBuiltinModule('worker_threads')` and `require` are already refused
  by the dynamic-import rule's loaders. A specifier the source does not fix is already refused by
  the dynamic-import rule. The computed-key limit recorded beside `GENERATORS` holds here too, as
  the card says.
- **Mutations shown to discriminate.** Run by `c382-probe.mjs` in a fresh clone at `6f2c97b`, each
  mutation had its anchor found once, was read back off disk and shown by `git diff --shortstat`,
  ran the file's 94 tests, and was restored with `git status` clean:
  - `node:worker_threads` dropped from the map: the worker test alone.
  - `worker_threads` dropped from the map: the worker test alone.
  - The static refusal removed: the `vm` test and the worker test.
  - The dynamic refusal removed: the `vm` test and the worker test.
