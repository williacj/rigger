# #430 — Ask what is at the path, not what the list remembers

**The list records registrations, not what is at a path now.** Round 1's fix left out entries git
marks `prunable`. The engineer judge then found two registrations git never marks prunable. One
was a locked worktree whose directory was deleted and replaced by a plain directory. The other was
a deleted worktree whose path now held another repository's worktree, whose `.git` file made the
stale registration look alive. Both read as this repository's worktree. A flag on the list only
narrows the cases; it cannot answer the question.

**Git answers it from the path itself.** `isWorktree` now asks git in the path for its top level,
its git directory and its common directory. It answers yes only where the top level is the path,
the common directory is this repository's, and the git directory is not the common directory,
which is how the main working tree answers. Each of the three conditions, mutated away, reds a
test: the subdirectory test, both different-repository tests, and the three main-working-tree
tests.

**Two rounds found what one fixture shape hid.** Every earlier fixture left the path and its
registration in step. Both counterexamples put a stranger at a path the repository still
registers, which is the state item 6 says the card must expect.
