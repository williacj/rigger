# Run stays up

Card [#1175](https://github.com/williacj/rigger/issues/1175) (M7-24), acceptance revision
`03d0c41be0e5`, from `origin/main` `752cdfd0`. While a clock trigger is declared, `loop.mjs`'s
`run` stays up past the drain, polls the board through `clock.mjs`'s one timer while it holds no
claim, and hands each settled hand-over to the verb, which writes it to standard output.

## What one idle poll costs (row L16)

A measurement: `test/loop.test.mjs`, "L16", on 2026-11-01 at this card's head, Node v26 on macOS
27.2 arm64. It counts each read the poll makes through the loop world's board handle and its
in-memory fake repository, one count per named read, on two board states, admission open, the poll
claiming nothing.

| Board state | *a* | *r* | Forge calls counted | Judged 3 + *a* + 6*r* | Difference |
|---|---|---|---|---|---|
| one card, in Done | 0 | 0 | 2: `readColumns`, `readPriority` | 3 | one fewer: `readBranches` is read only where a card is in Ready, Coding, Review or Owner, which the judged 3 counts always |
| two cards in Owner, each with one open pull request | 2 | 2 | 17: `readColumns`, `readPriority`, `readBranches`, then for each card `readPullRequests`, `readMergeBase`, `readDiff`, `readComments`, `readMergeable`, `readEffectiveRules`, `readCheckStates` | 17 | none |

The judged figure counts the card's pull request read inside *a*, and six reads inside 6*r*; the
measured split is the same sum. A card that a poll claims, or that this run set aside, is not read
again by the facts call, so a poll over such a board costs less than the formula; the first state
uses a Done card for that reason.

## Cases no row of Table L decides (row L20)

- **A pull that fails or reads admission closed without a drain.** "Where `run`'s outcomes go" hands
  over at a drain, and a poll's failure as it settles. A cascade that claimed cards, ended without a
  drain (as after a merge claim or a refused move) and failed is handed over when it settles, with
  the cards it settled; one that neither drained nor failed keeps its cards for the next drain.
- **A poll that reads admission closed** hands over the closers at each such poll, since each poll
  "names each closer" (L10), not only at the idle period's drain.
- **A stop fired with claims held** also stops the pulls at slot release, so no new claim extends a
  stopped run; "ends once its claims finish" is read as the claims held when the stop fired.
- **`rigger run`'s exit at `SIGTERM`.** L0's exit cleanup re-raises the signal once it has cleaned
  up, so the process ends by `SIGTERM`; its parent sees no exit code and the signal, which a shell
  reports as status 143, `128 +` `SIGTERM`'s number. L17 asserts both.
- **The `run` verb's text at a stop when nothing settled since the last hand-over** is empty, with
  the status picked over every hand-over (the architect's ruling 1175#6560236393, (b)).

## Round 1 of review

Both judges found that a drain which read admission closed dropped the cards that settled in it,
and their status: the verb rendered a closed admission's closers alone, because a single pull
never claims beside a closed admission, and a kept-up drain can. The verb now says those cards
after the closers and counts them toward the status, and says a closed admission's closers beside
a failure where the held cards have not named them. The architect found that a poll whose trigger
event the sink refused still claimed a Ready card; `take` now claims nothing for a refused poll,
and only for a poll, so every other trigger keeps its merge-base behaviour. The reviewer found that
a no-clock failure had lost the empty `reports` and `handoffs` it carried at the merge base; it
carries them again. Each fix began with a test that went red for the reason the finding gave.

One thing seen while building the verb tests, outside this card: a clock-held `run` re-pulls at
each slot release (L7), so a card whose maker exits non-zero and which L2 neither stops nor
withholds is claimed again at once, and again, until the run is stopped.
