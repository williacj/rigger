# The guide and the reference

#926 adds `docs/guide.md` and `docs/reference.md`, links both from `README.md`, and gives each a
strict entry in `doc-references.json`. The sections are the card's Table A, in its order, and
each links to the section the table pairs it with on the other page.

## What the pages write

The base is `origin/main` at `a23d98d`. Each page writes only behaviour landed there, and cites
the requirement that owns each behaviour by id. To keep that claim checkable, every id either page
cites is one a test claims in `docs/derived/test-matrix.md` at the base (a measurement: the
matrix read at `a23d98d`, one grep per id), apart from two. `R-LOOP-1` is made true by the role
prompt, and the reference cites `R-ESCALATE-19` as the owner of the categories rather than as
behaviour. The reference retypes no verb, key, column name, label,
category or marker field; each of its sections names the document that owns its fact.

The escalation section writes #858's landed part: a card carrying the escalation label waits, and
the owner answers by removing the label (`R-ESCALATE-10`, `R-ESCALATE-11`, `D27`).

The first round's judges found three faults, which the second commit fixes. Some escalation
sentences cited their requirement only in a later sentence, and one said every escalation goes
to the owner, which `R-ESCALATE-15` contradicts. The guide restated what verbs do, which
`README.md` owns. And the guide's pointer for exhausted rounds led to a section that did not
answer it. Each behaviour sentence now cites its own id, the guide names verbs only as steps and
links `README.md` for what they do, and the escalation section states `R-LOOP-9`'s outcome. Both
judges also ruled the acceptance's coverage insufficient. That is the card author's to revise, so
it went to the PM on #926.

The PM then revised the acceptance, to revision `b5c1599927e2`, adding five items. The third
commit meets them at the same base:
- no sentence on either page says what a verb does, and each sentence naming one links
  `README.md`'s verb list;
- setup is four numbered steps, each with what to check;
- daily operation is three numbered steps, ending at the board, the card's pull request and
  `rigger report`;
- how the loop works follows a card through the columns in the "Engine settings" order, calling
  each by its config key rather than a display name;
- troubleshooting has a row for each check `README.md`'s `doctor` line names.

The second round's architect found the reference's marker section defining what a marker is, a
fact `ARCHITECTURE.md`'s "Markers" owns. The fourth commit removes that sentence, and the section
now only links its sources.
