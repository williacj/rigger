# #383: wait for the entry, then lock the state directory

## What was wrong

`test/dispatch.test.mjs`'s test "given a sink that refuses the kill event and a record that
refuses the removal…" ran a command whose first action was `chmod 555 .rigger`. The fixture's
comment said the entry was written once the command ran, but that is false. L0 spawns the
command, reads the leader's start time with a synchronous `ps`, and only then does L1 write the
entry. Under load, the `chmod` landed in that window. The engineer diagnosed this on PR #380.

## What changed

The command's first line is now a read loop, `until grep -q "\"group\":$$," groups.json`. It
changes no permission until the record names its group. L1 replaces the record by a rename, so the
read never sees a partial write. The comment now states that ordering. No assertion changed, and
nothing under `src/` changed.

## Forcing the race

A harness loaded with `node --import` wraps `execFileSync` so that L0's `ps … lstart=` read waits
before it runs. It waits until the state directory has no write bit, or for 3 s, whichever comes
first. That holds the spawn-to-entry window open without editing the test or `src/`. The harness
is scratch work, not merged; its source is in the PR body.

- At the base `c4e933f`, the chmod landed while the window was held, and the test failed. Its
  unrecorded events held `bash` and `grep` survivors: L0 had killed the group while the command
  still ran.
- At the head `594fe49`, no chmod landed during the 3 s hold, and the test passed.

## Measurements

Measured on macOS 27.0 (12 CPUs) with Node v26.5.0, in fresh clones of
`https://github.com/williacj/rigger.git`, under a TMPDIR of the card's own.

- **Load.** 12 busy `node -e 'for(;;){}'` loops. The 1-minute load average was 42 at the start
  and 129 at the end.
- **Runs.** The one test, run through `npm test -- --test-name-pattern=…
  test/dispatch.test.mjs`. Base and head were interleaved per iteration, 100 times each.
- **Result.** The base failed 11 of 100, every one on `failure.result?.exit` (`undefined`, where
  4 was expected). The head passed 100 of 100.
- **Suite.** `npm test` passed 1,134 of 1,134, exiting 0, at both the base and the head.
- **Teardown on a red run.** A mutated grep anchor makes the wait never end. The test then fails
  when L0's 15 s timeout ends the command, and `pgrep` finds no process left under the TMPDIR.
