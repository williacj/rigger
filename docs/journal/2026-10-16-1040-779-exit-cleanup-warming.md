# Exit-cleanup fixture warming on the new host

The #779 targets each have a 30,000 ms test guard. At base `59b5883b4cd0387090d21044ccce2796a721278b`, `fixtures()` writes and synchronously warms its full fixture set before it starts the caller. The ordinary two-group paths use `command`; the `ps-never` and joiner paths select additional fixtures. The original nine cases can therefore spend their guard on fixtures they never run. The five added cases need the full set, but sequential first executions can spend the same guard before their caller starts.

The repair selects `command` alone for ordinary paths and warms the full set concurrently when a caller selects a `ps` stand-in or alternate command. Its concurrency changes setup timing while retaining every selected shell body and every caller, process, signal, status, liveness, census, kill-record and teardown check. The new regression asserts the ordinary path's fixture selection. The `ps-never` no-match assertion reads the real `pgrep` status, output and spawn error at its original position.

The falsifier is a trace in which fixture warming has returned before the original guard but the caller or an observation remains pending until it expires. Such an attempt needs its own first-divergence diagnosis and cannot be credited to this setup cause. Likewise, an uninstrumented historical timeout does not identify which operation consumed the guard.
