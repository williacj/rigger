ABOUTME: Records how ci.yml's host startup pins drifted from main, and how a deterministic test now
refuses that drift.

# Hold ci.yml's source pins to the files they pin

`.github/workflows/ci.yml`'s host startup check qualifies a run only where `.npmrc`,
`test/suite.sh` and `test/suite-guard.cjs` hash to the SHA-256 it pins in `projectSources`. The
pins came in with PR #1289 (card #1115), measured against the main line that pull request merged
onto at `4e884a31`. PR #1254 (card #1137) then changed `test/suite.sh` and `test/suite-guard.cjs`
and merged at `52fb8a3d`. Each pull request's `ci:full` was green on its own base, and a recorded
proof is kept across main's moves, so the two were never run together. From `52fb8a3d` on,
`full_host` had no qualified startup and no host key, and `check (26)` failed for every pull
request ([CI run 42558570287](https://github.com/williacj/rigger/actions/runs/42558570287)).

Nothing deterministic noticed because `test/ci-host-fixtures.mjs` held the same three values a
second time for its stand-in startup inspection, so every test using it agreed with the pins
whatever the files held. The fixture now reads them from `ci.yml`, the pins' only copy, as the
architect ruled ([1323#6732260863](https://github.com/williacj/rigger/issues/1323#issuecomment-6732260863)).

`test/ci-source-pins.test.mjs` hashes each file `projectSources` names and asserts it equals its
pin, naming the file when it does not. That test is an invariant guard, so its proof is the killed
`npm run mutation:receipt` quoted on the pull request, which changes one pin in `ci.yml` and turns
the test red naming the file, rather than a red run before its code. Because the drift was live
at the base, the test also went red there before the re-pin, naming `test/suite.sh` and
`test/suite-guard.cjs`; that red is the defect on main, not a red the guard's code was written to.

Cases no acceptance item decides, met while making this:

- Re-pinning `ci.yml` while the fixture still held the old values turned 15 existing tests in
  `test/ci-host-report.test.mjs` red, because the stand-in's fingerprints no longer matched what
  the check accepts. The second copy only ever caught a change to the pins, never a change to the
  files.
- The grant's three lines became one line spreading `projectSources` into the fixture's map, in
  the same order, so the fixture's paths are whatever `ci.yml` pins.
- The guard hashes working-tree bytes. `.gitattributes` does not pin `test/suite.sh` or
  `test/suite-guard.cjs` to LF, so a checkout converting line endings would red it; no CI job runs
  on Windows, so that checkout is not one this repository runs.
