# 2026-09-25 — `once` claims one card and says it did not work it

`src/cli/once.mjs` composes what `plan` composes — the source-tree guard, the consumer's config,
the read side and L2's next action — and adds L2's column changes and L5's sink, then hands all
of it to `claimOnly` with a claim limit of 1. The limit is the verb's own literal. Rule 4 of the
boundary test bars `src/cli/` from naming N, so a copy of the config with N set to 1 was never
open to the verb, which is why #231 gave L3 a limit at all (R3-B2 on #211). One handle is built
per invocation: two handles over one board would each claim the same card, because a claim is
held in memory on the handle that took it.

**Refusals reach the verb through `decide`, not through L3.** `claim()` answers the cards it
claimed and nothing else. The reviewer on #312 ruled that the verb sees every refusal through
the next action it injects, so the verb wraps `nextAction` and keeps each `{ action: 'refuse' }`
it returns. The lines are printed with `plan`'s own `refusalLine`, exported for that rather than
copied.

**A redo is claimed where it stands.** The PM revised the acceptance on 2026-09-25 for this: a
pullable Review card is the one card `once` claims, and its claim writes a pull event, no move,
and no L2 transition. `claimOnly` already does this, since its shared `start` step skips L2's
move for a redo, so the three redo tests passed as written. The one fixture, a Review card and a
Ready card under N 3, is shared by all three.

**The exit is non-zero after a claim, and zero with nothing to pull.** The README promises that
`once` pulls and finishes one card. A card claimed and not worked falls short of that, so the
verb exits 1 and says why: dispatch arrives with M2 and M4. Nothing to pull is the one outcome
the verb meets in full, so it exits 0 (U29). Which stream the message lands on follows from the
exit, because `rigger.mjs` writes a zero exit's text to stdout and any other's to stderr; the
tests read the stream the exit chooses.

**This card is the first production caller of the sink.** `test/event-sink.test.mjs` held that
nothing in production reaches for the sink, "until then" being the day a verb records events.
The acceptance has `once` write L3's and L2's events into `.rigger/events.jsonl`, so the guard's
premise ended with this card. It was narrowed rather than dropped: no layer opens the sink,
because a layer that did would name the state directory and the run, which the process owns,
and could write another layer's events. Only `src/cli/` opens it. The state directory's name is
`report.mjs`'s `STATE`, exported so the two verbs share one spelling.

**The run id is a UUID.** Nothing in the binding documents names how a run id is minted. The
report groups events by it, so each `once` invocation needs one no other run shares, and a UUID
is the smallest thing that gives that. A judgment, open to a later card that wants run ids a
person can read.

**The no-dispatch item is observed two ways.** A stand-in `claude` sits beside the fake `gh` on
PATH and records each run, because every role in the template's config names `claude` as its
provider and a dispatch runs the provider's CLI. The test asserts it was never run, and that no
recorded event carries a dispatch id or arises under L1. Neither observation is one the verb can
satisfy by accident.
