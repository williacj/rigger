# Which escalation note L2 reads

Card #942 (M6-03m) is the structure delta the architect owed in
[the rulings on #939's Q2 and Q3](https://github.com/williacj/rigger/issues/939#issuecomment-6386025375)
("Structure delta owed"). It adds both rules to `ARCHITECTURE.md`'s paragraph beginning "A maker
that cannot meet an acceptance item writes one escalation note and ends", and changes no sentence
already there.

## What the delta proposes

- **Q2: L2 ignores an edited note.** The forge answers only a comment's current body, so an edit
  leaves no first version to read. The reason is the one `D25` rule 2 gives for markers.
- **Q3: the earliest note counts.** L2 filters by write access, then by being unedited, then by
  parsing as a note, then by the dispatch id L2 reads notes under. Of the notes left, it reads the
  earliest in oldest-first order, ties kept in the forge's order.
- The filter names "the dispatch id L2 reads notes under", not the maker's, because the
  pre-dispatch attack on #942 (finding 1) showed M6-20a reads a role's note under the role's
  dispatch id (`ARCHITECTURE.md`, "Failure model").

## The cards that rest on it

- **#939 (M6-06)** builds the note read in `escalation.mjs` against both rules. It carries them in
  its own text, so this delta does not block it.
- **M6-20a** reads a role's note under the role's dispatch id by the same rules.

What would reverse the rules, per the rulings: the event record showing makers' escalations lost
because a maker edited its own note, or makers writing a second note to correct the first.
