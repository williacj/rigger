# #341 — Rigger ends every group it holds when it exits

## What was built

L0's adapter holds each group from the step that creates it until the call has emptied it. It
installs one exit cleanup when it creates its first group: an `exit` listener, and a listener for
each signal in `HANDLED`. The cleanup is synchronous. It kills any census read in flight. Then, for
each group, it takes the census, kills the group and confirms it. Only then does it record each
kill, and write the kills the sink refused to standard error. It hands each group to the caller's
`onExit`, which is where L1 removes a dispatch's entry. Last, it takes the steps handed to `atExit`,
which is where a verb ends its sink.

On a signal, the cleanup's listener runs ahead of every other listener, and runs the cleanup first.
It then takes itself off the signal. Where no other listener is left, it raises the signal again
with its default action. Where one is left, the process ends as that listener has it. If the
process keeps running, the listener is back on the signal a turn later.

The census became a generator of process-table reads, so the call and the cleanup share one census.
One driver waits on each read through `execFile`. The other runs each read through `spawnSync`.
The loop that writes all of a text to standard error moved out of the sink into
`src/substrate/standard-error.mjs`, because the cleanup is its second caller.

## What we learned

- **Which signals end a Node process, and which a listener can take.** Measured by sending each
  signal `os.constants.signals` names to a Node process with no listener and to one with a
  listener, with Node 26.5.0 and 20.20.2 on macOS 27.0, 2026-09-27. Twelve names ended a
  listener-less process and ran a listener: `SIGHUP`, `SIGINT`, `SIGQUIT`, `SIGTRAP`, `SIGABRT`
  (and its alias `SIGIOT`), `SIGUSR2`, `SIGALRM`, `SIGTERM`, `SIGXCPU`, `SIGVTALRM`, `SIGPROF` and
  `SIGSYS`. `SIGSEGV`, `SIGBUS`, `SIGFPE` and `SIGILL` also end it, and Node's documentation rules
  them out. `SIGPIPE`, `SIGXFSZ`, `SIGUSR1`, `SIGCHLD`, `SIGCONT`, `SIGURG`, `SIGWINCH`, `SIGIO`
  and `SIGINFO` did not end it, and `SIGTSTP`, `SIGTTIN` and `SIGTTOU` stopped it.
  `test/exit-cleanup.test.mjs` asks the same questions on every run.
- **`SIGPROF` is not safe to take.** Under `--cpu-prof`, a Node process with a `SIGPROF` listener
  was ended by `SIGPROF` in 5 of 5 runs on Node 26.5.0 and 1 of 1 on 20.20.2. The same process
  without the listener exited 0. So the rule "Node lets a listener handle it safely" leaves it out,
  though a listener does run when it is sent by `kill`.
- **The card's six named signals are not the whole set.** The rule in `ARCHITECTURE.md`'s Failure
  model also takes in `SIGTRAP`, `SIGABRT`, `SIGXCPU`, `SIGVTALRM` and `SIGSYS`. Each has a test of
  its own, beside the six.
- **Node reaps no child while synchronous code runs.** So a leader the cleanup kills stays in its
  group as a zombie until the process exits, and `kill(-group, 0)` keeps answering. The cleanup
  therefore confirms a kill by reading the group's states until every member is a zombie.
- **`SIGTERM` ends a stopped process on this host.** A `tail` stopped with `SIGSTOP` and then sent
  `SIGTERM` was gone at once, with status 143 (macOS 27.0, 2026-09-27). So a test of a stopped
  group proves the `SIGKILL` only where the group's processes ignore `SIGTERM`, and the fixtures'
  children now do.

## What failed

- **Three tests passed without what they prove, until guarded mutations showed it.**
  - The census stand-in marked its first read with a file named after the stand-in itself. That
    file always existed, so the read never hung, and no census read was in flight when the caller
    ended.
  - `SIGTERM` in place of `SIGKILL` passed, for the reason above.
  - The caller's own `SIGTERM` listener reported in the same turn in which the cleanup ran. So the
    test read the groups before the cleanup had killed them, and removing the guard for another
    listener passed.
- **The first guard for a caller's own signal listener was unsound** (the engineer judge's N1 to N3
  on #366). It left the signal to any other listener, counted when its own listener ran. There
  were three faults:
  - A `once` listener has already been taken off by then, so the cleanup ended a caller its own
    listener was keeping alive.
  - A listener that removes every listener and raises the signal again ended the caller with
    nothing killed.
  - A listener that raises the signal only when it is the last one left, as `signal-exit` does,
    deferred to the cleanup's listener, which deferred back to it, so the caller ignored the
    signal.

  The cleanup now always runs first, and then takes its listener off the signal. The other
  listeners then find only each other, as they would have without it.
- **The confirmation of the exit kill went untested until the engineer judge's M13.** Every
  tested group was stopped by the census, so one kill ended it. A test now puts a process into
  the group after the kill, holding the confirmation's read of the process table until it has
  joined.
- **The first draft named no environment at its `ps` calls.** `test/git-environment.test.mjs`
  requires every spawn of a command chosen at run time to name its environment in the call. So
  both reads now pass `env` at the call.
