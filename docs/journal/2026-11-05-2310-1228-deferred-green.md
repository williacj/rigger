# Card 1228: a deferred run ends green

The acceptance is [card 1228](https://github.com/williacj/rigger/issues/1228). The merge
stays blocked with no refusal in the aggregate, because a deferred run's job carries a name no
rule requires: `check (26)` is simply absent at that head, and `readCheckStates` answers
`absent`. So `guard` now admits `BROAD_DEFERRED` under the same result rules as the skipped-tier
modes, and the display name holds the property the old refusal held.

Three things moved with it. The name expression now also keeps a pull request run against another
base away from `check (26)`, whatever `plan` answered. `policy` answers `INVALID` for a base
differing from `main` only in letter case, so nothing rests on how a workflow expression compares
case. `cancel_superseded` logs `cancelled-nothing` and returns on a second count/list disagreement
([M7-U39](https://github.com/williacj/rigger/issues/1009#issuecomment-6671595720)), which changes
#1156's owner policy.

The new log line goes through `log`, not `diagnostic`, so the exact diagnostics the two existing
disagreement tests assert stay as they were, and the sample's L558 needed no grant.

- A pull request retargeted away from `main` and back at one head. A `check (26)` earned while it
  targeted `main` stays at that head, as at the merge base. This work does not touch it.
