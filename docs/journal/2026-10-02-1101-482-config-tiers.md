# #482 — the role refusals, and where each fact is held

**The tier set lives in the config core, the provider names in L0's map.** `O4` has Rigger fix
the tiers, so `TIERS` sits beside `CATEGORIES` in `src/config/validate.mjs`, which already holds
what is Rigger's and not the consumer's. The provider names stay the adapter map's: the validator
imports `ADAPTERS` and asks `Object.hasOwn` of it (ruling 3 P11), and a test reads the validator's
source for a quoted provider name. A provider that is no string is refused before the map is
asked, because `Object.hasOwn(ADAPTERS, ['claude'])` coerces the list to `'claude'` and answers
true.

**The owner named twice keeps its one refusal.** The existing test "a kind naming the owner
anywhere but last" expects exactly one refusal for `['owner', 'owner']`. A judge's directory is
the reason a judge named twice is refused (ruling 1 Q3), and the owner is never dispatched, so the
duplicate rule reads agent judges only. The owner twice is still refused, by the owner's position
rule, which names the kind and `owner`. No existing test line changed.

**The step's timeout check became a shared reader.** A role's `timeout` is read "as it refuses a
step's", so the step's check moved into `readTimeout` and both call it, with the step's message
unchanged.

**A role's `labels` is read as a plain object, every enumerable own key of it.** Codex's round 1 found
`new Map([['tier:high', 7]])` accepted: `Object.entries` shows a Map nothing, so a check written
over it passes anything it cannot see. The validator now requires `Object.prototype` as the
prototype, no enumerable symbol key, and a data value on every enumerable key, so a Map, a class
instance, a null-prototype object, and an inherited, computed or enumerable symbol-keyed entry are
each refused. The first
version read `Reflect.ownKeys`, which the layer-boundary test refuses under its code-generation
rule; a key that is not enumerable is left unread, as the engine leaves it. Codex's round 2 found
such a key accepted and ignored, and ruling 16 on #467 holds that it is no declaration, which the
validator neither reads nor refuses; the card now says so, and the code beside the check records it.
Codex's round 3 found the symbol check still refusing a non-enumerable symbol key, so it now
refuses only an enumerable one, read from each symbol's own descriptor.

**The four hours have one home.** `roleTimeout` answers `role.timeout ?? 14_400_000`, beside
`stepTimeout` (ruling 3 P10). Nothing reads it yet; #481 (`roleDispatch`) is its first reader.
