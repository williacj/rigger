# #555 — a scratch directory for each role's dispatch

**A worktree at the scratch path is found by git first, and by a `.git` second.** The first
version had no repository in `roleDispatch`, so it only walked for a `.git`. Codex found that a
registered worktree whose `.git` was moved aside passed that walk, and was removed with its
uncommitted work. Under ruling 21, L1's makes answer the repository as plain data. L3 hands it on,
and L1 asks git which worktrees are registered before it removes anything. The `.git` walk stays,
for a checkout of another repository. A worktree of another repository with its `.git` moved aside
is found by neither, which the code records under `D16` rule 3. Codex's next round found the
other direction: a scratch path that lies inside a registered worktree, the main one included. So
the same listing now also refuses that, before L1 makes anything, reading the nearest existing
parent where the path is not there yet. Codex's third round found a scratch base inside a linked
worktree of an unrelated repository, which this repository's git does not list, so L1 also walks
the ancestors from the scratch base up to the worktree root for any `.git`. It stops at the root,
because above it lies the operator's layout, and a home directory kept in git would otherwise
refuse every dispatch.

**A directory the check cannot read is refused, never made readable.** The first version made
an unreadable directory owner-readable so that the walk could go on. That left a refused worktree
altered, and the engineer judge ruled it out. The walk now reads names in order, and refuses at the
first directory it cannot read, because it cannot show that no `.git` lies inside. So an agent
that leaves an unreadable directory in its scratch directory stops that role's next dispatch until
someone removes it. That is the fail-safe direction.

**The grant table missed three lines, and running the files found them, not reading them.** They
were a direct `roleDispatch` call, a whole-stream event assertion, and the
boundary test's stand-in for `workspace.mjs`. Each turned up only as a red when the file ran. The
coordinator granted each under O79.
