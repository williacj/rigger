# #555 — a scratch directory for each role's dispatch

**`roleDispatch` cannot ask git which worktrees are registered, so it refuses any `.git` it finds.**
`loop` takes no new handle (ruling 19), and L3 holds no repository. So the check before L1 removes
an old `<scratch>/<role>` walks it without following a link and refuses on any `.git`, a file or a
directory. That covers a worktree registered there or inside it, and also any other checkout. A
registration whose directory is gone is not refused, because there is nothing at the path to
remove.

**The check runs before anything is changed, so one directory mode can still change on a refusal.**
A directory inside `<scratch>/<role>` that L1 cannot read is made owner-readable before the walk
reads it, as `writable` already does before a removal. The refusal tests hold a readable tree, so
they show nothing changed. A refusal of a tree holding such a directory may leave that one mode
changed.

**The grant table missed three lines, and running the files found them, not reading them.** They
were a direct `roleDispatch` call, a whole-stream event assertion, and the
boundary test's stand-in for `workspace.mjs`. Each turned up only as a red when the file ran. The
coordinator granted each under O79.
