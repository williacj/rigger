# #450 — replace only the card's own worktree, and ask for the literal name

**Git expands only previous-checkout syntax here.** Measured with git 2.54.0 (Apple Git-157), run
in a repository whose previous checkout was `owner-feature`, `git check-ref-format --branch`
printed `owner-feature` for `@{-1}` and exited 0. It refused `@{-3}` with exit 128, and printed
`rigger-1` for `rigger-1`. It printed `@` unchanged for `@`, in a repository, in a detached `HEAD`
and outside every repository, and `git worktree add -B @` then made `refs/heads/@`. So on this git,
`@` is a literal branch name. L0 compares git's printed name with the name asked, as ruling 9 has
it. It therefore refuses `@{-1}` and accepts `@`.

**The acceptance names `@` as an instance git prints back changed.** On git 2.54.0 it is not one.
The test for that item asks git about each name, including `@`. It asserts that L0 refuses every
name git changed and accepts every name git kept, which holds `@` to the rule as git measures it.
Refusing `@` would copy a rule of git's into Rigger, which `D16` rule 2 bars without a test tying
it to git. The PR escalates that item as `ambiguous`.

**The lock text.** A smudge filter ran while `git worktree add` checked out the new worktree's
files. It read `.git/worktrees/<name>/locked` as the 13 bytes `initializing\n`, and `git worktree
list --porcelain` printed `locked initializing`. Both held under `en_US.UTF-8` and under
`de_DE.UTF-8`. That build printed its own errors in English under `de_DE` too, so a translating git
is unmeasured. A test has the same kind of filter list the worktree mid-add, and compares the lock
git lists with L0's `ADDING`.
`git worktree unlock` accepted the path of a registration whose directory was gone, exited 0, and
the prune in `make` then forgot the registration.

**The order in L1.** L1 asks git about the attempt's own name, then clears the path, and only then
makes the workspace. Clearing a present path runs four checks, each ending the attempt before any
write:

- whether it is a linked worktree of the repository (`isWorktree`);
- whether its real path is the top level git reports for the handed path (`topLevel`);
- whether git lists the card's branch checked out there (`registration`);
- only then, `u+w` and the removal.

With nothing at the path, a registration git still lists there is unlocked only where it is on the
card's branch and carries git's own lock reason.

**A refused event is the halt.** L1 used to fold a refused `workspace.made` or `workspace.removed`
into `WORKSPACE_NOT_MADE`, which L2 retries. L1 now records both outside the part it treats as a
workspace failure. A refusal there rejects with `EVENT_REFUSED`, which L2's `unmade` already
answers with no action. So the halt #434 built reaches it with no change under `src/workflow/` or
`src/scheduling/`.

**Grant-bound imports.** The grant lists the existing lines this card may change, and no import
line is among them. So each new name is imported on a line of its own beside the existing import
lines.
