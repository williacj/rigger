# 2026-09-25 — `run` claims until the slots are full and says it worked nothing

`rigger run` is `once` with no claim limit. The verb hands `claimOnly` no limit, so L3 claims as
many cards as N allows, first pulled first, and stops when the slots are full or nothing is left
to pull. The verb names no N: rule 4 of the boundary test bars `src/cli/` from reading
`concurrency`, and L3 reads it from the config it is handed. That is the whole of what
separates the two verbs, along with the verb's name in each line it prints.

**One body, shared.** This card was built beside #232, and each verb landed with the same forty
lines. Once #232 merged, the body moved into one exported `claimVerb(verb, limit, options)` in
`once.mjs`, with `once` a one-line call at limit 1 and `run` a one-line call at none. It lives in
`once.mjs` rather than a module of its own because that is the shape the directory already has:
`plan` imports its guard from `doctor.mjs`, and `once` imports `refusalLine` from `plan.mjs` and
`STATE` from `report.mjs`. `once`'s behaviour is unchanged, and its fifteen tests are the guard
on that.

**A redo is claimed where it stands.** The PM revised the acceptance on 2026-09-25 for this: a
Coding card and a Review card that L2 would dispatch are both claimed, each with a pull event, no
move and no L2 transition. `claimOnly`'s shared `start` step already skips L2's move for a redo,
so the three redo tests passed as written, and so did the two second-run tests: a second `run`
over the board the first left claims the Coding cards again and writes no transition for them.
The tests run the real bin twice over one fake `gh`, which replays its write record between runs,
so the second run reads the board as the first left it.

**The claim cap, derived from events.** L3's `pull` and `slot.release` events, replayed in
order, never hold more slots than N: 3 under `concurrency: 3` and 1 under `concurrency: 1`,
over four pullable cards. A mutation that lets L3 claim one more than N reddens this test along
with the claim-count tests, so the derivation is not a restatement of the count.

**Failure output is outside this card.** A board read that fails, or a claim move the board
refuses, escapes `claimVerb` as a rejection, and `rigger.mjs` prints a stack trace. `plan` prints
one line in that case. No acceptance item on #232 or #233 covers it, so it is named in the pull
request rather than absorbed.
