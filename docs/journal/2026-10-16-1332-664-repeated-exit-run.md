**The protocol kept the forge's pace out of the evidence.**
- The stand-in maker waited for its pushed head to show.
- Each board add waited for its item to list.
- Each step waited for a `rigger/gate` status on its head before the card's next event.
- With Test quality holding its campaigns (P60), every engine invocation started at a one-minute
  load of 24 or less. The gate queue answered within about five minutes each time.

**One wait I planned could not happen.** My pre-run comment listed a final wait for a gate status
on E3 after the escalating run. That escalation records an event but makes no fixture event, so no
gate run follows and no status can come. I stopped my own wait. A wait needs an event that produces
its status, and a pre-run plan should name only those.

**Re-pinning a forked gate takes a card of its own.** `init` writes nothing over an existing file.
So the pin card removed the workflow with `git rm` first, and merged under the old pin's gate with
markers posted by hand.
