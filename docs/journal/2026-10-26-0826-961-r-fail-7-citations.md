# Card 961: `## Failure model` cites `R-FAIL-7`, and places a judge's scratch directory not made

[#932](https://github.com/williacj/rigger/pull/932) retired `R-FAIL-6` for `R-FAIL-7`, whose table
adds one out row: a judge's scratch directory not made because the file system gave no answer.
[U44](https://github.com/williacj/rigger/issues/740#issuecomment-6377288414) filed this card to
follow it into `ARCHITECTURE.md`. The ten citations of `R-FAIL-6` each rest on rows `R-FAIL-7`
holds unchanged, so each retarget changes only the id.

[The #920 attack's finding 6](https://github.com/williacj/rigger/issues/920#issuecomment-6377073780)
ruled that the added row also needs structure. The delta widens the `environment` bullet to the
withheld judge whose scratch directory was not made, and names the hand-off in step 4 of the
attempt order. L1 makes that directory inside the judge's dispatch, after the judge's directory
and its `head` steps, and a failure there is a command that did not start.

[This card's attack](https://github.com/williacj/rigger/issues/961#issuecomment-6416981742) ruled
that the hand-off fits boundary rule 2's existing vocabulary, "that a command never started". The
code agrees: `roleDispatch` in `src/execution/role.mjs` throws its not-started error for a judge's
unanswered scratch make. So nothing outside `## Failure model` changes, and nothing was escalated.

The same attack found that the retry sentence sent every environment failure but one to a second
attempt and a hold, a withheld judge included. The delta lists the withheld judge as a second
exception, cites `R-FAIL-7`'s rows for its outcome, and restates none of their Scope cells.

[K51](https://github.com/williacj/rigger/issues/740#issuecomment-6341789050) keeps a scratch
directory refused under `R-WORK-26` apart from a host failure. The existing sentence that makes
every such refusal an escalation already covers a judge's, so the delta leaves it as it stands.

What taught us: a retry rule written as "every X, except Y" goes stale each time X widens. Each
widening of the `environment` class needs its exceptions read again.
