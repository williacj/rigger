original commits for #697, #807, #788, #783, #813, #881, #891 and #901. Their prerequisite
ancestry includes #762, #766, #767, #879 and #873. The merge was automatic, including the

Any later overlapping source change invalidates this candidate and requires refreshed input
records before measurement. Superseded candidates supply no performance evidence.

Before measurement, record the actual resulting commit and tree, unchanged working status,
runtime and host, tier commands, observer route and distinct attempt identifiers. Install the
locked dependencies normally in this worktree. The normal commit hook must verify the
unchanged integration before either measured tier starts. No failed, incomplete or cancelled
attempt is silently replaced or counted as a saving.

The proposed observer uses Python's existing time.monotonic_ns around the actual child
command, recording that child's pid at start and retaining stdout and stderr separately.

time.get_clock_info('monotonic'), reports Python 3.14.4 and a non-adjustable monotonic
clock_gettime(CLOCK_MONOTONIC) implementation. Record that preflight again with each attempt;
wall-clock timestamps label observations rather than determining elapsed duration.
Use the unchanged npm test and npm run test:host routes. The host route remains serial
as test/suite.sh defines it. Use the established Linux Node runtime and record its actual
version and environment for each attempt.

Report ordinary and host root elapsed time separately. Existing runner-reported test
durations are observations of their named tests, not interchangeable with file wall time or
root elapsed. Do not sum nested durations into a critical path or invent absent file timing.
If the existing output cannot identify dominant work directly, return the exact limitation
and a bounded observation proposal before introducing another reporter.

No performance edit, target saving, host-stall diagnosis or merge authorization is supplied
by this journal. #778 remains open until the PM authors and independently reviews a measured
implementation scope, or the owner explicitly accepts a measured no-change disposition.
Queue cancellation is separate resource scheduling and earns no suite-speed credit.
This proposed integration does not ratify authored instruction or protected-policy changes;
their required owner approval and actual merge gates remain in force.
