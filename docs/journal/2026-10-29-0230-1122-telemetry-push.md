# Pushing the stream at a verb's return

Card #1122 (M7-31) wires L5's push. It is built to placement A, so `src/cli/verbs.mjs` hands each
verb `pushAtReturn()` from `src/observation/push.mjs`, and `recording(work, push)` calls it. That
call comes only after `work` returns normally, having named a repository with `name` and a config
with `admitted`. `scripts/gate-check.mjs` hands `recording` no push, so `node
.github/scripts/gate-closure.mjs` lists the same 29 files at the head as at `0a04fab8`.

## Where each verb is proved

- **`doctor`, `plan`, `once` and `run`** run in process in `test/telemetry-push.test.mjs`. They
  get a stand-in for the guard's `git`, which also records one event of the run's own, since
  `asked` records none.
- **`once` and `run` in process** reach a normal return only by refusing a worktree root inside
  the tree. The workspace handle they build next spawns `git` through L0's process adapter, which
  the deterministic tier refuses. I measured this on 2026-10-29: `run` answered "deterministic
  tier: … cannot signal" before any board read.
- **`setup-board` and `verdict`** take no stand-in for the guard or the forge, so they run as the
  bin in `test/setup-board.test.mjs` and `test/verdict-world.test.mjs`, which are on the
  `converting_tests` list. `run`'s drain (C9) runs as the bin in `test/run.test.mjs`.
- **"No push" on the bin** is observed through `GIT_TRACE`: no traced `git` command names
  `refs/rigger/events` or `rigger-data-push`.

## A signal in the test worker

The first form of the C10 test sent `SIGUSR2` to the test worker. Here that wrote a Node
diagnostic report, `report.<date>.<time>.<pid>.0.001.json`, into the worktree on each run.
`process.report.signal` is `SIGUSR2` on Node 26.5.0, so some part of the run turned reports on.
The test now uses `SIGHUP`, and no report is written.

## Cases met under C12 and O12

- **A stream that exists but cannot be read** (C12). L5 cannot show that it holds a line of this
  run, so there is no push and no `push.end`.
- **A push side that rejects with something other than `EVENT_REFUSED`** (O12). It is recorded as
  `failed`, with the rejection's message as `reason`, and the verb's answer is unchanged. L0's
  `pushStream` catches every other failure itself, so only a stand-in side reaches this.
- **`init`.** It names its target as the state directory's repository, but it names no config, so
  it never pushes (reading 2).
- **`doctor`.** It names its config straight after its guard, before its checks, so a `doctor`
  that stops on a refused kill event also returns normally and pushes.
