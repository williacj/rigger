# 2026-09-26 — `Owner` on board 6, and every column kept

This was the first time `setup-board` wrote to a real board. The engine was a tarball `npm pack`
made in a fresh clone of `main` at `b6a4ab3`, installed in a scratch directory outside the
checkout. It ran in a second fresh clone at the same SHA. Before anything touched board 6, the same
tarball ran twice in that clone against the fake `gh`, which held the `Status` options, fields,
labels and 80 items `gh` had just read from board 6. It predicted one write, the `Owner` column,
and none on the rerun. The before-comment on #235 posted that prediction, with every item's column
and option id.

The real run matched the rehearsal. It reported one write, `added the column Owner`, and the
rerun reported none. Afterwards every one of the 80 items held the same `Status` option id as
before, in both the GraphQL read and `item-list`. The eight existing options kept their ids,
positions and colours, and `Owner` was appended as GRAY. The labels and the other fields were
unchanged.

That settles the question #212's report left open. Way B keeps the columns of items that are
issues, not only of draft issues.
