# Who authors a clock-created card's acceptance

`R-CARD-3` named two authors, the owner and the decomposing role. A card Rigger opens from a clock
trigger has neither. [M7-U3](https://github.com/williacj/rigger/issues/1009#issuecomment-6440291524)
item 1 ruled that the trigger's configuration names the author, the owner by default, and that the
row replacing `R-CARD-3` takes a new id. Adding a third author changes what must be true, so under
the requirements preamble `R-CARD-3` is withdrawn and `R-CARD-41` replaces it. The two ids come
from [M7-K6](https://github.com/williacj/rigger/issues/1009#issuecomment-6440729098) item 1, which
gives #1020 `R-SCHED-28` to `R-SCHED-41` and this card `R-SCHED-42`, so the siblings cannot collide.

The new rows claim no test of their own. Under M7-U3 item 2, M7-22a's test claims `R-CARD-41` and
M7-20's claims `R-SCHED-42`, so the matrix marks both a gap until those cards land.

`R-CARD-41`'s `checked by` is the test suite, not `R-CARD-3`'s "the event record, by who first set
it". For a card Rigger opens from a template, Rigger is the first setter in the record, so that
derivation could not tell the configured author from any other. A change to `checked by` never
takes a new id, and it moves no requirement in or out of the counted gaps.

The citation retargeting follows [U71](https://github.com/williacj/rigger/issues/740#issuecomment-6417450089),
as #964 applied it: every file citing the withdrawn id outside the journal and the generated
matrix now cites its replacement, and each such line changes only the id. That covers three lines
of `docs/spec/decisions.md`, in `D18` and `D20`, and line 23 of both `pm.md` prompts. Outline r3's
M7-05b row, "decisions (an id only)", which M7-U3 item 4 ratified, is the authority for touching
`D18` and `D20` this way, so neither status line nor index row changes.

`D20`'s Notes line, once retargeted, reads "This choice uses the identities `R-CARD-41` and
`R-CARD-6` already require", citing a row that postdates `D20`. The meaning holds, because
`R-CARD-41` keeps `R-CARD-3`'s two identities, the owner for a card the owner files and the
decomposing role for a card it produced, and adds only the clock trigger's case. The line is an id retarget, not a rewrite of
`D20`'s reasoning.
