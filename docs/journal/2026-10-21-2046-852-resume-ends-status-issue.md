# `rigger resume`'s label removal ends the status issue

U25 answered the architect's escalation on PR #847. `rigger resume` and the owner close the
status issue through one account, so the forge cannot tell whose close it was. The owner chose
that an issue whose status label `rigger resume` removed is no longer the status issue.

The dispatch asked for an in-place amendment of `R-SCHED-21`. The reviewer's pre-dispatch attack
on #852 (B1) found that the preamble's id test answers the other way, and the PM agrees. Take an
open issue whose label `resume` removed before it was interrupted, with admission still closed.
Under `R-SCHED-21` and `R-SCHED-23`, a person's close of that issue reopens admission. Under the
amended text it reopens nothing. That changes what must be true, so the row takes `R-SCHED-27`
and `R-SCHED-21` moves to the retired register.

The text changes by three words. `### R-SCHED-23` names no row for the state above, and this
card leaves the table alone, because widening it would change `R-SCHED-23`'s scope beyond U25.
The pull request names the state for the owner.

`R-SCHED-21` was a gap at the base, and `R-SCHED-27` is a gap at the head. #747's pull request
named M6-05 as the card whose test claims the row; it is not yet filed.
