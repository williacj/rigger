# #356 — the census of a dispatch's directory

**`lsof` decides the working directory, and it prints some paths in a form the census cannot
read back.** It prints a newline as `\n`, a backslash as `\\`, U+0001 as `^A` (which the literal
text `^A` also prints as), and U+200B as `\x` escapes, while it prints `ü` as itself. So a
directory whose real path holds anything but printable ASCII other than `\` and `^` is refused:
a dispatch there does not start. Comparing it as printed could match another directory, or match
nothing and leave every process alive. A path of printable ASCII prints as itself, and a path
printed under it lies under it. The cost is that a worktree root with non-ASCII in its path cannot
take a dispatch. Refusing was chosen over guessing which characters `lsof` prints as themselves.

**Stopping before killing carries over from the group's census.** A process `lsof` listed can
exit, and its pid can go to another process, before the kill lands. So the census stops each
process it listed, lists them again while they are stopped, and resumes any that no longer work
there. It then names the rest and kills them. It finishes at the first list that holds no process,
so a process forked between a list and the stop is caught in a later round.

**A dispatch's directory is held while its entry is in the record.** The check for a second
dispatch in the same directory reads the record. The record holds the running dispatch's
directory from the step that spawned its command, and nothing between the check and that write
awaits. The check also refuses a directory under or over a held one. The card asks only for "the
same directory", but the census of the outer directory would end the inner dispatch's processes.

**The engine's own reads run in `/`.** `lsof` lists itself, and the census excludes Rigger's own
pid, so neither `lsof` nor `ps` can be listed as working in a dispatch's directory.
