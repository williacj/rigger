# #356 — the census of a dispatch's directory

**`lsof` decides the working directory, and it prints some paths in a form the census cannot
read back.** It prints a newline as `\n`, a backslash as `\\`, U+0001 as `^A` (which the literal
text `^A` also prints as), and U+200B as `\x` escapes, while it prints `ü` as itself. So a
directory whose real path holds anything but printable ASCII other than `\` and `^` is refused:
a dispatch there does not start. Comparing it as printed could match another directory, or match
nothing and leave every process alive. A path of printable ASCII prints as itself, and a path
printed under it lies under it. The cost is that a worktree root with non-ASCII in its path cannot
take a dispatch. Refusing was chosen over guessing which characters `lsof` prints as themselves.

**Stopping before killing carries over from the group's census.** A process `lsof` listed can
exit, and its pid can go to another process, before the kill lands. So the census stops each
process it listed, lists them again while they are stopped, and resumes any that no longer work
there. It then names the rest and kills them. It finishes only at a list holding no process it may
signal, so a process forked between a list and the stop is caught in a later round.

**Revision 1: a round that could stop nothing is not the end.** The first version also finished on
a round in which every listed process had gone before its stop. The engineer judge showed the cost
(PR #506, B1): a listed process that forks a successor in the directory and exits before the stop
left the successor alive and unrecorded, 3 runs in 3, and a chain of such hops outlived the settle
with no stand-in at all. Now a process gone before its stop sends the census round again, and only
one Rigger may not signal (`EPERM`) is passed over. A chain hopping faster than a round holds the
census to its read timeout, and it is then recorded as unread rather than passed over silently.
A census that gives up before listing a stopped process again resumes it, so a failed read leaves
nothing stopped.

**A dispatch's directory is held while its entry is in the record.** The check for a second
dispatch in the same directory reads the record. The record holds the running dispatch's
directory from the step that spawned its command, and nothing between the check and that write
awaits. The check also refuses a directory under or over a held one. The card asks only for "the
same directory", but the census of the outer directory would end the inner dispatch's processes.

**The engine's own reads run in `/`.** `lsof` lists itself, and the census excludes Rigger's own
pid, so neither `lsof` nor `ps` can be listed as working in a dispatch's directory.

**Revision 2: a restart sweeps a directory only where it is still the one recorded.** Codex
returned a coverage gap (`R-LOOP-6`): a restart swept whatever directory the record named, and
nobody watches that path between an engine's death and its restart. Ruling 7 and O36 settled it.
L1 now records the device and inode of the directory's real path alongside the path. A restart
sweeps the directory only where `stat` of that path gives back the same device and inode. Where it
does not, or the entry has no identity, or the path cannot be read, the restart records
`directory.skipped` and goes on, and the group is handled as before. The live census takes no such
check, because Rigger has watched its directory throughout. A command that removes and remakes its
own workspace still has the process it left there ended.

The identity check rests on one measurement. On this host's APFS volume, none of 200 directories
removed and made again at the same path got its old inode back. That APFS's inode counter only
grows is ruling 7's judgment, not a measurement.
