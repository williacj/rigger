# #599 — the last read that answered decides

**Why.** #586 recorded a member as not shown to have ended only where every read after the kill
failed. All three of #589's judges found the case beside it: one read after the kill lists the
member alive, and every later read fails. `ended` then settled with no member stuck, and
`reachedUnread` added nothing because one read had succeeded, so the member the kill left alive
was recorded as `survivor.killed` or `recorded.killed`.

**What changed.** `ended` now remembers which members the last successful read found alive, and
why a read after it failed. Where the last read failed and an earlier one succeeded, it hands both
back as `unconfirmed`. `reachedUnread` takes the named members that read found alive, where signal
0 still reaches them, and records each as not shown to have ended: `EPERM` where L0 may not signal
it, and otherwise a reason saying the last read that answered showed it alive and later reads
failed. A member that read showed a zombie, or did not list, is still recorded as killed.

**How it was shown.** A `ps` stand-in answers the group's states reads after the kill until one
lists the member as the test asks, alive or a zombie, copies that read to `answered`, and fails
every read after it. No load or timing forces the case. With the head's tests over `c1ac6ef`'s
`src/`, the four alive cases failed on `*.killed` where `*.unended` was expected, and the two zombie
cases passed.

**The first commit.** The card asked for a tests-only first commit that fails. The pre-commit hook
refuses a red suite and `--no-verify` is barred, so the coordinator ruled that the red run of the
head's tests over the base's `src/` is the evidence, and tests and fix land together.

**What is left.** The exit cleanup keeps its own path (#567). A member shown alive whose pid was
given to another process before the record is recorded as not shown to have ended; no read after
the failures could tell, and the code says so under `D16` rule 3.
