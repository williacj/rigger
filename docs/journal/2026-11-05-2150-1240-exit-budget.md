# Exit cleanup takes a fixed budget

launchd sent SIGKILL 60.01 s after `bootout` with `ExitTimeOut` 150 in the plist (1240#6676127384),
so the 135 s the config-scaled bound asked for could not be met. Cleanup now reads the host clock
before each group: careful to `EXIT_CARE_BOUND`, a bare group kill after it.

Measured with the stand-in host in `test/exit-cleanup.test.mjs`, row X11, at the commit carrying
this entry: the longest single dispatch took 37,266 ms, at reads answering half their timeout, with
the member and both survivors outliving the kill and the read before the kill listing nothing. At
reads one millisecond short of their timeout it took 20,000 ms, because the census then fails early
and skips the read before the kill. So the slowest speed is not the longest cleanup.

Cases met under row X10:

- **The clock reads exactly `EXIT_CARE_BOUND`.** The budget is spent, so the group has the bare kill.
- **The budget's start.** It is the first call the cleanup reaches, by that call's host clock, and
  each later group is compared by its own call's clock. One process holds one clock in production.
- **A group already empty past the budget.** Signal 0 finds nothing, so no kill is sent or recorded.
  Its directories went unsearched, so the entry stays, and the end carries the command's own exit.
- **A group its call had already emptied and swept, past the budget.** It takes the path it took
  before: no kill, and its entry goes, because nothing is left unswept.
- **A cleanup that runs again.** A process a listener keeps running gets a fresh budget at its next
  ending, because each run reaches only the calls then in flight.
- **A process kept running past a bare kill.** L1 has recorded the end and records nothing more, and
  the entry stays until the next start, even where the call's own sweep then finishes.
- **`ps` hung while `lsof` answers.** A listing that answers clears `unreadSince`, so each later
  group waits out `UNREAPED_BOUND` again, about 1 s. The hung read itself is still paid once, and the
  budget caps the rest.

The stand-in's clock stood still on a read L0 refuses at once, and `emptied` retries on the clock's
word, so a first draft of the X4 test spun for ever inside the signal handler. A real clock moves,
so this was the fixture's fault. A test's child that handles SIGTERM needs `killSignal: 'SIGKILL'`.

Round 1's judges ruled that a test declares what its removal shows, and each budget test has a
mutation behind its tag. X2 proves `R-STATE-9` and `R-STATE-17`, the paid-once X4 `R-STATE-12` and
`R-STATE-19`, and X11 `R-STATE-19`, because each still passes with the post-budget branch removed.
X1 declares nothing: no row of `docs/spec/requirements.md` says a sink ends with no group held.

What cleanup decides is also proved in this process, in `test/exit-budget.test.mjs`, from the same
world and assertions, under `D29` rule 2.2. That test takes `cleanup` off the `exit` event, because
emitting `exit` would reach the test runner's own listeners.

Rounds 2 and 3 of judging found promises of directory cleanup still unqualified, and the card pinned
each. A documents-only commit still stales proof step 2, because the proof names the head. So proof
results live in the pull request, and this entry is written before the load it would otherwise
report, since a later commit here would move the head that load ran.

`never-stop`'s nested identity test failed while verifying round 3: a process just past SIGKILL read
`(node)` with state `live`. It failed 3 of 60 at `55cc43f3` without this card, so it was no fault of
this work, and #1259 owns it.
