# The admission module

[#869](https://github.com/williacj/rigger/issues/869) lands `src/scheduling/admission.mjs`, the one
module over `.rigger/admission/`, with no caller yet. The card's Terms and its Tables A and B fixed
the behaviour. These are the choices it left to the maker.

## Choices

- **`read` is synchronous and the writes answer promises.** `ARCHITECTURE.md` has `take` list the
  directory inside its synchronous claim, so a read that awaited could not sit there. The writes
  are steps a verb awaits, and the card states them as resolving or rejecting.
- **A read answers a value, never a failure.** It answers `open`, `closed` with every closer, or
  `unreadable` with every entry it could not read, each with its path and cause. A caller cannot
  mistake a thrown read for an open one.
- **One id per close names both its temporary file and its closer.** The temporary file is
  `.tmp-<id>` and the closer `owner-<id>.json` or `hold-<id>.json`. The id source is injectable,
  and an id outside the Terms' form is refused before anything is written.
- **The temporary file is created with `O_CREAT | O_EXCL`.** A leftover of the same name therefore
  fails the create with `EEXIST`, and the leftover is never opened or written.
- **The read relists without a bound.** A closer listed and then gone sends it back to list. Only
  another process changing the directory between two listings repeats it, so the loop has no
  bound. This is a judgment, not a measurement.
- **Events.** A close records `admission.close`, naming its kind, id, name and reason, and the
  leftover temporary file where there is one. An opening records `admission.open` with
  `by: 'opening'`, and each closer `resume` removes records `admission.open` with `by: 'resume'`.
  A refused event fails the call, naming the event. The write it records stands, and a `resume`
  stops at the first refusal, which leaves the rest closed, the safe direction.

## How the tests went red

The read tests ran first against a stub module that answered nothing, and failed on its missing
answers. The module was then written whole, so the write and event tests did not each come one
step ahead of their code. To get a real red for them, the writes were stubbed to reject and the
event record emptied, and each file was run against that stub before the module was restored.
Two guarded mutations were also run:

- skipping a vanished name rather than relisting reds the two relisting tests;
- recording a close's event before its write reds four event tests.

The PR quotes both runs.
