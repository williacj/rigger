# The escalation role runs under the maker's claim

Card [#1007](https://github.com/williacj/rigger/issues/1007), acceptance revision
`f2927145732b`, defines done through Tables A and S and its acceptance. This work implements
that dispatch in the judges' place. L2 posts the routing comment before L1 makes the detached
escalation directory and the role's scratch directory. L3 retains the claim while L2 settles
the role, and retries only that role when its command never started.

The instruction holds the card's acceptance and the maker's reason, without judge evidence.
Its note form precedes user text so a title or reason containing the dispatch-slot spelling
cannot consume the role's dispatch id. A role's note, unsuccessful exit or second failed start
returns through the owner escalation path. An answered directory refusal uses that same
card-local path without a retry. The two failed starts need not have the same cause.

The detached-directory make shares the existing judge replacement checks. Escalations may
have main alone, or main and an open pull's head. An unanswered escalation make is reported as
NOT_STARTED, naming the missing directory, as the architect's [finding 6 ruling](https://github.com/williacj/rigger/issues/1007#issuecomment-6432536776)
requires. The role runner remains unchanged.

The pre-code binding search found the explicit workspace export mock in
`test/worktrees.test.mjs`. [G2](https://github.com/williacj/rigger/issues/1007#issuecomment-6434123747)
permits its new export stubs and clarified that there was one attack. G1 permits the interim
routing test's retarget. [K97](https://github.com/williacj/rigger/issues/740#issuecomment-6431286463)
permits the new host-list entries. No other existing test line is changed. The test matrix is
regenerated.
