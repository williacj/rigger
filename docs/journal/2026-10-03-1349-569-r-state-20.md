# #569 — a process no read can show

**Every row that promised a record of forced ends was too strong by one window.** #553's engineer
judge found it. A process joins a group after L0's last read before a kill, the kill ends it, and a
parent outside the group reaps it at once. Nothing ever lists it, so nothing can record it. The
base code already said so under `D16` rule 3, but `R-STATE-12`, `R-STATE-13` and `R-STATE-19` did
not. A requirement that the code cannot meet, and that no test could catch it failing, is a defect
in the register, not in the code.

**The fix is a row that names the window, not a weaker promise.** Recording the group's kill on
every kill would have kept the old words true for this process, and made them false wherever the
read before the kill found only zombies. So the three rows keep their promise and cite the one
exception, as `R-STATE-10` cites `R-STATE-11`. `R-STATE-13` was not in the architect's list. It
promises the same record on standard error, and no report can name a process no read showed.

**The claiming test is owed elsewhere, on purpose.** #539 makes the limit true, but taking a test
that waits on this card's merge would have held #553 for the owner. #567 owes it instead, and the
row lands as a gap in the matrix until then. That is the owner's to permit by merging.
