and why the queue became one queue.

# #430 — What round 1's judges found that the tests could not

**A listed worktree need not be a worktree.** Git keeps listing a worktree whose directory was
deleted, marked `prunable`. A plain directory made at that path then read as a worktree, and
`git worktree remove` refused it. Every fixture had made its worktrees through git and left them
whole, so no test put a stranger at a registered path. `isWorktree` now leaves out every entry git
marks `prunable`.

**A repository has more than one path.** The queue was keyed by the path the caller named, and
every test named the repository by one path, so two adapters naming it by its main working tree
and by a linked worktree queued apart unseen. Keying by git's common directory, as A4's
provisional text named, needs a git call to learn the key, and that call would run in no queue.
So every git call the module makes now waits in one queue for the process. One engine runs per
repository (`D11`), so the queue holds only that repository's calls.

**An import that binds nothing is still an import.** Rule 10 read only what an import bound, so
`import '../substrate/worktrees.mjs'` from `src/cli/` passed it. The rule now also reads each
import that binds no name.

**A fixture's spelling can hide a mutation.** Every fixture handed the adapter the repository's
real path, so skipping the main working tree by its spelled path survived. A test now hands the
adapter the repository through a symbolic link.
