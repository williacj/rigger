# #1407 — CI cancellation passes over runs it cannot act on

The historical GitHub measurements on [card #1407](https://github.com/williacj/rigger/issues/1407)
identify two failure classes. Run 43104652209 failed with `cancel request conflict unresolved`
after GitHub returned 409 for still-queued target 43096061904. Run 43114033018 failed with
`run attribution invalid` after targets 43096900156 and 43097906964 lost their detailed pull
request associations. The card records the commands, measurement window and later affected
runs; the [pre-dispatch attack](https://github.com/williacj/rigger/issues/1407#issuecomment-6812211557)
records the list/detail distinction and the three targets still queued with zero jobs.

[M8-U25](https://github.com/williacj/rigger/issues/1293#issuecomment-6812138525) authorizes passing
over these two states with a log record. Cancellation limits superseded work; its absence does
not change a run's result. The discovery scan now excludes an empty detailed association only
after validating the immutable source, and still resolves all other candidates before writing.
A 409 still requires the frozen identity on its reread; an active result is logged without
claiming acceptance or completion, and the next eligible target proceeds. Malformed attribution,
own-run attribution loss and association loss on final rereads still refuse.

The controlled tests execute the workflow's actual literal. Each changed behavior first failed
with the former refusal, then passed after its corresponding source change. The added cases
exercise every active discovery status and preserve the exact write traces. Existing assertions
are retargeted only under G1 and G2; no test is deleted, skipped or renamed. No real run was
cancelled, force-cancelled or deleted during this work.

The read-order assertion must prove that each read exists before comparing its position with
the POST. An absent read has position -1, which otherwise sorts before the POST. A guarded
counterexample that supplies target 60 from the discovery cache without any detailed GET
survived the initial assertion. Requiring a non-negative read position closes that gap; the
counterexample and the corrected proof are retained separately.

[M8-U26](https://github.com/williacj/rigger/issues/1293#issuecomment-6812179330) waives the dispatch
restriction only for this literal, its tests and this journal. The workflow remains a Self-hosting
path requiring the owner's marker before merge.
