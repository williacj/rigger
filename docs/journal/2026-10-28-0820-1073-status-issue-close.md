# `resume` closes the status issue, and closing it clears the hold

Card #1073 (M6-11c), acceptance revision `725c79ee8abe`, carries
[the M6-11c carry](https://github.com/williacj/rigger/issues/740#issuecomment-6416998469): a test
that `rigger resume` removes the status label from each issue it closes, before closing it. It
starts where #1016's "Where M6-11c begins" left off: a closer naming an issue, read each trigger,
with its comment and its placement retried. The `ARCHITECTURE.md` change is
[U88](https://github.com/williacj/rigger/issues/740#issuecomment-6468001402)'s two deltas, with
Delta 1's prose as [U89](https://github.com/williacj/rigger/issues/740#issuecomment-6468595833)
re-ratified it.

L3 now acts on the closers naming an issue before it reads the board, inside the trigger's `take`.
Doing it there, rather than after `take` answered a closed admission, lets the same trigger claim
once the last closer goes, because `take`'s own admission read still comes after the board read and
in the same synchronous step as the claims. The issue's state is read once per issue per trigger,
however many closers name it.

L2 decides from the timeline's order, not its times. A label applied at the opening is a label
event in the timeline, so replaying label events in order carries it from the opening without a
rule of its own. The opening counts as the notice reaching the issue only where its author holds
write access; a comment counts only where its author does and it was never edited.

Two measurements decided the fixtures. A scan of every issue in williacj/rigger on 2026-10-28, by
`gh api graphql` counting each issue's reopen, close, label and unlabel events, found no issue
holding both a reopen and a label removal: #794 holds a comment and labels at its opening, a close
by a merged pull request's keyword, a reopen and a close; #811 holds a label removal and no reopen.
The deterministic tier refuses to start the fake `gh`, so `resume`'s in-process tests answer
through an in-memory stand-in in `test/notice-forge.mjs`, and only the host-listed verb tests run
the fake `gh`.
