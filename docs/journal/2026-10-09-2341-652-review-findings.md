# Forge review findings

The repository-write runner had trusted its side to establish that a comment target was a pull request. A direct runner call could therefore post to an issue. The runner now performs that read itself before sending the comment, so the boundary it owns is complete even when another caller reaches it.

Rulesets and classic branch protection can name the same required context. Treating the context as one map key discarded one source's App pin. Effective rules now retain each distinct pin, and the check read requires every retained pin's result. Classic `app_id: -1` is the forge's “any App” value and adds no pin.

GitHub's legacy collaborator `permission` field collapses maintain to write and triage to read. The read now uses `role_name`, which preserves the five roles the card requires. The fake answers both fields in that shape.

The SHA guard's mutation test needed a working fake process emitter: without it, removing the guard still failed at process setup. With the emitter, removing the guard makes the three bad SHA cases reach the fake, and their refusal assertions fail for the intended reason.

An unrecognized HTTP 405 rejects with the server's status and message. The behind, method and closed messages in the fake remain examples; no live capture establishes their text.
