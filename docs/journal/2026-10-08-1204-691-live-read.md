# Card #691: first-live directory reads

The audited `r03/runner.log` in the `c689-original-base-runs` artifact from run 37783452030 records one failure of the first-live/later-live assertion. The fixture's `state-count` and answer markers are written before the result reaches L0, and that artifact's `689.trace.jsonl` traces the separate failed-first-state case. The historical failure therefore establishes a false read-count assertion without establishing which answer L0 received.

The diagnostic caller records each synchronous `ps` and `lsof` request and result, every signal answer, emitted events and caller exit in order. Its wrapper records an `ETIMEDOUT` even where `spawnSync` returned a zero status and partial standard output; that combination does not hand the printed row to L0. The named control retains its read-count and named-survivor assertions and prints this trace even when an assertion fails.

The new controls advance the caller's clock only at a chosen `readingNow` or `reaped` boundary. That makes a read skipped at `LATE`, a returned read evaluated at the wait bound, and a plain failure evaluated at the wait bound independently observable without depending on host load or a test sleep. The timeout controls instead let the existing synchronous read bound cut stand-ins that do not answer. Each stand-in lives in the test's scratch directory and its teardown ends it.

The original-base series used source commit `e770812ca43c395c980fd45081695d0ad1179812` with additive test observation. Its process-source SHA-256 was `3d22c77fe75eeb6f15c5fb9837d3027618bd8cbd29c3ddabb906432c9d99ceea` for every run. The audit of 20 whole-file `npm test -- test/never-stop.test.mjs` runs counted 2,180 tests, 2,180 passes and no failures. Start one-minute load ranged from 2.04 to 23.72; every run began under the card's 24 limit. The named control reached the first returned live answer, the omitted-listing result and at least one later returned live answer in all 20 traces. Seventeen terminal state reads timed out. A fixture marker alone was not counted as a returned answer. The historical `r03` failure did not recur, so this series does not establish its cause. The full runner output and ordered trace are retained per run; the pull request records their locations and the phase ruling.

The complete affected-file run on the proposed change passed 120 of 120 tests with no failures. Earlier affected-file failures exposed two errors in the added controls: an ineffective generated clock hook and a timeout-listing assertion that assumed a later state read had time to return. The final controls observe the `reaped` bound after a returned read and force a later `LATE` cut after a timed-out listing. Their full failed and passing outputs are retained for the pull request.
