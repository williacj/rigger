# #483 — L1 runs a role's dispatch through the adapter

**`facts` rides nested, not spread.** The role answer's `facts` name a `card`, and L5's sink refuses
any field it stamps itself, `card` among them. Spread into `dispatch.start`, the facts would be
refused as an event. So the start carries them as one field, `facts`, exactly as L2 attached them.

**The digest is SHA-256 over the evidence's UTF-8 bytes, in hex, as `digest`.** Nothing chose the
algorithm before. One byte of difference changes it, and the instruction is no part of it, which
is what lets two judges' starts be compared (`R-EVIDENCE-5`).

**Every refusal is `NOT_STARTED`, the unknown provider's included.** Ruling 5 makes a failed probe
a dispatch that never started, and the card asks only that an unknown provider "throws". A role
naming a provider L0 does not hold has not started either, so L2 can class all of them the same way.

**An `env` value must be absolute.** Ruling 9's limit 3 says "an absolute path", and the card's
items name only the real-path refusals. A relative path would resolve against the engine's own
working directory, so it is refused too, with a test of its own.

**`within` is extracted, not copied.** `escapes` and `placed` in `run.mjs` each compared a real path
against a root. `roleDispatch`'s check on an `env` value was the third, so the comparison is now one
exported function that all three use.

**Outside this card.** `session` in `test/claude-live.mjs` builds the live run's environment in
ruling 9's order by hand, with no git removal. Now that `roleDispatch` exists, the gated live runs
could go through it. That would change existing lines under `test/`, which this card has no grant
for, so it is named in the pull request and not done.
