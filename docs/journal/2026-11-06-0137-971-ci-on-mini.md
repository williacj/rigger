# Owner-enabled automatic CI Mac routing

[U73](https://github.com/williacj/rigger/issues/740#issuecomment-6419140542)
requested Mini CI with Hosted fallback. On 2026-11-06 UTC the owner explicitly
approved owner-enabled Auto: Hosted default, owner opt-in, idle eligible Mini when
readable, otherwise Hosted. That answer superseded the supervised procedure and
gave no coordinator authority to change `MACOS_RUNNER`.

The implementation keeps routing inside the existing inline plan. One bounded
repository runners read produces one runner/reason snapshot for the four Mac jobs.
A fixed endpoint and dedicated label prevent choosing another runner. Availability
fallback does not reserve capacity, migrate queued jobs or change submission policy.
The [operator procedure](../testing-macos.md#owner-enabled-mac-routing) owns setup
and evidence collection; the [D32 proposal](../spec/decisions.md#d32--the-owner-may-enable-automatic-macos-ci-routing)
records the trust change and preserves D31's historical text in the retired register.
Concept approval is not the final exact-head owner marker or ratification by merge.

The PM's runners API observation on 2026-11-05 UTC recorded one registered runner,
id 23 `CJs-Mac-mini`, online and idle, without `rigger-ci`. This is historical card
provenance, not a current availability or dedicated-label observation. A complete
dated API refresh at final proof remains due.

The new dedicated fine-grained credential is restricted to `williacj/rigger` with
repository Administration read and unavoidable Metadata read, without writes.
Owner provisioning, actual effective capability and expiry metadata remain due;
no credential was provisioned or value read for this implementation evidence.
Only plan selection receives it under `CI_RUNNER_READ_TOKEN`. Same-repository
workflow writers can access repository secrets; per-step propagation is no isolation
from malicious workflow edits. Fork approval and the existing runner hook stay intact.

Root executed the native deadline assurance and whole workflow host regression
once on 2026-11-06 UTC. The maker reopened their physical-LF reporter originals:
named 1/1 and whole-file 69/69 passed, with zero failures, skips, cancellations or
todo. Source scope was the uncommitted host test `9cfc7504` and workflow `e52ce413`,
not final reviewed-head proof. Each run exercised actual fetch/header and body
nonreturn against an owned endpoint, after readiness, using native 100 ms abort
and an independently asserted production deadline request of 30,000 ms. Both chose
Hosted/timed-out, observed peer close before cleanup and completed owned cleanup.
The capture retained EOF-drained streams and closed sampled PID/start identities;
it makes no global or unsampled-descendant absence claim. This proves neither
literal 30-second elapsed behavior nor the default timer factory's runtime identity.

Earlier staged TDD retained meaningful named refusal, availability, read-guard,
timeout, explicit-Mini, shared-job, secret/reason wiring and safe-log RED/GREEN
originals. These are historical slice results; final deterministic and affected-host
verification and guarded semantic mutations at a committed source remain due.
No requirement id was borrowed for these repository-infrastructure diagnostics.

The card remains open. Authenticated Administration-read GET, current unique label
inventory, both final-head candidate pools, actual per-pool submission observations,
bounded interleavings and persistent Mac state measurements are unproved. Normal
hooks, final checks, independent review, self-hosting/gate checks and the owner's
