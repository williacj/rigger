ABOUTME: Records how card 1467 records a dispatch's tracked set in L1's entry and ends it at a later start.

# Record and restart for tracked descendants

Done means every item of #1467's acceptance at K7 `7500fccf9c52`, which builds on M8-39's
tracker (PR #1475, merged at `6798fdf1`).

## What changed

- **L0 hands L1 each process it adds.** `runCommand` takes `onTracked`. The tracker calls it
  in the read that adds a process, naming the group and each added pid with its start time.
  A throw there leaves the process in L0's memory alone, so the dispatch's ending still ends
  it. This is R10's case.
- **L1 names them in the entry.** `addTracked` appends the added processes to the entry's
  `tracked` list and never prunes it (R13). An entry with no `tracked` field reads as an empty
  set, so entries written before this card are handled as before (R7). The record refuses a
  tracked process with no start time, or with a pid that is not an integer greater than 1, as
  a record it cannot read (R8).
- **A later start ends the recorded set by identity.** `killRecordedGroup` takes `tracked` and
  ends it first, through the sweep's stop and start-time confirmation, whether or not the group
  is confirmed (R3, R4). It does this after the group's start-time read, so a start that cannot
  read the group still ends nothing (`R-STATE-11`).
- **What it leaves.** A pid whose start time no longer matches, or cannot be read, is never
  stopped and is recorded as `recorded.unended` (R5, R12). A failed read is treated the same
  way. A pid that no read lists gets no signal and no event (R11).

## Placement of the tests

- The decisions are proved in the deterministic tier, in `test/exit-budget.test.mjs`, from
  `trackerWorld`'s controlled table. `test/descendant-tracker.test.mjs` is not in this card's
  "Lands in".
- The host tests R1 to R8 are in the files the card names. Each carries a host reason and
  names one of those two deterministic tests as its counterpart.
- R2's premise is "the tracker listed M6", not "the record names M6". So the engine runs a
  `ps` that logs each whole-table read, and the test waits on that log. The premise then holds
  with `src/` at M8-39's merge too, so the test fails there on the behaviour itself.

## Not used

- Grants G1 and G4 needed no edit. No whole-entry comparison saw a tracked set, because an
  entry gains the field only once a process is tracked.
- R10 uses `trackerWorld` rather than `budgetWorld`. Its premise is that the parent exits
  before the exit's final read, and only `trackerWorld` lets a test change a process's parent.
