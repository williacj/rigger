# Card 832 Linux zombie fixture completion

Concurrent verification of 7c65b537990c2c17a96c9e846341adadbf9bc7f5 exposed two Linux
fixture assumptions after the earlier full green runs. The owner-authorized G5 scope in
[#832](https://github.com/williacj/rigger/issues/832) covers demonstrated host differences
while retaining behavioral assertions and deadlines.

## Transition into zombie state

On 2026-10-20, repeated npm test runs of the B1 exit zombie case on Ubuntu 26.04.1 x64 under
WSL 2 with Node 26.12.0 failed on attempt seven. The actual returned process-table answer
showed the killed target in D, with wait status zero, while the scenario required Z. The
existing assertion correctly rejected that answer. Linux can expose this intermediate state
while SIGKILL is pending.

The zombie scenario's stand-in now waits for the real target to reach Z before answering its
post-kill reads on Linux after a successful signal call. The caller's existing read deadline bounds that condition wait.
The answer still comes from the real process-table adapter; the scenario's assertions and
deadlines are unchanged. Twenty subsequent focused runs passed, each reporting one test,
zero failures and zero cancellations.

The first version also waited after a deliberately refused kill. Its full hook caught the
A0 zombie K1 assertion that a later group kill must reach the group. The exit fixture's
existing signal trace now distinguishes a successful SIGKILL from a refused attempt before
waiting. Twenty combined runs of B1, A0 K1 and the reaping case passed all 60 test executions,
with zero failures, cancellations or skips.

## Reaping after cleanup

The unseen-member exit case failed its immediate signal-zero absence assertion. A disposable
diagnostic retained the original liveness result [false, true] and read the second PID's
/proc stat immediately afterwards: its state was Z and its wait status was 9, SIGKILL.
The independent reviewer captured the same distinction separately at the same head.

The Linux case now first asserts that both recorded PIDs are absent or zombies, rejecting a
running survivor immediately. It then waits for their adopting parent to reap them before
the original signal-zero absence assertion. The existing test deadline is unchanged. Twenty
focused runs passed with zero failures and zero cancellations.

These changes affect the test fixtures and their completion checks. The Linux process adapter
continues to report real running, D and zombie states. The normal full-suite commit hook and
the fresh independent review are recorded at the revised head on the draft PR.
