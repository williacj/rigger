# L2's review loop answers from markers

Freshness was an injected stand-in for markers, and the loop world leaned on it in a way no test
named. A maker that exited non-zero was never dispatched again, because the world called it fresh
once it returned. With the stand-in gone, the world's forge has to hold what makes L2 leave a
card alone. Under the world's owner-only kind, that is one open pull request from the card's line
of work. So the world now opens one for every returned maker when `fresh` is set, and the
retargeted tests keep every answer they asserted.

The review loop reads a pull request's number and head from `readPullRequests`, not from the
merge-base read. Only a judge's evidence needs the merge base. Reading the head there let a fake
pull request with no merge base fail every Coding and Owner answer, though none of them used it.

Rounds are counted by handing `readMarkers` only the unedited comments. That keeps one reader for
identity, permission and card matching, and it still counts a pair at a head the pull request no
longer holds.

The sink stamps `dispatch` itself and refuses an event that supplies it. So `marker.read` carries
the marker's dispatch id through the emitter's context, not as a field.

I wrote the Owner column's code before running its tests. I backed it out and watched all eleven
Owner tests fail before I put it back. Several table rows passed on their first run because
earlier slices already covered them: the owed-judge rows, the `R-LOOP-11` m2 to m11 row, and the
Coding conflict, unknown and continue rows.

Round one's judges found three faults. Each was a test I had not thought to write.

- **Rounds across a changed acceptance.** A marker from an earlier acceptance with a different
  item count stopped counting as a round, because it was reparsed against today's count. Each
  marker is now read against the item count its own block rules on.
- **The return dedupe.** It trusted any comment opening on the return's first line, so a
  reader's copy could stop a return. It now needs the return itself, written by an account with
  write access.
- **Failed reads beside mergeability.** A conflicting or unknown mergeability answered before a
  failed rules or checks read was looked at. Every read is now held before any answer.

The refusal tests now run through the loop world, so they show nothing moved. A guarded mutation
of each refusal, and of the review loop's digest, fails the new tests.

Round two found two more.

- **Prose after a marker block.** Counting item lines over the whole comment still miscounted a
  marker: prose like `item 1: …` after a closed block inflated the count. Each comment is now read
  at every count up to its item-like lines, and kept at the one count its block parses against.
  The marker syntax stays in `marker.mjs`.
- **An Owner move on a failed read.** A Review card whose kind names agent judges and the owner
  moved to Owner before the forge reads were held. That move now holds them first. A kind naming
  the owner alone still moves without reading them. Holding them there broke 17 tests outside
  this card, in worlds whose stand-in serves a pull request the fake repository does not hold.

Round three overruled that exception, and the failed-read row now holds for a kind naming the
owner alone. Its move to Owner holds the three reads too. The harness worlds that broke now read
through `readsServing`, which answers those three reads for the pull request they already serve.
No assertion changed. The lesson is to apply a table row as written, not to carve out an
exception because the tests are expensive to change: the exception cost a review round.
