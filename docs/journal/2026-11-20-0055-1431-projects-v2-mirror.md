# A Projects v2 board mirrors a Temporal card workflow, at a batched-read price

Spike #1431 ran a Temporal card workflow per card on the Windows machine and mirrored each one to a
scratch Projects v2 board ([report](../spikes/projects-v2-mirror.md)).

The spike deleted the scratch board. The scratch repository was meant to be left for the owner to delete
by hand. Instead rigger-ae deleted it at the owner's request
([1431#7027544903](https://github.com/williacj/rigger/issues/1431#issuecomment-7027544903)).

**What held.**
- Every API edit away from the workflow's column was reverted by the reconcile within the 60 s bound.
- No board edit changed the workflow's state.
- An escalation answer sent as a CLI signal reached the board in about 1.5 s, measured to the completion of the first poll that showed it.
- A worker killed between two field writes healed on retry: the retry wrote only the missing field.

**What we learned.**
- **A successful run can leave drift.** A read-compare-write mirror misses an edit that lands after
  its read, in a run that found nothing to write. The run reports success over a drifted board, and
  only the next reconcile closes the gap.
- **The cost is in the polling.** Polling per card at a 30 s interval costs about 3,600 GraphQL
  points an hour at 30 open cards, against 5,000 for the whole account. One batched board read per
  pass costs about 120.
- **The forge does not return a mutation's cost.** `x-ratelimit-used` on a login shared with other
  sessions only bounds it. One card's 8 mutations cost between 8 (the documented minimum) and 44 points by those counters.

**What failed.**
- WSL's sshd was not reachable, so the run moved to native Windows.
- One setup call died with `EHOSTUNREACH` after its issue had already been created. That made setup
  resumable and taught the logger to record failed fetches too.
