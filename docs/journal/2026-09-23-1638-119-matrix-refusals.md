# Measured matrix refusals

At the branch base `e09ce40`, a temporary fixture put each shape to `node --check`, `node:test`'s `run({ files: [file] })` event stream, and `declarationsIn(source, file)`. Each source parsed, each run emitted `test:pass` with the title below, and each declaration was refused with its file and line. The line-separator shape was checked with both Unicode separators, so the eleven listed shapes took twelve runs.

| Shape | Scan at base | Runner title |
|---|---|---|
| import through a two-file re-export chain | refused-and-run | `re-export title` |
| `test(...args)` spread | refused-and-run | `spread title` |
| `(test)('x', …)` parenthesised callee | refused-and-run | `parenthesised title` |
| dynamic `import('node:test')` binding | refused-and-run | `dynamic title` |
| `require('node:test')` in `.cjs` | refused-and-run | `require title` |
| namespace member call | refused-and-run | `namespace title` |
| `?.()` optional call | refused-and-run | `optional title` |
| `String.raw` title | refused-and-run | `raw title` |
| title containing a line ending | refused-and-run | `line\nending` |
| title containing `|` | refused-and-run | `pipe | title` |
| title containing `U+2028` or `U+2029` | refused-and-run for both | `line` + `U+2028` + `separator`; `paragraph` + `U+2029` + `separator` |

The eight source-decidable refusals remain explicit in the reader and the TDD skill copies. Tracing an indirect binding, spread value, callee expression, CommonJS call, namespace member, optional call, or tagged title would broaden the reader's grammar. Refusal names the declaration and costs a matrix row; an unsupported claim could tell a judge a requirement is tested when no such test ran. The repository's current declarations already pass the matrix check using the reader's direct-call form, so none needs an added grammar branch today.

A matrix row is one line with two pipe-delimited cells. A title carrying a line ending, a pipe, `U+2028`, or `U+2029` cannot be written in that format. The TDD skill copies state each constraint where a maker writing a declaration will meet it. The separate `describe` question is unchanged here.
