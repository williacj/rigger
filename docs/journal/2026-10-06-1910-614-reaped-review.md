# Card #614 review corrections

The review of PR #686 found that the production deadline branch behaved as intended, while several tests and the evidence table did not establish their claimed cases. A holder release scheduled by elapsed time made the fixture itself an uncontrolled clock. The holder now stays open until test teardown, which kills only the PIDs that fixture recorded. Each test waits for the stand-in's printed marker and lets the read deadline close the pipe.

The nonzero child-exit case now has its own assertion inside the read-outcome test. Its descendant holds stdout open past the deadline. The same test also checks before-deadline signal and spawn failures and the exit-0 held-output case, so the behavior-changing case remains red over base source. Tests for the unchanged `reaped` failure and late branches likewise run inside behavior-changing cases. Their stand-ins mark the prior answer and failure; a test-only clock jumps after a marked read to reach `LATE` without waiting for elapsed time.

A synchronous `reaped` read refused with no code while waiting on a killed directory PID cannot be reached. If the refusal already exists, `sweeping` cannot make the state read needed to find and kill the PID. If a sweep read first answered and then timed out, `sweptNow` clears that process-table refusal when it records the kill. The PR's cell table states this limit rather than citing an unrelated test.

The first full head suite had one read test wait for a fixture holder until the holder's recorded PID was killed manually; that suite then passed. Its captured output and the intermediate failed-run outputs are posted on PR #686. The condition-based fixture removes that cause of the wait.
