# Card 574: a mid-exec census spends CPU on reads it cannot use

The target measures processor time across the whole `recorded` call against the wall time after its stand-in's second `ps` call. On 2026-10-14, `c574-summarize.py` over `c574-natural-base-01` through `20` at declared base `07e67cd` found 20 consecutive passes: starting one-minute loads 7.35–8.55 on 12 logical CPUs, whole-call CPU 70.539–80.481 ms, and re-read intervals 1,490.901–1,493.976 ms. Those observations do not reconstruct the historical CI failures. The historical logs give a numerator and denominator, but no ordered reads or processor-time phases.

The current stand-in reports `?` for the live survivor's state. Once a whole census round has finished, a later round whose first state read contains `?` cannot agree: agreement requires settled states in both state reads. On the base, each such round still reads the command table twice, reads the survivor's name, and reads the state table again. The forced fixture source emits 512 chunks of 65,536 spaces after the real `/bin/ps` name, which is 32 MiB by multiplication. In `c574-force-base-chunk`, the ordered trace showed 18 name reads, 324.115 ms of Node CPU between those read starts and answers, and a 588.133 ms whole-call numerator against 1,492.414 ms of re-reads. A CPU-snapshot calculation over that same original places 579.785 ms between the first census read start and last answer, 6.457 ms before and 1.897 ms after. In `c574-force-head-chunk`, the trace showed one name read, 29.545 ms for that read and a 98.839 ms numerator against 1,492.264 ms. The head stops later `?` rounds after their first state read, preserving the last complete round and its sightings. This is a probe of the mechanism; it does not establish that CI supplied padded names.

The census also observes how long a completed round took. At the post-round clock observation, when enough time remains for a round of that duration, it caps the requested wait to leave that much room. It never requests more than the base's wait. A scheduler can still delay the next read beyond the request; the controlled answer tests distinguish the request from the actual start. On 2026-10-14, the `c574-r2-*` and `c574-controlled-*` traces at the instrumented base and head showed matching controlled groups of one, 25, and 100 members, requested one-clock-unit waits and agreeing second rounds.

The trace hook is optional at the process adapter boundary. It records the source's wait and round decisions and the reader's starts, answers, failures, and CPU snapshots. The same hook and test bytes are applied to the instrumented base and head; only the census change differs in the comparison. The generated test matrix follows the new requirement claims. No protected ratio operand or bound changes.
