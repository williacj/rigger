# #349 — A restart kills what the dead engine left first

## What was learned

- **The kill belongs in `take` as well as `run`.** `run()` records `run.start` before any pull, so
  it awaits the kill itself. `pull()` and `claim()` reach the board only through `take`, so the
  same memoised kill is awaited there. One promise per handle means the kill runs once, and a
  kill that failed rejects every later call on that handle.
- **"Rigger mid-dispatch" needs its own process.** A restart is only real if the engine it
  follows dies by SIGKILL, so the stand-in is a Node process that runs one pull of L3's loop.
  It is started through `-e` importing `test/mid-dispatch-engine.mjs`, and not as a script file,
  because `node --test` would run any `.mjs` under `test/` as a test file with no arguments.
- **The moment of the first board read is observable from outside.** A `gh` first on PATH checks
  with `kill -0` which of the dead dispatch's pids are alive on its first call, then hands on to
  the fake `gh`. With the start's kill removed from `claimVerb`, it records both pids alive.
- **Declarations nested in a `for` loop are refused.** The matrix builder cannot say whether the
  runner reaches a call inside open brackets, so the `once` and `run` variants are written as
  four top-level tests over two helpers.

## What surprised

The restart tests passed first time against the wiring committed before them. So their red is
shown by mutation, in the pull request, rather than by the order of the commits.
