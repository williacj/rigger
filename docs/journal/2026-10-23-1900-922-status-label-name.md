# The status label's name

Card #922 (M6-03j) is the short structure delta that
[K54](https://github.com/williacj/rigger/issues/740#issuecomment-6341789050) asks for:
"Whichever card carries M6-04b's status half settles the name and #752's 'the status label is
the second' wording, through a short structure delta for the owner first."

## What the delta proposes

- **The string, for the owner's ratification: `rigger:status`.** It is the one the architect's
  pre-dispatch attack on #922 (comment 6377074167) proposes. It takes the escalation label's form,
  names the issue it marks, and stays true while a stale status issue is open. It differs from
  `rigger:escalated` under any letter case, and nothing in `rigger.config.mjs` or `templates/`
  selects by it or names it as the epic label.
- **Exactly two fixed labels.** The escalation label's sentence now says "one of Rigger's two
  fixed labels", and the status label's sentence says Rigger fixes no other.
- **The one-request opening.** One new sentence carries the architect's Q1 ruling on #923
  (comment 6377060821): L2 opens the status issue in one request with its label, no later write
  adds that label, and the repository-write side rejects an opening whose forge answer lacks it.

## What it leaves to later cards

The M6-04b status-label residual is the card this unblocks. At this head `FIXED_LABELS` in
`src/config/validate.mjs` still holds the escalation label alone, so the residual adds the status
entry there (the attack, finding 5). Open PR #868 edits the same paragraph's `R-WORK-33`
citation; whichever merges second keeps the other's change.

What would reverse the string, per the attack: a consumer repository already using
`rigger:status` for its own purpose, or the owner preferring a name tied to the issue's title.
