# #591 — a process every answering read leaves out

**The record of forced ends had a second hole, and this one no structure can close.** #567's
hidden-member item asked L0 to record a live process that every read of its group leaves out,
while the read still lists something. The maker found no read or signal that tells such a read
from a complete one, and the architect ruled the same on all three kill paths. The table is the
only source of a group's pids, and signal 0 to the group answers alike for a live process and a
zombie. The `D16` rule 3 notes beside `beforeKill` and `startsIn` already said so. The rows did
not.

**It is a new row, not a wider `R-STATE-20`.** `R-STATE-20` is about a process no read could see
because it came and went between reads. This one is present at every read and the table hides it.
Folding it in would change what `R-STATE-20` makes true, and the preamble would then demand a new
id and the old one's withdrawal, orphaning every test that declares it.

**The row speaks the register's words, not the code's.** The card wrote "member" and "leader".
Neither appears in any binding document, so the row says "the same process" in "a process group
Rigger created", and "the command Rigger ran in that group", as `R-STATE-7` already names the
leader. The meaning is unchanged.

**The row has to say which reads it means.** The first draft said "every time Rigger reads the
group". The engineer judging PR #592 showed that either reading of it was wrong. Counting the
reads after the kill, a read landing while the process exits lists nothing, so the row missed the
case it exists for. Not counting them, the row said "records nothing" where the code records the
group's kill, as three tests in `test/never-stop.test.mjs` prove. So the row now names both: every
read before the kill leaves the process out while it lives, and no read after the kill lists it,
live or as a zombie, counting one that lists nothing.

**What it gives up is real.** Rigger no longer promises a trace for every process it ends by force.
A host whose table hides such a process would end it silently. Nobody has seen such a host. A
measured one, or a second source of a group's pids on macOS and Linux, reverses this.
