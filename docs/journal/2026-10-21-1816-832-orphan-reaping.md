# An exited orphan still answers signal zero before reaping

Card #832's G5 permits corrections for independently observed Linux fixture differences while
preserving behavioral assertions and deadlines. This correction uses that existing grant.
It changes no production code, engine-host promise, signal policy or timeout.

## Measurement

On 2026-10-21, a disposable checkout of 56a00abc634569da07213c116dc160ed46ccbe6f reproduced
the EPERM leader exit-cleanup test's original child-absence assertion failure. The host was
Ubuntu 26.04.1 x64 under WSL 2, kernel 6.18.54.1-microsoft-standard-WSL2, with Node v26.12.0.
The command was `npm test -- --test-name-pattern="given a command whose leader answers signal 0 with EPERM once" test/never-stop.test.mjs`.

The diagnostic captured both signal-zero answers before reading the process table, so the
diagnostic did not move the original assertion's sample past the failure. A later probe read
Linux's `/proc/<pid>/stat` immediately after those answers. Its second invocation failed:
the first child was absent, and the second still answered signal zero. That child's proc row
identified PID 589 as `tail`, state `Z`, with exit status 9. It had exited by SIGKILL and was
waiting for its adopting parent to reap it. A signal-zero answer alone had called it alive.

## Correction

The Linux branch first asserts that both children are absent or exited zombies. It then uses
the existing condition-based `until` helper to wait for their reaping under the test's existing
bound. The original child-absence assertion remains after that wait. A live child fails the
new state assertion before the wait. The macOS path and every original assertion remain.

This follows the Linux orphan-reaping treatment already present in `test/never-stop.test.mjs`.
It adds neither a sleep nor a new or enlarged deadline.
