# One repository write-access list

Card #1036 fixes the list's home in `src/workflow/marker.mjs`. Exporting its existing `WRITERS`
lets escalation notes, earlier acceptance returns and status-notice recovery use the same rule
as verdict markers. The gate gains no import. The earlier `RETURNERS` name and its local list
are removed because the return check now uses `WRITERS`.

The acceptance revision was measured before editing with `gh issue view 1036 --json body --jq
.body` piped to `shasum -a 256`: `85f5a6ddf24d`. The supplied branch's base, measured with
`git rev-parse HEAD`, was `2b6d64f3cec10848cfda2912b6985e41e63d3cc7`.

At that base, `git grep` for the ordered write-access literal across `src/`, `scripts/`,
`.github/` and `test/` found four workflow copies and two test expectations. The test literals
remain independent expectations. Searching `test/` for each workflow filename also found the
gate's import constraints; exporting the list preserves those constraints. No existing test
line needs to change.

The deterministic baseline passed through the host-wide slot: the runner measured 3,767 tests,
all passing, with one-minute load 2.30 at start and 3.39 at end. The export test first failed on
`undefined`, then passed after the list was exported. The import-contract test then failed on
`escalation`, and passed after all three consumers imported `WRITERS`.

The new permission checks exercise markers, maker notes, suppression of duplicate acceptance
returns and status-notice recovery. Their expected outcomes come from the card, independently
of the exported array: `admin`, `maintain` and `write` count, while `triage` and `read` do not.
These are preservation checks for the extraction; the card introduces no requirement claim.
The final-head run records and guarded mutation receipts belong in the pull request evidence.

The first guarded removal of `write` also removed the return test's setup marker, so that test
reached a missing-fact error instead of its permission assertion. Supplying equivalent setup
markers from all three writer permissions keeps the return check reachable when a single
permission is removed. The original receipt is retained with the final receipts in the PR.
