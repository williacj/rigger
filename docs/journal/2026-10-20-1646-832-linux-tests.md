## Operating system facts

The adapter's Linux process-table command lives in L0 under the existing
[layers boundary](../../ARCHITECTURE.md#the-layers). GNU ps selects a session for the existing
`-g` invocation, while the adapter needs a process group. The Linux wrapper selects the PGID
explicitly and preserves the underlying status. Its restricted-PATH test uses two real groups
in the same session, so an accidentally selected session cannot satisfy the assertion.

GNU ps sanitizes control bytes in command names. The Linux wrapper reads /proc/PID/comm for
the existing raw-name request. Linux's comm limit leaves 15 name bytes, documented by
[proc_pid_comm(5)](https://man7.org/linux/man-pages/man5/proc_pid_comm.5.html).
For zombie exit status, Linux's ps returns no usable xstat; the wrapper reads field 52 of
[proc_pid_stat(5)](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html) and retains its
POSIX wait-status meaning. A real unreaped exit-7 child verifies hexadecimal 700.

Linux lsof uses /usr/bin/lsof and omits the fcwd field from the existing field selection.
The real-tool listing test remains the authority for the shared stand-in format. No manually
created /usr/sbin/lsof link is used in final verification. Signal classification uses names
the runtime actually exposes and retains the real bare/listening probes.

## Fixture corrections

Linux fixtures explicitly select Bash where they need its shell behavior. GNU pgrep/pkill use
their ancestor exclusion so the observer does not count itself. Linux lock fixtures use flock's
nonblocking conflict status 75; macOS retains lockf. Git fixture repositories and clones set
their own identity. Partial JSON records become visible only after their terminating newline.
An exec fixture explicitly replaces its shell so its recorded PID remains the group leader.

The profiler's empty Linux program sometimes exited before its first sample. A Node spawn
probe on 2026-10-20 measured 6 normal exits among 120 concurrent empty programs with a SIGPROF
listener. Giving the same probe CPU work produced 120 SIGPROF endings among 120 runs. The Linux
test now performs that work; its signal assertion and ten-second subprocess bound are unchanged.

An attempted shared input drain caused the held-start fixture to wait on a pipe while the
engine's synchronous start-time read prevented its input write from progressing. The existing
held-record test reproduced the failure in isolation. That drain was removed; only the
short-lived direct-spawn test command consumes its input before exiting. The combined focused
signal, held-record and exec tests reported nine passed, zero failed and zero cancelled.
