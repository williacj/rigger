# Only `run` and `once` copy the record

Card #1410 (M8-26), acceptance revision `61d7f1db444e`, made against `origin/main` `c1f6c41e`.
The owner ruled Q-A as option (a) under M8-U31.

## Which verbs push

- **At the merge base `c1f6c41e`:** `src/cli/verbs.mjs` handed L5's push to every verb. `doctor`,
  `plan`, `setup-board`, `verdict`, `once` and `run` handed it to `recording`, so each pushed at its
  normal return. `init`, `pause`, `resume` and `report` took it and handed `recording` none.
- **At the head:** `verbs.mjs` hands L5's push to `once` and `run` alone. `doctor`, `plan`,
  `setup-board` and `verdict` no longer take one, as `init`, `pause`, `resume` and `report` never
  did. `run`'s pushes at each drain trigger use the push `once.mjs` is handed, so they are
  unchanged.

The four verbs' `opened.admitted(config)` calls, and `doctor`'s `admitting`, existed only so L5
could read `telemetry.push`. With no push handed, nothing reads that config, so they are gone.

## Cases no item decided

- **The four-verb test runs the verbs as commands.** `setup-board` and `verdict` cannot reach
  their normal return in process under the strict deterministic guard: the first spawns `gh`
  through L0's process adapter, and the second needs a terminal. So the test runs all four through
  `src/cli/rigger.mjs` in the verdict world, which isolates the PATH and fronts a fake forge, and
  sits in `test/verdict-world.test.mjs`. Each verb runs twice in one repository, with the push off
  and then on, and the fake forge's state is restored between the runs, so both runs read the same
  board.
- **The push off, in process.** `consumerConfig` reads each config file once per process, and `once`
  imports it from the one instance of `doctor.mjs`. So the second module instance the tests used for
  `doctor` cannot stand in for `once`. The run with the push off now hands L5 the admitted config with
  `telemetry.push` false, through the real push.
- **The second O12 test and C10** were about `doctor`'s own return; `once` has no in-process path
  that stops on a refused kill and returns normally. O12 now asserts `doctor` reaches no push side,
  and C10 hangs work handed to `recording` directly. What the second O12 proved for `doctor`, that a
  normal return with exit 1 after a refused event still pushes once, is kept by a test of work handed
  to `recording` with the push. That behaviour is `recording`'s at the merge base too, so the test
  passes there; a guarded mutation shows it discriminates.
