# Tie the fake gh and the fake board to real gh with one contract suite

`test/gh-contract-cases.mjs` holds the cases. `test/gh-contract.test.mjs` runs them against the
fake gh in process, and `test/gh-contract-host.test.mjs` runs them against real gh and the live
board 6 where the run sets `RIGGER_LIVE_GH=1`. Each case sends its commands through the forge
adapter's read runner, or through a contract agent read runner that admits only `gh pr view` and
`gh pr diff`. So the real side refuses a write by structure, and a guard in front of both runners
fails the case by name first. The board cases run the adapter's `readSide`: against the fake board
behind the fake gh, and against the live board through real gh.

The live facts a case ties by value were measured with gh 2.98.0 on 2026-11-08, read-only:

- pull request #1202, merged from `rigger-1194` at `d902e65c`;
- issue #1194;
- `.npmrc` at `52fb8a3d`;
- the `gate` environment;
- `williacj`'s `admin` role;
- `main`'s missing classic protection.

The same day, a throwaway driver ran the 33 gh cases that read no board against that gh, outside
the suite, and all 33 passed. The 7 that read the board, and the 8 board cases, were not run: the
token lacked `read:project`. That run is a measurement. It is not the opted-in host run the card
asks for, and nothing here claims it as that run.

Three things the work found fall outside this card:

- **Fake gh's missing pull request.** For a pull request number the repository lacks, real gh
  prints the response, holding a `NOT_FOUND` error, on stdout. The fake gh prints nothing there.
  This was measured with gh 2.98.0, for #999999. The fake modules take added lines only on this
  card, so the difference is recorded beside the answer, not fixed.
- **Fake board's direct reads.** Called directly, the fake board's `readColumns` and `readItems`
  answer in another form than the adapter's `readSide` does: column names rather than columns by
  key, and every item rather than the cards. This is recorded beside them.
- **Stale suite fingerprint.** `ci.yml`'s `CI_HOST` holds a fingerprint of `test/suite.sh` that
  already differed from the file at the base `52fb8a3d`. This was measured with `sha256sum`.
