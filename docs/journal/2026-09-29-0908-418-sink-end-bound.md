# #418 — The first write restarted the bound it should have been charged to

## What was wrong

`writeWhole` restarted its deadline after every write that took bytes, the first included. On a
reader that never drains, the first write goes into the room the pipe had from the start, so it
shows nothing about the reader. Restarting there left out everything the call did before it,
opening `process.stderr` included, and the write then waited its full 899 ms after that.

The product was wrong, not the test: the instrumented `writeWhole` alone ran 1082.2 ms from its
call to its return, and the test's measure added 0.9 ms to that.

## What taught us

An instrumented run on a loaded host (macOS 27.0, 12 cores, Node 26.5.0, base `a901fce`) caught
one overrun, on a standard error the process never touched: 181.5 ms passed between the call and
its first write, and the last pause ended 0.5 ms late. The pauses were never the problem. The
SPARE kept for a late pause cannot cover time the deadline never counted.

## The fix

The deadline is read first, before `process.stderr` is opened, and only a write into a pipe
found full since the last write restarts it. A slow reader still gets every byte, because each
time it makes room in a full pipe the wait starts again.
