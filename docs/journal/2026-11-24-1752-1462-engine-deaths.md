# #1462 — How often the engine and its hosts died

## What ran

On 2026-11-24 one command read the Emend engine's event stream under M8-U126. It kept only the card's fields, printed
every count, and wrote the extract to the owner's archive once a checker passed the same lines. Two searches read this
repository's journal entries and comments. The counts, the method and the limits are in
[the report](../spikes/engine-deaths.md).

## What we learned

- **There is no rate to rule on.** The stream holds one engine death, in 9.6 engine hours, and a death's cause is not
  recorded. A rate needs at least four deaths that can be told apart from stops.
- **The public records hold two engine deaths with a dispatch in flight, and both were deliberate.** One is a planned kill of
  the same engine. The report does not match it to the stream's death, because the card publishes no event's time.
- **A handled stop and a fault look the same in the stream, and so do an engine's death and its host's.** An event that
  named the host's boot and a run's deliberate stop would tell all three apart.
- **What resume would save is the wait, not the work.** #1429 found Temporal recovers the attempt and not the agent, so the
  redo happens either way. The wait is bounded by launchd's interval.

## What went wrong, so the next spike avoids it

- **"The output the checker passed" was read two ways.** The card meant the extract's own lines, byte for byte. Settle
  which bytes a digest covers before the code is written.
- **A closing stretch is wider than the last line.** An exit cleanup ends every call in flight, so several ends are one death.
  The first D2 condition missed that, and the PM settled it.
- **`recorded.killed` from a later run does not prove the engine's process was alive.** A start also records one for any
  process it finds in the dispatch's directories. The card said it did, until the code was read.
- **A `jq` search of every saved comment was too slow to finish.** Node read them line by line in seconds.
- **The suite discovers test files anywhere in the tree, the gitignored `spikes/` included.** A spike's test file there runs in
  the commit hook. Name it so the suite does not find it, and publish it under another name.
- **A recorder that keeps a command keeps only half of it.** Its first scripts changed between runs, and the record named
  only the file. Copy each script into the record as it runs. Recovering the texts later took the maker's session record.
- **A mutation script that deletes its children's outputs deletes the evidence.** A judge could not tell an assertion from a
  crash, so the run was repeated with every output kept.
- **A figure read from another spike still needs a recorded read here.** The times #1429 measured were cited, and the judge
  held the citation short of the card's rule, so a run recomputed them from that spike's evidence.
