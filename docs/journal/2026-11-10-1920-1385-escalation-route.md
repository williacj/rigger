# The instruction and its dispatch grant

Card #1385, acceptance revision `0d76f01ab699`, pins a file and one command for an escalation note. The instruction names that
command, L1 passes the dispatch's card number, and the Claude adapter adds the exact rule after
building any reached-directory grants. The settings templates and Codex adapter stay unchanged.

One case the acceptance does not decide is a direct adapter invocation without a dispatch card.
Existing adapter tests exercise that case without an escalation instruction. Such an invocation
keeps its existing settings; only an invocation handed a card gains its card's command. This
avoids granting a command naming `undefined` and preserves the existing direct-call contract.

The shared fake forge routes the added issue-comment CLI spelling through its existing REST
writer. Its existing command enumerations and handlers remain unchanged. The route test uses
literal note bytes with quotes, shell characters, a backslash and Unicode, and checks that the
other card receives no comment. The zero-exit guard keeps the note's category ahead of outcome
classification, as the acceptance requires at both base and head.

The requirement and architecture deltas are the card's pinned proposals. Their ratification is
the owner's marker, which the coordinator arranges; this maker supplies none.

forbidden command spellings, and the escalation role in its `main` directory. The Codex live
