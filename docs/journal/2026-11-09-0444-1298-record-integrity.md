## I4 measurement correction

The coordinator's pre-judge finding invalidated the original overlap evidence at commit
0cd2cf0fdb8c66479745ddddd0b00d507c27d7bc. Both first timestamps preceded the emit-0 rendezvous,
so the overlap predicate could not reject serial continuations. The retained guarded mutation
`1298-0cd2cf0fdb8c-old-serial-control.log` measured that defect: original, serialized and restored
selected suites each exited 0 and reported tests 2, pass 2. Its receipt status is `survived`.

The driver now reads the first timestamp immediately before emit 1, after that rendezvous,
and the last after emit 999. All 1000 events from each writer remain subject to the existing
byte-count, whole-event, envelope and per-writer-order checks. Diagnostics report the measured
interval and observed run switches without asserting overlap in their text.

A guarded local control gave B a separate continuation signal, released only after A exited.
Both line sizes then failed the named assertion `the two measured emit windows must overlap`:
tests 2, fail 2, native suite exit 1. The guard restored the working test's preimage byte for
byte. The restored full event-sink file passed: tests 40, pass 40, fail 0, skipped 0. These are
measurements from `1298-local-serialized-red.log` and `1298-corrected-host.log`, through the
host-wide slot with the card's TMPDIR, before committing this correction. Formal committed-head
receipts and final-head verification belong to the PR evidence.


## R1: persistent writer signals

The [reviewer’s F1](https://github.com/williacj/rigger/pull/1329#issuecomment-6750329529)
at bedafc1230497d418fd89887d2c081bdf8e59882 reproduced two unmodified host failures:
R7 cancelled at its 60-second deadline, and the 1 MiB I4 case cancelled at its 180-second
deadline. Each affected-file run reported tests 40, pass 39, cancelled 1, native exit 1.
The reviewer observed A stopped after event 0 while `continue` existed and B had completed
1000 events. Those failures supersede any inference of fixture reliability from the earlier
passing host run. They are this card's introduced harness defect, not evidence of sink loss.

The helper checked file presence before waiting, then only after a future directory-watch
notification. Its start/first-returned IPC message followed arming the JavaScript wait, so
moving the listener earlier cannot establish reliable progress. An absent notification leaves
that promise suspended without another presence check. The [earlier #622 investigation](2026-10-16-1210-622-watch-before-fsevents-stream.md)
records this native-arming fault. The current runtime reports Node 26.13.0/libuv 1.53.0;
reading that Node tag's [directory-watch path](https://github.com/nodejs/node/blob/v26.13.0/deps/uv/src/unix/kqueue.c#L587)
and [FSEvents initialization](https://github.com/nodejs/node/blob/v26.13.0/deps/uv/src/unix/fsevents.c#L843)
confirms that initialization queues work for the CoreFoundation thread and returns, while that
thread later creates/starts the stream with `kFSEventStreamEventIdSinceNow`. Thus arming the
JavaScript listener does not close the native startup window: a file can be written before
the stream exists and never produce the notification the promise needs. That mechanism fits
the captured persistent-file stall; the capture does not instrument which native startup/event
was missed. Runtime/version/source bytes and hashes are retained as `native-watch-provenance.json`.
The signal is persistent state,
so the wait now rechecks it on each event-loop turn, matching the existing predicate-wait
pattern in this host file and `test/process-fixtures.mjs`. Neither deadline changes.

R7 now exercises both start and continuation with directory notifications withheld. A child
preload observes the actual stdout report following each returned emit and answers over IPC
after an event-loop checkpoint. Each case first observes an absent signal and no returned-emit
report, then creates the real file and requires progress. The existing independent kill,
returned-report, reader, envelope/order and restarted-writer assertions still run in each case.
The preload forwards stdout unchanged and does not change the sink or its writes.

Before changing the wait, the new cases at the stated head plus uncommitted regression tests
failed both named release assertions: tests 3, pass 0, fail 3, cancelled 0, native exit 1
(the parent failure groups its two assertion failures). With the predicate wait, that same
target passed: tests 3, pass 3, fail 0, cancelled 0. The complete affected file then passed:
tests 42, pass 42, fail 0, cancelled 0. These are measurements from `red-signals-native.log`,
`green-signals-native.log` and `green-affected-native.log` in the retained `1298-r1` evidence
directory; `stages.jsonl` records exact commands, heads, native endings and start/end loads.
Final-head repetitions, serialization/loss controls and whole-tier receipts are required before
re-review; their measured results belong in the PR.
