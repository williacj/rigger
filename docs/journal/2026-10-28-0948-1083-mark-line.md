# Clock firing marks

Card #1083, acceptance revision `b09bb0fff8fe`, defines done: Table M's rows, one new workflow
module without a production importer, new tests only, passing deterministic verification and
package budgeting. The PR carries the head-specific verification and mutation receipts.

`src/workflow/clock-mark.mjs` exports `composeClockMark(name, occurrence)`, `parseClockMark(line)`
and `carriesClockMark(body, name, occurrence)`. A mark is the plain-text prefix `Rigger clock: `
followed by a JSON pair. JSON preserves the name and numeric time value while escaping CR and LF.
The parser accepts the composed spelling; other lines return null. The body scan compares exact
lines, splitting at LF and CRLF as the existing form reader does.

## M15 cases met

- A mark alone, at EOF without a newline, or followed by LF counts.
- A duplicate mark still counts. An exact mark line inside a fence counts, following the
  architect's ruling that a mark on any body line counts (1083#6471918553).
- A lone CR, U+2028, U+2029, vertical tab or form feed does not split a body line. Marks joined
  to surrounding text by any of these do not count.
- A leading or trailing space, blockquote prefix, other prefix or suffix, or two concatenated
  marks prevents an exact-line match.
- Both inclusive time-value boundaries round-trip for each name case. Occurrences below the
  lower boundary, infinities, undefined and null are refused with the supplied value named.

Table M's M10 test also changes each character position of every pair's mark independently;
none of these bodies carries the original pair. M11 scans every two distinct pairs' marks
against every pair, so it observes both presence and absence independently of the parser.
