# The config is read once, into plain data

The owner's ruling U109 at
[740#6505537594](https://github.com/williacj/rigger/issues/740#issuecomment-6505537594) ratified
boundary rule 4, which names `consumerConfig` in `src/cli/doctor.mjs` as the config's entry point
and has it hand on a plain-data copy, read once. #1146 landed the rule; this card makes the code
meet it.

## A consumer-visible change

A config holding `undefined` as a nested value is now refused where it was admitted. At
`e20bd768` the validator admitted `kinds.change.rounds: undefined`: measured at `f94446e0`, where
`src/config/validate.mjs` and `src/cli/doctor.mjs` are as at `e20bd768`, `validate` answered `[]`
for this repository's `rigger.config.mjs` with that key added. `consumerConfig` now refuses the config with one line naming
`default.kinds.change.rounds`, and every verb that reads the config reports that line where it
reported a config before. A consumer whose config writes `rounds: undefined` deletes the key,
which the validator reads as before. The whole export being `undefined`, or no default export at
all, is answered as before, `{ config: undefined }`, which the validator refuses as holding no
declarations.

## How the copy reads nothing that runs

The copy reads only own enumerable string keys, each through its property descriptor, and refuses
a Proxy before reading any key, so no accessor and no trap the config holds runs during the copy.
A non-enumerable property is never listed, because `test/layer-boundaries.mjs` bars code under
`src/` from naming an API that lists one, so the copy leaves it out rather than refusing it (row
E17).

The hold is keyed by the real path of the target directory joined with `rigger.config.mjs`, so
two spellings of one directory, a symbolic link among them, share one read. Each call answers a
fresh copy of the held answer, so a caller that changes its copy changes no later answer.

## Depth, and JSON.stringify

The card bounds nesting at 100 levels. Its row E19 asks for a case deep enough that
`JSON.stringify` throws a `RangeError`. Measured on Node 26.5.0 on this Mac on 2026-10-29, with
`node -e`: `JSON.stringify` of objects with `Object.prototype` nested ten million levels, and of
lists nested a million levels, threw nothing; of objects with a null prototype nested 100,000
levels, it threw `RangeError: Maximum call stack size exceeded`, as it did for objects with
`Object.prototype` given a replacer or an indent. So E19's overflowing case is built of objects
with a null prototype, and its test checks that premise on every run.

## The two tests whose fixtures used a getter

`test/telemetry-push.test.mjs` switched `telemetry.push` between two runs through a getter, which
`consumerConfig` now refuses (grant class G1). Its config now exports a live binding the test
switches to a second plain value, and the run with the push off goes through a second instance of
`src/cli/doctor.mjs`, imported with a query string, which holds its own reads as another process
would. Every assertion stays.

`test/doctor.test.mjs`'s test of a getter that throws in validation now asserts
`consumerConfig`'s refusal in its place (grant class G2), with the report, the failed config line,
no stack trace and no forge call beyond `auth status` still asserted.

## Refusal before closer work

The [PM's published r3 acceptance](https://github.com/williacj/rigger/issues/1149#issuecomment-6534270782)
adds G3's reason retargets and G4's six duty replacements under
[U120 option A](https://github.com/williacj/rigger/issues/740#issuecomment-6523272481).
The six fixtures keep their config text and verbs. Each now proves that its enumerable board
accessor is refused at `default.board` before admission opens: the hold closer remains and no
opening event is recorded. The existing no-reread-output assertions remain. This retires their
post-opening changing-AggregateError duty by the owner's grant; it does not claim that duty is
still proved. G3 keeps every config input and the resume test's closer, forge and no-stack
assertions, retargeting only the refused values' reasons to the entry point's paths.

The plain-data answer also makes the named config-validation throw guards obsolete. They are
removed from `resume`, `doctor`, `verdict` and the gate's `defaultConfig`. The separate catches
for admission, forge reads and writes, `notice.close`, and gate-file cleanup remain at their
own boundaries. The config-load inventory finds one consumer-module import in `consumerConfig`;
its CLI callers and the gate hand only that answer to validation and the lower layers.

The earlier full host run at the first commit failed the seven old expectations in
`test/hold-close-verbs.test.mjs`; its complete output remains in the maker's scratch directory.
The revised tests replace those duties only within G3 and G4's granted causes.
