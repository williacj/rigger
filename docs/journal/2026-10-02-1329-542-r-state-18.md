# #542 — a stop Rigger sent is a stop Rigger releases

**Why a row, and why now.** #539 found that L0's census can leave a process stopped under pid 1 for
good. That happens when a child detaches while the census holds its group stopped. `R-STATE-17`
puts a process outside every group Rigger created, and working in no dispatch's directory, outside
its rule. So no row bound Rigger to release such a process. Architect ruling 11 on #467 found the
fact observable from outside, which makes it a requirement, and the PM proposes it (`D18` rules 3
and 7).

**The id.** `R-STATE-18` is the next unused id in the group. Neither register holds it at the base,
no open card or pull request names it, and `npm run check:ids` passes.

**The words.** The row says what must be true and names no mechanism: no signal, tool or module.
How L0 finds and resumes such a process is #539's, and the structure is ruling 11's delta, which
#541 carries. The row reads the same whether or not the process is still in a group Rigger created,
because the leak #539 found is a process that left one.

**What claims it.** Nothing yet. The row lands as a gap in `docs/derived/test-matrix.md`, and #539's
tests will declare it. Landing it unclaimed is the owner's to permit by merging.
