# 2026-09-25 — setup-board adds what is missing and touches nothing else

`setup-board` reads the board first, plans every write, and only then writes. So a board it must
refuse is refused before the first write. A priority field of another type is refused that way
today, and #289's check goes in the same place. Each write goes through the schema-write side and
prints one line. The verb refuses the source tree it runs from with doctor's own check (`R-SAFE-5`).
It uses the `sourceTreeGuard` and `consumerConfig` that #300 pulled out of `doctor` for `plan`.
This branch had pulled out the same two under other names, and dropped its copies when it merged.
A name the validator accepts may hold a line break or an escape sequence, so each printed line
writes a name's control characters and line separators as `\u` escapes. That keeps one write on
one line, as round 1 found it did not.

Round 1 also found three ways a field creation's options slipped past the colour check: one
option given where the list belongs, `singleSelectOptions` given twice, and `color` given twice
in one option. The check read only the first of each. It now reads every field through the same
`fieldsOf` the options write uses, which refuses a field given twice.

The read side could not tell a priority field of another type from no field at all. A
single-select fragment answers any other field as an empty object. Asking for the field by name
does not work: on board 6, with gh 2.99.0 on 2026-09-25, `field(name:)` for a name the board does
not hold made gh exit 1 with `NOT_FOUND`. So the new read lists every field with its `dataType`
instead. #224 landed the same listing for its priority read while this card was open, so both
reads now share one query, one fake `gh` answer and #224's board 6 capture. The board 6 reads
made for this card came before the coordinator asked for reads to be posted first, and #234
records them.

The labels created are the ones the config's kinds and provisioning steps select, and the epic
label where the config declares one. The first acceptance named only the selectors. On
2026-09-25 the owner ruled that the declared epic label is created too, and the PM revised the
card to match.

The option colour check came in with the card's revised acceptance (finding 1 on PR #295). The
runner had admitted any unquoted scalar as a colour. It now admits only the eight values GitHub's
`ProjectV2SingleSelectFieldOptionColor` held when introspected with gh 2.99.0 on 2026-09-25. That
check covers both a field's creation and an options write, and it runs before anything is sent,
including the options write's own read.
