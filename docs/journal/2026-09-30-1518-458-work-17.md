# #458 — R-WORK-17: no worktree inside the workspace Rigger replaces

**The rows governed the directory, not what lay inside it.** `R-WORK-13` to `R-WORK-16` say which
directory at a card's workspace path Rigger may replace. A worktree registered inside that
directory goes with it when it is replaced, and no row forbade that. The engineer judge on PR #456
measured both cases (non-blocking 2, j456-3): the handed worktree nested in the card's own
worktree lost the engine's uncommitted file, and an owner's nested worktree was deleted while the
attempt succeeded. The owner ruled that Rigger never replaces such a workspace, and chose (A): one
more condition in `R-WORK-13`'s list.

**Only the new condition takes a new id.** Under the preamble's test, adding a condition changes
what must be true of Rigger, so it takes `R-WORK-17`, the next id the group has never used.
`R-WORK-13`'s words are unchanged and already require every condition below it, the shape
`R-CARD-12` kept when `R-CARD-34` to `R-CARD-40` joined it. `R-WORK-16` changes only its final
"." to ";", which changes nothing that must be true, so it keeps its id.

**The row is a gap until #457 lands.** No test may claim a row before the build meets it, so the
matrix lists `R-WORK-17` as a gap, and #457 (M3-05c) claims it.
