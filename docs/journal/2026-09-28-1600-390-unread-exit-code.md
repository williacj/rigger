# #390 — An end recorded as Rigger exits may say why the exit code could not be read

## What was built

- One sentence in `ARCHITECTURE.md`'s Failure model, directly after "Each end carries the exit
  code or why the command did not start.": "An end recorded as Rigger exits may instead say why
  the command's exit code could not be read."
- It is a proposal. The owner ratifies it by merging (`D18` rule 1; `D21`).

## Why

- #370's item 6 ruling (https://github.com/williacj/rigger/issues/370#issuecomment-5879030357)
  covers a direct child that exited on its own and was not reaped when Rigger exits. The cleanup's
  final process-table read then fails or does not answer, so the child's exit code is unknowable.
- The ruling has the end say so rather than invent 137. H2's clause, "the exit code or why the
  command did not start", fitted neither half of that case.

## What we learned

- **The bound is what keeps L2 whole.** The sentence reaches only an end recorded on the exit
  path. No caller is left there, so no result L1 hands to L2 lacks an exit code.
- **What would reverse it.** A non-exit path on which an exit code can go unread. That case would
  reach L2, and would need its own ruling on what L2 classifies.
- **Wrap kept.** The paragraph was rewrapped only across the two lines the sentence joins, so the
  diff shows one sentence added and no other sentence changed.
