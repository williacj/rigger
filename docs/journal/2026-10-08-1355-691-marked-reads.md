# Marked reads and deadline cuts in the directory control

The first #691 judge round found that the L5b and L6a `LATE` controls had no start of the named `lsof` or `ps` operation. The fixtures therefore could not have written the listing or live marker in those controls. Those tests now assert the absent starts explicitly. They describe a cut before the operation, not a marked operation whose answer was lost.

The marked L5b listing and L6a first-state cases use the synchronous read timeout. The caller trace records each operation's start and end, fixture marker state at both boundaries, the timeout error, later-read reachability, emitted events, and caller end. The L6a stand-in now writes the live marker and one live line before remaining open until `spawnSync` times out. That partial output is captured with `ETIMEDOUT`, but `runOnce` throws before returning it to L0. The L5b stand-in similarly marks its listing timeout, but returns no omission answer.

At the source read boundary, `runOnce` checks a spent deadline before `spawnSync`. A read that has begun cannot produce `LATE` inside `runOnce`; its bound failure is `ETIMEDOUT`. This explains why a marked-read `LATE` branch is excluded on this exit path while the no-start `LATE` controls remain useful. The controlled cases are diagnostic; they do not establish the phase or cause of the historical `r03` failure.

The unrelated PR CI A0 failure remains assigned to open #696, with its complete original output linked on PR #695. Its cause is unresolved.
