# #324 — `--help` describes `doctor` as the README does

## What changed

`doctor`'s description in `src/cli/verbs.mjs` is now the comment beside `doctor` in `README.md`'s
"Install and usage" block, word for word. PR #315 had rewritten that comment to name every check
`doctor` runs, and `--help` still carried the older list.

`test/cli.test.mjs` gained a test that runs `rigger --help`, reads the README's comment beside
`doctor`, and fails when the two differ. The expected text is read out of the README on every
run, so a later rewording of the README moves the test rather than needing an edit to it.

## How the readers were shaped

The file already read verbs out of both sides, `usageVerbs` from the README block and `helpVerbs`
from `--help`. Each now sits on a line reader that keeps the text beside the verb as well:
`usageLines` keeps the `#` comment, and `helpLines` keeps the description. `usageComment` and
`helpSummary` pick one verb's line and refuse a verb listed other than once. A second test runs
both readers on fixtures, so a reader that answered with a constant, or with another verb's line,
would red.

## What was left alone

Only `doctor` is held to its comment. `once` and `run` say in `--help` that they dispatch no work
before M4, and their README comments do not, on purpose. `README.md` and `src/cli/rigger.mjs` are
untouched.
