ABOUTME: How #1448 makes `rigger doctor` refuse a gh older than 2.97.0, and which test proves each row of its version boundary.

# `doctor` refuses a gh older than 2.97.0

[Card #1448](https://github.com/williacj/rigger/issues/1448) adds a `gh version` line to `rigger
doctor`'s report. It sits between `Node version` and `gh authentication`. The forge adapter sends
`gh --version` through its read runner, which now admits that form. `readGhVersion` in
`src/substrate/forge/read.mjs` reads the release off gh's first line of standard output, and
`GH_MINIMUM` there holds `2.97.0`. `doctor` compares the two by number, using the same `reaches` it
uses for the Node floor.

The card's version boundary table, row by row, with the test that proves each one. `gh-version`
is the test in `test/gh-version.test.mjs`. "Detail" is the test in `test/doctor.test.mjs` titled
"the gh version line's detail names what #1448's version boundary asks of each answer…":

| Row | Answer | Verdict | Proved by |
|---|---|---|---|
| V1 | gh cannot be started | not asked | detail (verdict, detail and one line) |
| V2 | gh exits non-zero | not asked | detail |
| V3 | gh runs past its timeout | not asked | detail |
| V4 | first line `gh version DEV`, empty, or a sign-in message | not asked | gh-version (verdict); detail |
| V5 | `gh version 2.97.0` | ok | gh-version; detail; the whole-report test exits 0 |
| V6 | `2.96.0`, `2.96.9` | failed | gh-version; detail; the whole-report test exits non-zero |
| V7 | `2.9.0`, `1.99.0` | failed | gh-version; detail |
| V8 | `2.97.1` | ok | gh-version; detail |
| V9 | `2.103.3` | ok | gh-version; detail |
| V10 | `3.0.0` | ok | gh-version; detail |
| V11 | `gh version 2.97.0-rc.1`, `gh version 2.98.0-rc.1` | not asked | gh-version; detail |
| V12 | `2.97.1` with an update notice on standard error | ok | gh-version; detail |

The whole-report test is the one in `test/doctor.test.mjs` titled "the gh version line comes once,
after the Node line and before the gh sign-in line…". The host-tier test in
`test/forge-runners.test.mjs` holds the read against the host's real gh each run (`D16` rule 2).

A row whose answer names no release is `not asked` rather than `failed`. No comparison was made,
which is how `nodeVersion` reports a floor it cannot read.

This card's first draft had no deterministic test file outside `D30`'s conversion list that the
host test's `D29` rule 11 declaration could name. The maker escalated it
(1448#issuecomment-7066459653), and the revision added `test/gh-version.test.mjs`.
