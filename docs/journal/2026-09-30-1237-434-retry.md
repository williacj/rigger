# #434 — one more attempt, then the card stays in Coding

**Where the decision lives.** L2's next action decides it, as ruling 1 (A1) gives L2 every branch
of an attempt. L3 hands it the attempt's number with each outcome, as a third argument to `decide`,
`{ attempt, workspace }`, and L2 keeps no count. A required step that failed, a required step that
never started or a workspace L1 could not make is the environment's failure. L2 then records
`attempt.failed` and `attempt.decided` under the card and answers one of two things. Before the
last attempt it answers `{ action: 'again', attempt }`, naming the next attempt; on the last it
answers `stop`. `ATTEMPTS` is 2, by the owner's O4.

**The workspace L1 could not make.** #453's judges noted that L3 never handed that failure to
`decide`. L3 now settles the workspace call and hands the rejection to L2 unread. L2 accepts only
L1's `WORKSPACE_NOT_MADE`, and answers no action for any other rejection, as it does for a step
outcome it cannot read.

**L3 takes only the attempt it expects.** L3 makes another attempt only when L2's `again` names
`number + 1`. A `decide` that drops the third argument keeps answering attempt 2, and L3 then stops
the card with L2's answer instead of looping. That is how the existing harness first ran the new
code, before it forwarded the attempt.

**A refused event spends no attempt.** L2's `failed` reads a refused event as no step's failure and
answers no action. That throws through L3, so the refusal halts the card before any retry. This was
already true at the base; mutation M5 shows two new tests and four existing ones depend on it.

**Existing lines that moved.** The card has no grant table, so every changed line is listed in the
pull request for the owner's approval:

- `test/step-selection.test.mjs`: three calls gain `attempt: 2`, so the `stop` they assert is the
  last attempt's.
- `test/attempt.test.mjs`: the harness forwards the attempt, and the required-failure test expects
  both attempts to stop at `b`.
- `test/worktrees.test.mjs`: the boundary test's stub of `src/execution/workspace.mjs` gains the
  `WORKSPACE_NOT_MADE` export. It stubs the whole module over the real tree, so any new importer of
  another name breaks it.

**Found outside the acceptance, and not built:**

- L1's `makeWorkspace` rejects with `WORKSPACE_NOT_MADE` even where only the sink refused its
  `workspace.made` or `workspace.removed`. L2 therefore reads that refusal as a workspace failure
  and retries, although a refused event should halt. Telling them apart needs a code of L1's own,
  in `src/execution/`, outside this card.
- `test/loop-world.mjs`'s `decide` does not forward the attempt. No test there fails a step, so
  nothing needs it yet. A verb that hands `loop` a `decide` must forward it.
