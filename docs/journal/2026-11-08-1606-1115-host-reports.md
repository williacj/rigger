# Preserve the host invocation's truth

The host command outcome and the reporting outcome serve different purposes. The producer saves
the selected child start, native ending, separate original streams and JUnit bytes before
publishing results. A reporting failure therefore cannot become evidence that the command
succeeded or that no failed test was reported.

The report reader accepts a complete UTF-8 JUnit document through saxes. Its whole-document
close decides acceptance, so callbacks before a later XML error supply no partial names.
Decoded names retain their order, duplicates and embedded line feeds. The consumer selects
only the source-qualified startup record; later worker key lookalikes do not change it.

The existing host worker verifies the tested source. That result travels separately from the
names payload to the Issues-only writer, which performs no checkout or second current-main
verification. Fixed host, source and report fields survive an oversized variable payload. The
complete output and summary bounds follow the local policy in [#1115](https://github.com/williacj/rigger/issues/1115);
they are not claims that an external service will deliver the payload.

The fixed repository-wide writer group protects the complete fresh-lookup-through-write
interval. Raw issue bodies and comments carry the invocation identity. A replay reads them
before any mutation, and an uncertain POST response requires reconciliation rather than an
automatic retry. Two admitted attempts therefore contribute distinct records to the same
store without treating dispatch order as a FIFO guarantee.
