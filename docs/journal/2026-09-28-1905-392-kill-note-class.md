# 2026-09-28 — The kill path records the whole class of tables that hide a live member

**The kill path's note named one instance as if it were the limit.** Beside `outlived`, the note
recorded only a table that hides a live member while listing the group's zombies (#368's item 5).
#372 found the same limit in another shape, a table that lists only a later-started member once the
leader has been reaped, and the note beside `startsIn` records the start path's class: a read that
exits 0 and consistently leaves out a live member other than the leader, whatever else it lists.

**The note now records the class and names both instances.** It says why no read can close it: the
table is the only thing that says which pids the group holds, and signal 0 cannot tell a zombie
from a live process. `killedOf`'s note points to it as the one class its check against the census
cannot catch. Only comment lines changed.

**The two paths' classes are not the same.** Codex's round 1 on #398 found the first draft's claim
that `startsIn` records the same class false: the start path reads again where the recorded
leader's pid answers signal 0 but the read left it out, so its class leaves the leader out. The
kill path asks signal 0 of the group, and of a pid only once the census has named it, so a live
leader every read hides is hidden like any other member. The note now names `startsIn`'s note and
states that difference.
