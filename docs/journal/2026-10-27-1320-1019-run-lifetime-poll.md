# #1019 — `run`'s lifetime, the board poll, and the skip

The owner's M7-U2 item 1 (1009#6434513387), Q1 (a), keeps `run` up after the board drains while
any clock trigger is declared. Until then launchd's relaunch was what read the board again, so a
`run` that stays up would not see a card the owner moves to Ready until the next clock firing. The
architect's r2 review (1009#6434658018) placed the answer as F1: an idle board poll that is Pull's
own read, with its timer in a new `src/scheduling/clock.mjs`. Its F2 amends `D28` rather than
superseding it, because neither rule changes and only one note sentence reads false. M7-K5
(1009#6434666807) accepted both.

The clock declaration is stated in a paragraph below the config shape and not in the fenced block.
That is the attack's ruling in finding 1 (1019#6440710700): `test/config.test.mjs` compares the
block with what `src/config/validate.mjs` offers, which holds no `clock` until M7-20.

How long a set-aside card stays skipped is the owner's M7-U4 Q20 (c) (1009#6449422492): until the
card's board column changes, and moving it back to Ready ends it. The round-2 attack
(1019#6449892027) bounded it to reads begun after the setting aside, and defined the compared column
as the claiming pull's read, changed by each change the board accepted.

Choices the card left to the maker, each a judgment on the code at `6b31ca74`:

- **A hold's closer that could not be saved ends `run`.** No pull claims a card after it, so a
  `run` that stayed up would poll and claim nothing. Ending lets launchd's next start read
  admission again.
- **The next poll is timed from the previous poll's settle.** Two polls then never overlap, and the
  forge-call judgment counts one `take` per interval.
- **A failed or refused poll hands its failure to the verb as it settles**, beside the hand-over at
  each drain. A read that keeps failing never reaches a drain, so its failure would otherwise never
  be printed.
- **The memory stays in `loop.mjs`'s `run`**, and `take`'s `available` compares, as the round-2
  attack's finding 5 recommended. Each of L2's accepted column changes answers the column it left
  the card in, because L2 owns column changes and L3 compares only.
- **The forge-call figure is about 3 + *a* + 6*r*, not 2 + *a* + 6*r*.** `facts.mjs` makes one
  `readBranches` read per poll where any card is active, at `6b31ca74` as at `0dba1dcb`, and the r2
  review's table did not list it.

"Failure model" still says the memory lasts one invocation. "Triggers" now says how it ends earlier
while a clock trigger keeps `run` up, and "Failure model" lies outside this card's "Lands in".
