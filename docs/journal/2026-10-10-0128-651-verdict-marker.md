# The verdict marker replaces the findings comment

`src/workflow/marker.mjs` holds the marker's syntax once. The instruction's template block and a
composed marker come from one line writer, so the block a judge is shown is the block the parse
reads back. The stand-in judge in `test/stub-claude.mjs` fills in that template from its prompt,
which is the test that the two have not drifted.

The parse needs the acceptance's item count to rule an ordinal missing or out of range, so it takes
the count beside the comment. A marker at another digest can then read as unreadable for the
current count, which is harmless: it governs nothing at the current digest.

An unreadable marker still governs for the role, head and digest its block names as written, so a
judge whose later marker is broken is owed again. A broken block that names no readable role is
attributed to no role.

At one `createdAt`, markers are ordered by comment id, shorter first and then lexically, as the card
asks. A GraphQL node id is opaque, and I don't know that its order follows creation. Two markers of
one role created in the same second are the only case it decides.

L1 now records the digest L2 hands it and computes none, so every role answer L2 composes carries
one, the maker's as well as each judge's. The first round left the maker's out, and the judges
caught it against `ARCHITECTURE.md`, "Telemetry": a dispatch's start names the digest of what L2
composed for any role, not only a judge.

An unclosed marker block still reads its fields to the comment's end. Returning early with no
fields let a later broken marker drop out of the governing read, so an earlier sound one governed;
the architect judge found it with a one-test probe.

A `// proves` declaration belongs on the test that fails when the behaviour is gone. Round one put
`R-LOOP-5` and `R-VERDICT-5` on tests a mutation of the item check and of the digest match left
green; a mutation per claimed behaviour is how to place them.

The first round's marker tests and owed-state tests were written in one batch before the module,
not one test ahead of the code. Round two's fixes each ran red first.
