# 2026-09-28 — The adapter's timeout polish from #364

**An unref'd timer was the whole fix for a leaked one.** `whenElapsed` arms a timer of up to
`TIMER_MAX`, 24.8 days. With its cancel made a no-op, the round-5 engineer judge on #364 saw the
adapter's test file report the leak red at once and then never exit. Unref'ing each timer the
chain arms ends that: with the cancel a no-op and the unref kept, the whole of
`test/process-adapter.test.mjs` reached its verdict, 89 of 90 passing, the one red being the
cancel's own test (`c375-mut.py`, macOS 27.0, Node 26.5.0, 2026-09-28). Nothing else needed the
timer to hold the loop: while a command runs its child handle does, and a held pipe holds it
while the output is read.

**The test for a leaked timer cannot leak one of its own.** Each test that asks whether a caller
exits runs that caller as a Node process of its own and waits on its exit under a bound, so a
regression fails the test and the teardown kills the caller, rather than holding the suite.

**A stopped process cannot exit.** A command that exits on its own as its timeout fires did so
before the containment's census stopped its group, since once stopped it could only have been
killed. So every process that containment killed outlived the command, and is now recorded as
`survivor.killed`. The race is set up as the existing race test set it up, by holding the test's
thread until the command is a zombie, so the timer and the exit are both due when the loop
resumes. Before the fix the new test red on the label in its first run. After it the test passed
20 of 20 runs (`c375-repeat.sh`), and with the relabel removed it red on the label again.

**The refusal keeps the value unquoted.** An existing test requires the message to hold
`timeout 300 ` for the string `'300'`, so the type follows the value in parentheses rather than
the value being quoted.
