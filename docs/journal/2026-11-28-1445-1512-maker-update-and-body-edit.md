ABOUTME: What drafting #1512's rows taught: a maker's two missing capabilities, and where a limit on them can hold.

# A maker can update its line and replace its pull request's body

Card #1512 proposes `R-WORK-50` to `R-WORK-54`. The proposal is its pull request's body.

- **The requirements already asked for what the settings refused.** `R-CONFLICT-1` returns a
  conflicting card to its maker. The settings Rigger ships let that maker neither read the main
  line nor join it to its own. On Emend each such return became an owner escalation (M8-U173).
- **A static settings file cannot name a dispatch's own pull request.** A limit to one pull
  request holds only where something set per dispatch names it. Rigger's escalation-note exception
  is the precedent. Where no such setting exists, as for a Codex maker today, only the instruction
  stops a change to another pull request.
- **No setting stops code a maker writes and runs.** A maker that can edit files and run the
  project's scripts acts with the consumer's own credentials (`R-SAFE-4`). `R-WORK-54`'s
  `checked by` says so rather than claim a check no setting makes.
- **Emend's body-edit grant names no pull request.** Its allow rule admits any pull request's
  body. Its deny rules, read and not measured, match each flag only in its spaced spelling. The rows are narrower than
  that grant on both counts.
