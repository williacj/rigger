# 2026-09-23 — The worktrees are a prefix of the checkout

`R-SAFE-5` asks `doctor` to refuse the source tree it is running from, and the plausible way to write that comparison is wrong here in a way no test written beside it would show. Two directories compared by string prefix read `C:\Users\williacj\github\rigger-worktrees\card-34` as sitting inside `C:\Users\williacj\github\rigger`, because the checkout's name is a prefix of the worktree root's. A worktree is where every dispatched maker works, so that refusal would have refused every card Rigger builds itself with, and the tests an author writes beside a prefix comparison are two unrelated directories that agree with it. `path.relative` answers containment instead, and the test asserts the two paths are a prefix pair before it asserts they are not the same tree, so the claim keeps its bite if the naming convention moves.

The comparison also has to be between real paths rather than names, and the reason was measured rather than reasoned. `git rev-parse --show-toplevel` answers `C:/Users/...` on this host where `process.cwd()` answers `C:\Users\...`, so the two never compare equal unless both are resolved; `realpathSync.native` answers the canonical casing, so a lowercased spelling of the checkout resolves to the one the filesystem lists. On macOS the same resolution is what makes `/var/folders/...` and `/private/var/folders/...` one directory. Dropping the resolution and running the suite is what showed it: the junction test redded, and nothing else did.

Containment counts either way about, and that is the half an author drops. A run from inside the checkout has the target within the package. An engine installed into the target's own `node_modules` has the package within the target, which is exactly the arrangement where an agent clearing that directory deletes the runtime mid-run. The second only reaches the comparison because git is asked which repository the working directory sits in: a run from `<repo>/src` against a package in `<repo>/node_modules` compares two unrelated paths otherwise.

A mutation found a defect no test had asked about. Stopping `repoRoot` asking git pointed the Node check at a directory with no `package.json`, and what should have been a report with one line unasked was an ENOENT that took the whole report with it. The check had read its file as though it were always there, while every other check here could already say it could not look. The mutation was run to prove a test discriminated; it also said the report had a way of not existing at all, and that is worth more than the verdict it was run for.
