# 2026-09-25 — A priority option is a name too

#262 had `select.labels` refuse an entry holding only whitespace, and reported that the priority
options check still tested `option === ''`. An option of `'  '` names no board option, so every
card holding that value would rank as undeclared while the config was accepted.

The fix does not copy #262's `trim()` test into `readPriority`. Both checks now read one rule,
`names`, which says a value is a string holding something other than whitespace. A second helper,
`holdsUnnamed`, applies it to a list through `Array.from`, because `some` skips an empty slot.
Both checks had carried that comment and that loop separately.

The two refusal messages are unchanged. Each still names its own key and says what the key must
list, and only the test for whether an entry is a name moved.

One mutation, which reverts `names` to `value !== ''`, reds the new priority test and #262's
labels test together. That shows the two checks share the rule, and each test discriminates.
