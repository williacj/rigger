# #490 — the verbs' judge lines

**A judge withheld for a step is seen through `decide`, not through L3.** L3 answers the judges it
dispatched and nothing of a judge L2 stopped naming. The verb already hands L3 its own `decide`, so
it keeps each card's judge answers there. Where L2 is handed a judge's head outcomes and stops naming
that judge, the verb reads the newest outcome with L2's own `failed`, because L3 asks after every
step. This needed no change below `src/cli/`, which is what the card's "Lands in" allows.

**A judge's refused start is now refused in the bin, through `NODE_OPTIONS`.** #598's journal says
a verb test cannot refuse one judge's dispatch event, and it refused L1's `workspace.made` instead.
This card asks for the start event itself. `test/dispatch.test.mjs` already changes `node:fs` in a
child process with an `--import` module and `syncBuiltinESMExports`. The new test hands the bin such
a module through `onceWithAgent`'s existing `env` option. The module refuses only L3's `dispatch`
append naming `reviewer`, so the sink refuses that start without knowing it is under test. #598's
test at `test/once.test.mjs:444` still passes unchanged. Its line is L3's own message,
`card #10's judge \`reviewer\` handed back no outcome: …`, which already has the judge-line form this
card prints. So the grant's retarget of that line was not needed.

**A judge whose outcome never came back is printed after every card's line, not beside its own.**
L3's failure carries a card whose judges failed with its maker's result alone. It names the card
only in the failure's message text, so the verb prints that failure where it printed failures at
the base. The judges that did hand back beside a failing one are on the failure's `judges`, with no
card on them, so the verb prints nothing for them. That is outside this card's acceptance, and is
named in the pull request.

judges alone) were written together after the first red. To show each test still discriminates,
each piece was removed by a guarded mutation and the test aimed at it was run. The logs are named in
the pull request.
