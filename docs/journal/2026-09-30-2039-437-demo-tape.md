# #437 — the demo tape records `once` as M3 builds it

**Most of the card had already landed.** #435 changed the line `once` prints, the screen
`test/demo.test.mjs` checks CI's demo grep against, and the grep itself. It also gave the demo
world its one provisioning step, `run: true`. What this card had left was the tape's ABOUTME
header, which still said nothing dispatches before M2 and M4, and the GIF.

**The GIF is committed in a commit of its own.** CI uploads the GIF and commits nothing, so the
committed one has to come from a run on some other commit. Every change but the GIF goes in
first. CI records the tape on that commit. Its `demo` artifact is then committed byte for byte as
the head. The two trees differ only in `docs/demo.gif`, which `git diff --name-only` on the pair
shows. A later change to anything else would break that tie, and the GIF would have to be
recorded again.

**The workspace path wraps on the recorded screen.** At the tape's width the path runs onto a
second line, both in the GIF and in `docs/demo.txt`. CI's grep anchors on the start of the line,
which stays on the first row, so the check holds. The card's author ruled the wrap cosmetic and
left it outside the acceptance.
